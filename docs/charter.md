# yanshi 项目章程

> 状态：草案 v0.1（2026-10-08）· 术语以 [CONTEXT.md](../CONTEXT.md) 为准 · 关键决策见 [docs/adr](./adr/)

## 1. 定位

yanshi 是公司内部的**分布式 Agent 运行时基础设施**，承载多条 C 端业务线。

它让业务线只需定义"Agent 做什么"，不必关心"Agent 如何在云、手机、电脑之间长时间、可靠、安全、低成本地运行"。

## 2. 目标

| # | 目标 | 含义 |
|---|---|---|
| G1 | 多端 | 手机、电脑通过嵌入业务 App 的 SDK 接入；同一 Session 可多端同时在线、跨端接续 |
| G2 | 多模态 | 文本、图片、音频、视频、文件统一为内容块；含全双工实时语音/视频交互（Call） |
| G3 | 长任务 | 单个 Run 可持续小时级；可挂起、恢复、中断、插话、取消；节点故障不丢进度 |
| G4 | 个性化 | 用户级 Memory；默认归属业务线，经用户 Grant 可跨业务线共享 |
| G5 | 执行 | API 工具调用（含 Device 提供的本地能力）与云端 Sandbox 代码执行 |
| G6 | 问答 | 低首字延迟的即时问答，与长任务共存于同一 Session |
| G7 | 分布式 | 服务端无状态、线性扩容、高可用；端-云协同执行；跨节点多 Agent 协作 |
| G8 | 生态 | 业务线以声明式 AgentDef + SDK 接入；能力/技能/Agent 可注册、版本化、复用 |
| G9 | 模型中立 | 首选火山引擎模型；更换模型不改业务代码，以评测结果为准入依据 |

## 3. 非目标

- 不训练模型，不自研推理引擎（私有化场景只做模型接入）。
- 不做具体业务应用；只提供参考实现与北极星场景 Demo。
- 不重造通用基础设施（数据库、消息系统、对象存储、容器编排），只做可插拔适配。
- 端侧不预设大模型：端侧智能按"规则 → 经典 ML → 小模型"逐级选用，由具体场景决定。

## 4. 关键约束

- **私有化部署**：不依赖任何公有云托管服务；全部组件可在客户 IDC 的 K8s 上自托管，可在无外网环境运行（移动推送通道等少数必需外联项须显式列出、可配置）。见 [ADR-0001](./adr/0001-private-deployment.md)。
- **规模未知**：并发量级暂无法确定，架构必须支持线性扩容，而非为某个固定规模优化。
- **技术栈**：服务端使用 Go。
- **由 Agent 开发**：主要开发者是 AI Agent，因此"可被 Agent 正确修改"是一等架构约束（见 §5 原则 7–9）。
- **C 端合规**：内容安全审核、个人信息保护、生成式 AI 相关监管要求是基座能力，而非业务线自行实现。

## 5. 设计原则

1. **变与不变分离**：基座只承诺语义稳定的原语（Session、Run、Event、Node、Capability、Policy……）；Agent 循环策略、上下文工程、模型选择、工具协议都是可替换插件。
2. **薄 harness**：不把当下模型的缺陷固化进基座；模型变强时，策略插件变薄，基座不动。
3. **Event 日志是唯一事实源**：Run 的全部状态可由 Event 日志重建；Worker 无状态，故障即重放。见 [ADR-0004](./adr/0004-event-log-as-source-of-truth.md)。
4. **设备即节点**：手机、电脑是执行网络中的 Node，与云端 Sandbox、云服务在 Agent 眼中是同一种 Capability 提供者。见 [ADR-0002](./adr/0002-device-as-node.md)。
5. **快慢分离**：实时交互（Call）走低延迟通道，耗时工作交给后台 Run，两者经 Session 协同。见 [ADR-0005](./adr/0005-realtime-and-async-split.md)。
6. **安全默认**：高风险 Capability 默认需要 Approval；所有外部输入（网页、文件、工具结果）视为不可信数据，不可提升权限。
7. **契约先行**：模块间接口以 IDL 定义；Agent 修改一个模块无需理解全系统。
8. **可验证性第一**：每个模块可独立测试；分布式行为用确定性模拟测试覆盖节点崩溃、网络分区、设备离线。
9. **单进程可运行**：全系统可作为单个二进制在本地启动，开发调试不依赖集群；这同时服务于私有化小规模部署。
10. **评测即基础设施**：换模型、改提示词、改策略都必须经过评测回归与灰度，而非直接上线。

## 6. 北极星场景

**场景 A：跨端长任务**

> 用户在手机上语音说："把我电脑上昨天的会议录音整理成纪要，发给参会的同事。"

覆盖：语音输入 → 云端规划 → 调用电脑 Node 读取文件 → Sandbox 执行处理 → 用户锁屏离开、电脑短暂休眠后任务挂起并恢复 → 结合 Memory 识别"同事" → 发送前在手机上 Approval → 推送结果；过程中可随时追问进度。

**场景 B：全双工实时协作**

> 用户做饭时用手机与助手语音通话："帮我看看电脑上那份 PPT 第三页写了什么……标题改得更口语一点。"

覆盖：Call 全双工、端侧 VAD/回声消除、用户随时打断 → Call 中派生后台 Run 操作电脑 → 结果语音播报 → 跨端状态一致。

## 7. 分层架构（概览）

```
生态层   注册中心(能力/技能/AgentDef) · 业务线 SDK · 开发调试工具 · MCP/A2A 适配
治理层   身份与租户 · Policy/Approval/Grant · 内容安全 · 配额计费 · 可观测与回放 · 评测
能力层   模型网关 · 能力路由(云服务/Device/Sandbox) · Sandbox 服务 · Memory 服务
执行层   Event 日志 · Run 运行时(无状态 Worker + 租约) · 调度 · 多 Agent 编排 · Call 实时通道
接入层   多端长连接网关 · 事件流分发与断线续传 · 推送唤醒 · 设备节点协议 · 端侧 SDK
```

## 8. 成功标准

具体数值待基准测试后确定，此处先定义"怎么算成功"：

- **线性扩容**：Worker 数量翻倍，吞吐近似翻倍，无单点瓶颈。
- **故障透明**：随机杀掉任意 Worker 或网关实例，进行中的 Run 自动恢复，用户仅感知到短暂延迟。
- **模型可换**：仅修改 AgentDef 的模型策略、通过评测报告即可切换模型，无业务代码改动。
- **接入成本**：新业务线通过声明式 AgentDef + SDK 接入，无需修改基座。
- **私有化**：一套部署制品可在无外网 K8s 集群完成部署；单二进制模式可跑通两个北极星场景。
- **Agent 可开发**：任一模块可独立构建、测试；Agent 仅凭仓库内文档与契约即可完成模块级改动。
