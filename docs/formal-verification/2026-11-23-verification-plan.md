# yanshi 形式化验证方案（2026-11-23 修订）

本文取代 `docs/formal-verification/2026-11-22-yanshi-verification-plan.html` 中的工具分工、门禁与路线部分；那份方案写于 PoC 之前，保留作历史记录。本文依据两个已落地模型的实测（`docs/formal-verification/poc1-lifecycle-recheck/`、`docs/formal-verification/a5-slot-migration/`），由 Claude 组织 codex（gpt-6.2）与 gemini（gemini-4-neon）各自独立出方案、再互评，最后定稿。分歧及最终取舍见第 6 节。

## 1. 结论

- **形式化补 sim 的盲区，不替代 sim。** `internal/sim` 已经在真实 Core 上注入故障、做 PG 与双库差分，是执行语义的裁判（AGENTS.md"不变量"）。形式化只投在 sim 结构上够不到的四类地方：输入域大的安全判定、尚未实现的设计、少见但代价高的跨存储交错、跨部署视图的切换。
- **三种手段各管一类对象**：安全纯函数用 Go 属性测试与 fuzz；协议的设计与少见交错用 Quint；规约与实现的对齐优先"由规约生成调度驱动真实 Go"，事后轨迹回放只做定向锚点。
- **不迁语言，不引入第二套模型语言。** P、手写 TLA+、Gobra、Lean/Rocq 暂不进入门禁（第 3 节）。

## 2. 对 11-22 方案的更正

| 原主张 | 实测与判断 |
|---|---|
| `make verify` 15–30 秒，可作 Tier 0 内循环 | 两个模型已约 355 秒（`Makefile` 中 `verify` 目标的注释：两部分各约 42、315 秒）。A5 的随机模拟串行跑了约 30 次，每次至多 10 万样本。内循环需要按协议拆出的快速入口，不能用完整 `make verify`。 |
| Apalache 数十秒穷举，深度"远超 2000 种子"，可替代大量 sim 种子 | A5 的符号检查每步代价约三倍（5 步 22 秒、6 步 78 秒），只做到 5 步；一次迁槽（stop → copy → switchTable → rolloutDone → rotate → resume）就要 6 步，5 步只能检查迁槽中途的性质（如 `invNoFalseGone`、`invRowsOnOwner`），到不了迁槽后的 `invConverged`。TLC 穷尽 15 分钟后状态文件达 17 GB。模型步数与 sim 种子不在同一尺度：sim 检查的是真实 Worker、存储与 SQL，规约检查的是抽象协议。sim 的种子数不因形式化而减少。 |
| 90% 的高危缺陷来自协议时序 | 没有缺陷样本支撑。安全判定（来源、NFKC、污点门、能力交集）与协议同样高危，而且前者用属性测试就能直接验证生产代码。 |
| PoC #2 对全量 `session.State` 与 `Worker.Step` 建模 | A5 单个协议已 932 行；全量建模会状态爆炸，而这里正是 sim 覆盖最密的地方。只在需要裁决具体组合语义时，建窄切片模型（第 5 节）。 |
| 反例自动给出最短路径 | 门禁只要求反例可复现、违反指定的性质；不承诺最短。 |

两个模型已经证明的价值：PoC #1 的首轮回放揭示模型把 presence 的撤回写成逐条删除（模型错）；A5 补出 ADR-0046 与 ADR-0051 §5.4 未写明的两处顺序要求，并随建模修复了 xinli 消费端的三处真实问题（提交 5919704、d4a03dd、916a9e5）。收益集中在**设计期与跨部署切换**，这决定了后续投入方向。

## 3. 手段与适用对象

| 手段 | 用于 | 不用于 |
|---|---|---|
| Go `pgregory.net/rapid` 属性测试 + `go test -fuzz` | 纯判定与小接口：来源推导、写入闸门、MCP 污点门、子 Run 能力交集、检查点的平台字段校验、健康类 Grant 的同意检查；有状态小接口（队列、Ledger）用 rapid 的状态机模式 | 跨进程、跨存储的交错 |
| Quint 随机模拟 + 可达见证 + 指定违例的变体 | 协议的主力检查：深交错靠大量随机轨迹，见证证明关键状态确实走到过，变体证明不变量不空洞 | 输入域枚举（交给 rapid） |
| Apalache 有界检查 | 小模型（动作少、参数小）做到能走完一次完整协议的深度；大模型只用来检查中途性质，并在报告中写明深度 | 宣称"穷举" |
| Quint 归纳不变量（Init ⇒ I，I ∧ Next ⇒ I′，I ⇒ P） | 拆出的安全核（如 A5 的所有权与残留），只有过了三项检查才能写"不限步数成立" | 活性、难归纳的收敛性质 |
| 由规约生成调度驱动 Go（模型驱动测试） | 跨组件的少见交错：把模型找到的调度固化成 Go 场景，在内存与 PG 后端复跑 | — |
| Go → Quint 轨迹回放 | 定向锚点：确认抽象与真实语义一致（PoC #1 已证明它能发现模型错误） | 批量随机种子回放：先拿几条定向轨迹量出映射成本再决定 |

暂不采用：P（与 Quint 和 sim 重叠，引入第三套执行模型）；手写 TLA+（只把 TLC 作为 Quint 小模型做活性检查时的后端）；Gobra 等 Go 代码级验证器（出现边界很小、需要对 Go 源码本身证明的模块时再试点）；Lean/Rocq（无需要任意规模证明的稳定算法）。

## 4. 门禁与预算

| 层 | 内容 | 预算 | 触发 |
|---|---|---|---|
| `make check` | rapid 属性测试与 fuzz 固定语料 | 增时 < 5 秒，记录实测 | 每次提交 |
| 单协议快速入口（计划：`make verify-fast`） | 类型检查、场景测试、小样本模拟、选定变体 | 每个协议热缓存 ≤ 20 秒 | 改动对应协议时的内循环 |
| `make verify` | 全部模型、见证、变体、Apalache、轨迹对照 | ≤ 7 分钟；有界并行后按实测（1/2/4/8 并发的墙钟与峰值内存）收紧 | 按 AGENTS.md 的路径规则，合入前 |
| 定时 | 长时间 fuzz、更深的符号检查、TLC 活性实验 | 不设硬限 | 夜间或专题 |

`make sim` 的种子数与合入前地位不变。

## 5. 路线

### 近期三件事

1. **安全判定的属性测试与 fuzz（2–3 天，约 300–550 行 Go）。** 对象：`internal/session/provenance.go`、`internal/runtime/memgate.go`、`internal/mcpcap/mcpcap.go`、`internal/runtime/worker_calls.go` 中的能力交集、`internal/service/checkpoint.go`、`internal/memory/service.go` 的健康类同意检查。用独立的判定表作为期望值，不复用被测代码。验收：来源污点只增不减、NFKC 变体不绕过闸门、任意祖先链下子 Run 能力不超过交集、客户端无法写入平台字段；每条性质各配一个"坏补丁"（去掉规范化、漏查一层祖先、跳过平台字段检查等），坏补丁下对应测试必须失败；固定语料随 `make check` 运行并记录增时。为什么先做：直接验证生产代码，没有抽象漂移，不依赖 JDK 或 Docker，sim 在这块只有固定模板与只读 MCP 工具（`internal/sim/attested.go`）。

2. **验证基座整顿（2–3 天）。** (a) PoC #1 的变体检查改为要求违反指定的不变量（照 A5 `run.sh` 的 `expect_violation`），工具崩溃或类型错误不再算"抓到"；(b) `internal/sim/lifecycle_trace_test.go` 中补写的中间帧（写入、复查、第二遍清扫）改为经测试侧存储包装观测真实中间状态（参照 `internal/sim/end_user.go` 的拦截器），并用一条故意颠倒顺序的轨迹证明适配器会拒绝；(c) 两个模型共享一份 Quint 依赖与锁文件，目录按协议名命名（去掉 poc1、a5 编号）；(d) 增加单协议快速入口，按并发度实测 `make verify` 并据此定预算；(e) 用 A5 的场景驱动真实的 xinli 消费者（复用 `apps/xinli/delivery/removal_test.go` 的可控内核替身），为 SeenRound、退役与 identity 核对补回归。为什么第二：之后每加一个模型都依赖它，而且 (e) 保护的是已经上线、出过三处问题的代码。

3. **EndUser 注销屏障与幂等建会话的小模型（3–4 天，约 200–350 行 Quint 与 Go）。** 对象：`internal/lifecycle/end_user.go`、`internal/janitor/end_user.go`、`internal/service/service.go`（`Service.CreateWithReplay`）、ADR-0059。覆盖注销 Revision 变化、建会话回包丢失后重放、写后崩溃、宽限期 Prune 后复用 EndUser ID。交付：Quint 模型、至少三个见证、至少三个指定违例的变体（如过时的完成请求、跳过最后一遍清扫），以及由模型调度驱动的 Go 场景（内存与 PG）。验收：小模型的 Apalache 深度足以走完一次注销与重建，并写明参数。为什么第三：触及隐私删除红线，ADR-0059 的复查逻辑刚落地，sim 每次只插一个钩子（`internal/sim/end_user.go`），复合竞态是它的盲区。

### 按条件触发

- **未实现的协议型 ADR 在动工前先建模**，作为规则写入 AGENTS.md：ADR-0048（三方 Agent：旁听污点经压缩与委托的传播、`origin` 推导、撤权后的出口检查与发送竞态）一旦排期就先做；ADR-0041 与 ADR-0056 B 期一起做提交、重试与接管模型（已完成，2026-11-24：`docs/formal-verification/external-loop/`，按 ADR-0062 的契约）；ADR-0056 A 期可只用属性测试检验"上下文策略不改变来源与治理"。
- **A5 拆分与归纳**：迁槽工具排期时，或 `make verify` 超出预算时，拆出"所有权、残留与换代"安全核，完成三项归纳检查；完整模型保留，继续覆盖滚动切换、合并、回滚、摘要 ABA 与过期单库进度（拆开会丢掉 5919704 那类跨机制缺陷）。
- **Worker 接管与原子唤醒窄模型**（1 Session × 2 Worker，含过期 Attempt 的隔离、`Park`/`Release` 与提交唤醒的竞争、work_dues 的搬移）：改动这些语义时，或 sim 在此处出现难以裁决的失败时再建。PG 一致性套件已覆盖并发 `Promote`（`internal/workqueue/workqueuetest/workqueuetest.go`），不必为此单独先建模。

## 6. 防漂移与防"改弱规约"

- **性质清单**：每个协议目录登记稳定的性质 ID、对应 ADR 段落、Go 符号与路径、环境假设、检查命令、见证与变体。docrefs 已检查文档里的路径与标识符（`scripts/docrefs/main.go`），扩展它校验清单中的 Go 符号存在、且每个规约都登记在验证入口里。
- **同步规则**：改动已建模协议的动作、使能条件、持久化顺序、错误与重试语义或环境假设时，同一 PR 更新规约或清单；纯重构也要跑对应入口，可以附上证据说明"规约无需修改"。
- **改弱需显式申报**：删除或放宽性质、缩小参数或深度、删除动作、收紧初始状态、增加假设、跳过观测，都必须和实现改动分开提交，在 PR 中逐项列出，并由不同于实现方的审查者审过。机器侧的兜底是：变体必须违反**指定**的性质，见证必须可达，所以弱化不变量通常会让某个变体意外通过，从而变红。
- **措辞**：报告只说"在某参数、某深度或某样本数下通过"，只有过了归纳检查才写"不限步数成立"。

## 7. 讨论中的分歧与取舍

| 议题 | codex | gemini | 定稿 |
|---|---|---|---|
| 第一件事 | 首轮：补强删除屏障对齐；次轮改为安全属性测试 | 安全属性测试 | 安全属性测试（两方最终一致） |
| Worker 接管模型 | 首轮排进前三；次轮改为按问题触发 | 首轮排末位；次轮上调，并主张与队列两表合并 | 按条件触发。PG 一致性套件已覆盖并发 Promote，gemini 首轮说的盲区不成立 |
| A5 五步符号检查 | 有证据价值，另做拆分与归纳 | 首轮称"无效"；次轮改为"只覆盖中途性质" | 中途性质有效、迁槽后无效，写明深度；拆分按条件触发（两方都把它列进前三，定稿推后：迁槽工具未排期，A5 模型已在用，近期只取驱动真实消费者这一部分） |
| 未实现 ADR | 排期时上调 | 定为硬规则 | 排期即先建模，写入 AGENTS.md |
| 目录 | 留在 `docs/formal-verification/` | 首轮主张顶层 formal/；次轮同意留下，共享依赖、按协议命名 | 后者 |
| `make verify` 预算 | ≤ 7 分钟，先测速 | 并行后 ≤ 90 秒 | 先测速；90 秒没有依据，暂按 7 分钟 |
| 轨迹对齐 | 规约驱动 Go，回放做定向 | rapid 状态机驱动小接口，回放维护贵 | 三者分工（第 3 节），批量回放待实测 |

尚未解决的问题：拆分 A5 后，组合假设能否保持简洁；随机 Go 轨迹的抽象映射成本（一步 `Worker.Step` 内需要多少观测点）；注销宽限期依赖业务侧凭据失效与旧请求寿命，这条环境假设须在建模前写清。
