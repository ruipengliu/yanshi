# 判断记为 Event，只收紧不放宽，失败退回默认路径

harness 中"给定状态、有限选项"的判断（暴露哪些工具、调用结果是否含注入、是否追加审批、Call 中这句话是否要派生 Run）将逐步由规则与自托管小模型承担（[判断设计](../design/m6-decisions.md)）。这类判断与模型调用一样不确定、可能失败，而 Worker.Step 要求可重放、`internal/sim` 要求可注入故障，安全默认要求外部输入不能提升权限。

## 决定

1. **影响后续执行的判断先作为 Event 写入日志，再据此行动。** 与 Recall（ADR-0016）、Compaction（ADR-0012）相同：重放时读日志，不重新调用判断。Event 只含判断种类、选项、结果、置信度与模型标识，不含输入原文（ADR-0015）。
2. **判断只收紧不放宽。** 它可以缩小候选、追加标记、追加 Approval、触发检查，不能免除 Approval、不能替代内容安全提供商、不能跳过写日志前的检查。与 Memory 写入闸门（ADR-0023）同一取向。
3. **判断不可用时退回默认路径。** 默认路径是"不做优化"：全量暴露工具、按原规则审批、不加标记。判断失败只计数、不使 Run 失败，也不放行。
4. **判断受评测约束。** 阈值只在留出集上确定；评测报告调用率与漏检率；改动判断模型或阈值与改动提示词同等对待，须 `make eval` 无回归。
5. **判断是计量的模型调用**（ADR-0019），并在 `internal/sim` 中注入失败与超时。

## Considered Options

- **判断不进日志，重放时重新计算**：重放结果可能不同，破坏"状态只由日志投影得到"（ADR-0004）。
- **判断可以放宽（如高置信度时免审批）**：把分类器变成安全闸门；独立评测显示其作为唯一闸门不可靠，合规上也不接受。
- **判断失败时让 Run 失败**：把一个可选的优化组件变成单点。

## Consequences

- 新增 Event 类型 `DecisionMade`；`session.Reduce` 据此投影"当前 Run 的候选工具集""已标记的调用结果"等，改动 `Apply` 时递增 `ProjectionVersion`。
- 托管 API 形态的判断模型不可用于私有化部署（ADR-0001）；自托管小模型需要推理端点支持 logprobs。
- 术语：Decision（判断）在 CONTEXT.md 定义；本 ADR 转为 accepted 时随第一个判断点一起实施。
