# Agent 的提问是路由到用户本人的调用

Agent 需要用户在几个候选中选择、或补充少量结构化信息时，调用内置能力 `ask_user`，参数是问题、选项与字段。它沿用路由调用的生命周期（M1 §3），只是目标是用户本人（`NodeID = "@user"`），不经任何 Inbox：

- Worker 记下 `ToolCallStarted{node_id: "@user", deadline}` 后挂起 Run，不占用 Worker；
- 用户在任一设备上点选或填写，回答作为该调用的外部结果（`ToolResult`，attempt = 0）写入日志并唤醒 Run；其他设备从事件流看到结果，随之收起问题；
- 用户直接打字回复时，这段文字作为回答，而不是插话；
- 截止时间到了仍无回答，调用以超时错误结束；中断 Run 时，提问随之作废。

我们没有新增"提问 / 回答"事件类型。挂起、截止、外部结果、中断撤回、接管后重放这些语义，路由调用已经有了，也已由模拟测试覆盖；投影不需要改动。模型看到的也只是一次普通的调用与结果，不需要额外的上下文规则。

## Consequences

- 客户端从 `AssistantMessage.tool_calls` 中 `capability == "ask_user"` 的调用读出问题，由该调用是否已有 `ToolResult` 判断是否仍待回答。
- 回答在写日志之前按用户输入做内容安全检查（ADR-0021）。选项文字是模型输出，已在输出时检查过。
- 回答是用户本人的话：Memory 写入闸门（ADR-0023）把它算作用户输入，而不是外部内容。
- `@user` 不是 Node：撤回调用（中断、删除）时没有 Inbox 项要移除，执行路径须跳过派发。
