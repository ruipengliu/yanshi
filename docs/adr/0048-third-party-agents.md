# 三方 Agent：出站是能力，入站的来源按入口推导

persona agent 要调用三方 Agent 办事，让三方 Agent 来查询或对话，以后让三方开发的 Agent 运行在 yanshi 上。三方给的内容不可信，三方拿到的是个人信息。

## 决定

（设计见 `docs/design/m7-agent-ecosystem.md`）

- **出站**：内核实现 A2A 客户端（新增的 `a2acap` 包，与 `mcpcap` 并列），三方 Agent 按登记成为能力 `a2a__<名称>`。结果是外部内容；总是需要审批，`no_approval` 与 `read_only` 不能免去，审批展示将要发出的内容；只发出调用参数，平台不附带上下文；长任务按后台调用处理（ADR-0035）。
- **入站数据档**：Persona 对外的 MCP，OAuth 范围授权，只读加提议写入（进"待确认"），不含旁听原文。不改内核。
- **入站对话档**：网关实现 A2A 服务端，每个 (EndUser, 三方) 一个 Session；`RunRequested` 带只能由网关写入的 `origin`（三方与授权版本），**来源推导为外部**。这类 Session 的 AgentDef 不召回 Memory、`scope: run`；有活跃 Run 时拒绝（不产生插话）、不允许重答；`origin` 随 MCP 调用传给 Persona 逐次检查范围；同步响应、查询与推送在出口检查授权版本；审批与提问仍路由到用户本人。
- **托管**（注册中心里程碑）：三方开发者是独立的 BusinessLine；Grant 扩展为调用授权与数据授权，委托可以跨业务线，能力取各方白名单与授权的交集。
- **同意**：按三方 × 范围单独同意，可撤销，有访问记录。**旁听原文不开放给三方**；听过他人旁听的 Session 记一个只增不减、随压缩与委托传递的标记，置位后不能调用三方。Persona 摘要中的转述按用户授权的范围提供，逐字引用是写明的残留风险。

这在入站上采用了 ADR-0037 没有选的"派生自不可信内容的标记"：那里有 MCP 拉取这条更简单的路，入站对话没有，输入本来就要进入 Run。

## Considered Options

- **应用层自己对接三方**：内核不变，但审批、来源推导、同意记录与他人原话的拦截都管不到。
- **三方以服务令牌提交输入**：最简单，但三方的话成了用户原话。
- **整个 Run 交给三方**：见 ADR-0041，平台的检查管不到三方内部。
- **三方 AgentDef 放进 xinli 业务线**：省去跨业务线的授权，但数据、配额与指令的信任混在一起。

## Consequences

- 统一检查点新增平台专属字段 `origin`；来源推导新增"A2A 入口 → 外部"；投影新增"听过他人旁听"的标记。
- 不用文字重合判断他人原话是否外流：启发式可以被拆分、编码与长参数夹带绕过（Codex 评审，2026-10-27）。
- ADR-0031 的"不跨 BusinessLine"在托管阶段经 Grant 放开，届时另行修订。

## 重审条件

（2026-11-14 补充）任一出现即重新评估：

- 三方托管（三方开发者作为独立的 BusinessLine、委托跨业务线）开始实施之前：届时修订本 ADR 与 ADR-0031；
- "听过他人旁听的 Session 不能调用三方"开始实现时：核对它仍只依赖来源推导（ADR-0052 第 4、8 条）；
- 出现三方需要读取旁听原文的需求——按本 ADR 仍应拒绝，但须记录理由。
