# 用量独立于 Event 日志计量，配额为软上限

模型调用与沙箱执行的用量按价格表折算为金额（微元），记录在独立的用量存储中，不放进 Event 日志，也不从日志推导。原因是 Session 会被物理删除（ADR-0015），而成本结算必须在删除之后仍然可核对。为了让这份长期保存的数据不成为个人数据，记录中不含 Session、Run 与任何内容，注销 EndUser 时其标识被匿名化。

用量在模型调用返回后、写日志前记录：token 在返回时已经消耗，之后写日志失败也应计费。这使"日志中的用量"与"计量的用量"可能不同：计量可以多于日志（调用后 Attempt 被接管），不会少于日志（记录失败时除外）。

配额（业务线每月、EndUser 每日）在提交新 Run 与每次模型调用之前检查，超额时拒绝新 Run、挂起进行中的 Run。检查与扣减不原子，是软上限：超出量至多是检查时在途调用的费用。我们没有做额度预留：它需要预估单次费用并处理退回，对 C 端的小额调用不值得。

## Consequences

- 计量是 Event 日志之外的第二份事实，只用于计费与配额，不参与执行语义；Run 的状态仍只由日志决定（因配额挂起是一个普通的 RunSuspended）。
- 价格表成为部署配置的一部分；启用配额时，所有在用模型都必须有价格。
- 配额挂起期间重新检查不写事件，避免长期超额的 Run 持续写日志。
