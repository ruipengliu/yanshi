# 评测使用仓库内的固定用例集与不同系列的评分模型

模型、提示词、AgentDef 与策略的变更，以仓库内 `evals/` 的固定用例集评测：每个用例多次运行，确定性断言与模型评分并用，并与提交在仓库中的基线比较，出现回归时失败。评分模型与被评测模型属于不同系列（默认 `glm-5.3`），以减少模型偏袒自己回答的倾向。线上 Session 不直接回放，只能经导出工具转为用例骨架，在取得用户同意并脱敏后加入用例集。

我们没有选择直接回放线上 Session：它覆盖真实分布，但属于对个人信息的再处理，与 ADR-0015 的数据最小化方向相悖。也没有放进 `make check`：评测消耗真实 token，且结果有波动，不适合作为每次提交的门槛；改为在相关变更时强制运行（AGENTS.md）。

## Consequences

- 基线是仓库的一部分，有意的效果变化须随代码一起更新基线，评审时可见。
- 评测结果有随机性，用多次运行的通过率与评分均值衡量；阈值（通过率下降 0.34、评分下降 0.5）偏宽，以减少误报。
- 用例集需要随新能力增长；新增给模型看的文本（工具描述、系统指令片段）时，应同时增加覆盖它的用例。
