# 实时交互（Call）与异步执行（Run）分离

全双工 Call 走独立的低延迟实时通道，媒体流不进入 Event 日志（只记录转写与关键事件）；需要调用 Capability 或耗时的工作，由 Call 派生后台 Run 执行，结果再回注 Call。这样实时通道可针对延迟优化、Run 可针对可靠性优化，二者互不拖累；代价是需要定义清楚 Call 与 Run 之间的协同语义（派生、回注、打断传播）。

## 重审条件

（2026-11-14 补充）快慢分离保证了 Call 中做的事都经过写日志、审批与内容安全（ADR-0004、ADR-0021），因此保留。任一出现即重新评估本 ADR 与 ADR-0027 中"语音模型只通过 `run_task` 做事"的决定：

- 实时模型能在不绕过写日志、审批、调用去重、Memory 写入闸门与内容安全的前提下直接发起 Capability 调用；
- `run_task` 派生与回注的延迟成为评测上可测量的主要瓶颈（`evals/call-*.yaml`）；
- 弱网下的通话质量达不到上线要求（重审媒体通道，见 ADR-0024、ADR-0027 的修订）。
