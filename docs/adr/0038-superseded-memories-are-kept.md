# 被取代的 Memory 标记失效、保留历史

`memory_save` 的 `replaces` 原先删除旧条目。旧事实并非没有用处："以前住哪""上次的计划"这类问题只能依据它回答；模型用错 ID 时，删除还会悄悄丢掉一条无关的信息。带日期的计划过了日期也一直被召回。

改为：替换时把旧条目标为被新条目取代（`superseded_by`、`superseded_at`），不删除；写入时可以给出有效期 `valid_until`。召回、检索、去重与 Grant 只看有效的条目；`memory_search{history: true}` 与 `GET /v1/memories?history=true` 可以查到历史。失效满 180 天、过期满 30 天的条目，在同一 EndUser 的下次写入时清除。用户要求忘记时，删除这条与被它取代的整条链。

## Considered Options

- **维持删除**：实现最简单，但历史问题无法回答，用错 ID 不可挽回。
- **只追加、不记录取代关系，读取时按时间消解**（mem0 2026-04 的做法）：写入最简单，但每次读取都要由模型判断哪条有效，召回会被同一主题的多个版本挤占。
- **把 Memory 放进 Event 日志**：天然只追加，但 Memory 跨 Session，而日志按 Session 删除（ADR-0015）。

## Consequences

- 用户说"忘掉"时删除整条链：失效的历史不再是"忘不掉"的残留。
- 用户改正一条错误的事实（不是"忘掉"）时，错误的旧条目作为历史保留 180 天，在 `GET /v1/memories?history=true` 中可见、可删。
- 每人每业务线的上限只计有效的条目，历史另有期限，存储量有界。
- 召回文本带记录日期，给模型看的文本变化须经评测（AGENTS.md）。
