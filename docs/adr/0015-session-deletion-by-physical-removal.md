# Session 数据以物理删除方式清除

EndUser 删除对话、注销账号或数据超过保留期时，yanshi 先写入删除记录，使该 Session 立即不可见；再由后台 Janitor 从所有存储（事件日志、工件、沙箱工作区、队列、Inbox、账本）中物理删除数据。删除记录只保存 Session ID、业务线与时间，不保存 EndUser 标识。

我们没有选择加密销毁（crypto-shredding：每个 Session 或 EndUser 一把数据密钥，删除时只销毁密钥）。它的优势是备份中的副本也会立即失效。但它要求每次读写都加解密，还需要一个与数据库备份隔离的密钥存储；私有化环境不一定有 KMS，而密钥如果和数据一起备份，就失去了意义。物理删除的代价是：备份中的副本要到备份过期才会消失，这一点必须写进部署文档。

## Consequences

- 关闭（closed）与删除（deleted）是 Session 的两个终态，各自对应新的 Event 或删除记录；ADR-0004 的"只追加"约束的是 Session 存续期间的写入。
- 新增 Session 索引表（日志的投影，可重建），用于按 EndUser 查找与列表。
- 所有写入入口都要检查删除记录，防止删除过程中有数据"复活"；模拟测试需要覆盖这些竞争。
- 如果将来需要备份中的数据也立即失效，可以在此之上增加加密销毁，删除流程不变。
