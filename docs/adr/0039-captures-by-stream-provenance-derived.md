# 采集按流登记，来源由平台推导

旁听是第一种"不是对 Agent 说的输入"。接入它时，信任规则分散进了写入闸门与注入判断的多个函数，每个都按事件类型单独判断；旁听整理的业务规则（交谈间隔、接着读的位置）也写进了内核，接着读的位置还要靠正则从给模型看的文字中找回。再加一种采集，就要再改一遍这些地方（[设计](../design/m5-inputs-triggers-loops.md) §1）。

## 决定

1. **来源由平台推导。** 每段内容的来源（本人、他人、外部、平台、模型）是"事件 + 内容块"的纯函数，写入闸门、注入判断、`cite_captures` 与给模型看的标注都只用它。不在内容块上存储来源字段；唯一推导不出的旁听说话人仍是结构化字段，只能由 `captures` 的结果写入。
2. **采集按流区分。** `CaptureAppended` 增加必填的 `stream`。流的种类由平台登记，决定校验、内容安全、来源推导与给模型看的格式；AgentDef 以 `streams` 声明接收哪些流，`captures: true` 删除，AgentDef 改为严格解析。非文字的种类每一种另立 ADR。
3. **读取位置是结构化的。** `captures` 的结果带平台写入的读取位置，投影在 `RunCompleted` 时提交；接着读直接读投影，不再扫描日志、不再解析文字，原来的扫描与正则一并删除。分段参数（交谈间隔）来自 AgentDef，一个 Session 内沿用第一次读取时的值。

## Considered Options

- **每个内容块存一个来源字段**：读取最直接，但字段可以由写入方自报，每个入口都要校验它没有被伪造；推导则天然只认平台写入的事件。
- **换一个新名字的通用事件**：不保留兼容时也可行，但只是改名，没有语义上的收益，代码、SDK 与文档的改动面更大。
- **不泛化，等第二种采集出现再说**：眼下改动最少，但信任规则会在第二次接入时继续分散，接着读的全量扫描也仍在。

## Consequences

- 不兼容之前的实现：旧的 AgentDef 写法、`after` 的整数形式与不带流名的提交直接报错，升级前的日志不再能加载（开发数据库清空）。给模型看的文本不变，评测须与基线一致。
- 删除的 proto 字段保留编号与名称，契约仍通过 `buf breaking`。
- 新增一种采集只需登记种类与它的来源，闸门与判断自动适用；但非文字的采集仍要逐种论证删除与内容安全（ADR-0036）。
- 投影增加读取位置，递增 `session.ProjectionVersion`。
