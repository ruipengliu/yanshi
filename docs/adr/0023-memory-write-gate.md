# Memory 写入闸门：外部内容影响下的写入须经用户批准

当模型上下文中出现过外部来源的内容（设备、沙箱、MCP 的调用结果，或可能概括了它们的压缩摘要），而 `memory_save` 要写入的内容在 EndUser 本人的输入中找不到依据（其中的邮箱、链接、号码未出现在用户输入中，或字符二元组覆盖不足一半）时，这次写入需要用户批准。判定只依据日志投影，不调用模型。

记忆投毒是持久化的提示注入：写进去的指令会在之后所有 Session 中被召回（Memory 调研笔记 §2.3）。评测显示当前模型能抵抗直白的投毒（`memory-poisoning-*` 用例），但这种抵抗随模型而变，而章程要求模型可换（G9），因此需要一道不依赖模型的防线。我们没有选择用小模型判断内容是否可疑：相关调研中这类判断的准确率不足以作为闸门，且会引入非确定性；也没有选择一律审批：用户亲口说的事实不应打扰用户（`memory-gate-user-stated` 用例）。

## Consequences

- 闸门只收紧不放宽：误判的代价是多一次审批，而不是放行投毒。
- "记下这个网页里的联系人"这类合理请求会出现审批，用户在审批中看到将被记住的确切内容，包括夹带的指令。
- `replaces` 只能替换同类别的记忆；按来源 Session 撤销记忆的接口供业务线运维使用。
