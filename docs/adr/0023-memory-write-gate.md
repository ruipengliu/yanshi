# Memory 写入闸门：外部内容影响下的写入须经用户批准

> **缺陷已修复**（2026-11-15）：2026-11-14 发现字符二元组只收汉字（U+4E00–U+9FFF）、ASCII 小写字母与数字，内容的二元组为空时判为有依据，因此日文假名、韩文、西里尔字母、带变音的拉丁字母、汉字扩展区组成的内容在含外部内容的 Session 中写入时一律免审。现已按文末修订实现（`internal/runtime/memgate.go`）：两侧先做 NFKC 规范化，二元组收录 Unicode 的字母、附加符号与数字，号码识别任意十进制数字，二元组为空时按无依据处理。

当模型上下文中出现过外部来源的内容（设备、沙箱、MCP 的调用结果，或可能概括了它们的压缩摘要），而 `memory_save` 要写入的内容在 EndUser 本人的输入中找不到依据（其中的邮箱、链接、号码未出现在用户输入中，或字符二元组覆盖不足一半）时，这次写入需要用户批准。判定只依据日志投影，不调用模型。

记忆投毒是持久化的提示注入：写进去的指令会在之后所有 Session 中被召回（Memory 调研笔记 §2.3）。评测显示当前模型能抵抗直白的投毒（`memory-poisoning-*` 用例），但这种抵抗随模型而变，而章程要求模型可换（G9），因此需要一道不依赖模型的防线。我们没有选择用小模型判断内容是否可疑：相关调研中这类判断的准确率不足以作为闸门，且会引入非确定性；也没有选择一律审批：用户亲口说的事实不应打扰用户（`memory-gate-user-stated` 用例）。

## Consequences

- 闸门只收紧不放宽：误判的代价是多一次审批，而不是放行投毒。
- "记下这个网页里的联系人"这类合理请求会出现审批，用户在审批中看到将被记住的确切内容，包括夹带的指令。
- `replaces` 只能替换同类别的记忆；按来源 Session 撤销记忆的接口供业务线运维使用。

## 修订（2026-11-14）

- **匹配算法可以替换，但必须失败保守。** 字符二元组覆盖只是现行的一种判断"在用户原话中有依据"的方法，不是契约本身；替换为别的确定性方法时，同样只依据日志投影、不调用模型。任何识别不了的内容（例如二元组集合为空）按**无依据**处理，须经用户批准。
- 覆盖范围至少包括 Unicode 的字母与数字类别，不能只认某几种文字（[ADR 评审](../review/2026-11-14-adr-review.md) §2.1）。
- （2026-11-15 实施）比较之前，内容与用户原话都做 NFKC 规范化：全角的 `＠`、数字与拉丁字母归一为半角，分解与组合形式的变音字母得到相同结果，邮箱与号码的识别不能用全角字符绕过。邮箱与链接的识别仍只认 ASCII：放宽为 Unicode 时，紧贴地址的中文会被并入地址而造成误报；非 ASCII 的地址由二元组覆盖判断。

## 重审条件

（2026-11-14 补充）任一出现即重新评估：

- 多语言业务线接入，或现行算法对某种文字的判断不可靠；
- 评测中闸门的误报（打扰用户亲口说的事实，`memory-gate-user-stated` 等用例）或漏报（`memory-poisoning-*` 等用例）越过阈值；
- 出现准确率足以作为闸门、且确定性可复现的判断方法（上文否决小模型判断的理由不再成立）。
