# 健康信息作为单独的 Memory 类别，按业务线的单独同意开启

Memory 增加 `health` 类别（过敏、饮食禁忌、慢性病与用药等）。业务线在配置中声明 `memory.health: true`，表示已在产品流程中取得用户对健康信息的单独同意；只有这样的业务线能写入该类别，召回与检索也只在开启时包含它。经 Grant 跨业务线读取时，还要求写入方业务线已开启。这修订了 ADR-0016 中"敏感个人信息不在任何类别中、平台拒绝写入"的约定。

原来的做法使助手在用户主动说出"我对花生过敏"时也不能记住，评测中观察到模型在指令与用户意图之间摇摆（3 次中有 1 次没有记住）。过敏这类信息关系到安全，记住它是用户期望的。我们没有选择对所有业务线默认开放：单独同意必须由业务线在自己的产品中取得，平台需要一个明确的声明，才能在出问题时说明哪条业务线承担了取得同意的责任。

## Consequences

- 健康信息是独立的类别：用户授权时能看懂"允许 B 读取你在 A 中的健康信息"，默认不会随其他类别一起授权。
- 关闭开关即停止使用（不召回、不检索），但不自动删除：删除仍由业务线经 API 完成，或随 Session、账号删除。
- 写入指令（`memory_save` 的描述）改为鼓励记住与安全相关的健康信息；修改它须经评测（`memory-health-recall`、`memory-save-intro`）。
