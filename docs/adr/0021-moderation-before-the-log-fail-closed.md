# 内容安全在写日志之前检查，失败即拒绝

用户输入在 Service.Submit 写日志之前检查，违规时拒绝且不写入日志；模型输出在写日志之前检查（回复文本与调用参数），违规时替换为拒答文本、丢弃调用，并记录不含原文的 `ContentModerated` 事件。内容安全服务不可用时一律不放行：输入返回 503，输出重试直到 Run 因持续出错而失败。检查由可替换的提供商完成；上线前须用真实提供商替换模拟实现。

我们选择在写日志之前检查，而不是写入后再标记：日志是唯一事实源，也会被投影成模型上下文与客户端展示，违规原文一旦写入，就要在每个读取路径上过滤，且受删除与保留策略约束。代价是检查的延迟加在提交与每次模型调用上。

实时增量在检查之前推送，是可被覆盖的草稿；如果监管要求草稿也不得展示违规内容，需要提供商支持流式检查。

## Consequences

- 被拦截的输出在日志中表现为拒答文本加 `ContentModerated`，Run 正常完成；评测与统计可以区分"模型拒答"与"被拦截"。
- 内容安全服务成为 Submit 与模型调用的依赖：它的可用性直接影响服务可用性。
- 调用结果暂不单独检查，由输出检查兜底；上线前重新评估外部来源的结果。
