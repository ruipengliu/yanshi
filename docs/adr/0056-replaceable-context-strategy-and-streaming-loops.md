# 可替换的上下文策略与流式外部循环

> **方向已批准（2026-11-15），尚未实现。** 本文记录方向与实施前必须定稿的问题，不是"已经支持"。ADR-0041 的外部循环本身也尚未实现。来源：[ADR 评审](../review/2026-11-14-adr-review.md) §3.4。

章程原则 1 要求"Agent 循环策略、上下文工程、模型选择、工具协议都是可替换插件"。ADR-0041 让业务线的外部服务决定每一步做什么，但留下两处不可替换：

- **上下文由平台固定组装。** 内置循环与外部循环拿到的都是 `runtime.Transcript` 组装的同一份视图：系统指令只放 AgentDef 的指令，召回放在 Run 的位置上，Run 内只在尾部追加，压缩与 `context.scope: run` 是仅有的调节手段（[长 Run 设计](../design/m2-long-runs.md)）。业务想按自己的知识选材（例如只带与当前项目相关的历史），只能写进指令或改平台。
- **外部循环不流式。** 第一版每一步返回整条回复（[m5 设计](../design/m5-inputs-triggers-loops.md) §7），客户端在外部服务想完之前看不到任何东西。

## 提议的决定

### 一、上下文策略

1. **平台治理不可替换，策略可以替换。** 平台始终负责：来源推导（`session.Provenance`）、能力白名单与审批、写入闸门、内容安全、按 Session 的可见性与删除。业务可替换的只是"给模型看哪些内容、以什么顺序"。
2. **策略只能选择与追加，不能改写来源。** 业务线登记的上下文策略（与 MCP、外部循环同样按业务线登记，ADR-0041 第 4 条）在每次调用模型之前，按引用从平台给出的候选（本 Session 的事件、召回、压缩摘要）中**选择与排序**，并可以**追加**自己的内容。追加的内容一律推导为外部内容（与 MCP 结果相同），经内容安全检查、计入写入闸门与注入判断。策略不能把外部内容或他人的话标为用户原话，不能去掉平台写的说明（例如审批摘要、内容安全的占位），不能改动系统指令。
3. **策略的结果先记为 Event，再据此组装。** 与召回相同（ADR-0016）：选择的结果（引用与追加内容）写入日志，回放读日志、不再请求策略服务，`Worker.Step` 的确定性不变。
4. **请求前缀的稳定由策略自己负责，平台度量。** 策略改变已发送过的前缀会降低提供商的前缀缓存命中（AGENTS.md 的不变量）。平台不禁止，但评测报告的"缓存命中"列与计量按 AgentDef 区分，使代价可见；改动策略时须 `make eval` 比较。

### 二、流式外部循环

5. **草稿经实时增量推送，最终回复照常提交。** 外部服务可以按步流式返回；Worker 把收到的片段作为实时增量推送给订阅者（ADR-0013 的直接拉取，不进日志）。整条回复返回后，照常在写日志前送内容安全检查、写入 `AssistantMessage`。草稿是可被覆盖的（ADR-0021）。
6. **已输出过增量的步不在连接层重试。** 沿用[模型调用](../design/model-calls.md)的规则：订阅者已经看到部分输出时，重试会让它们看到两份；失败交给 Worker，下一步重新请求，连续失败计入出错预算，客户端丢弃未提交的草稿。
7. **状态带版本。** `state` 仍是外部服务给自己的不透明数据（至多 64 KiB，随回复写入日志、随 Session 删除），另加一个由外部服务填写的版本号，便于它在升级后识别旧格式。平台不解释它。
8. **用量分两份。** 平台按步计量，用于配额与计费（ADR-0019）；外部服务可以上报它自己调用模型的用量，平台只作为"业务线自报"的属性记录，用于报表，不参与配额判断。外部服务调用模型时的缓存由它自己负责。

## 待回答的问题（批准前须给出答案）

1. 上下文策略的接口：是每次调用模型前一次远程请求（延迟、可用性、失败时的默认路径），还是在 AgentDef 中声明式描述（能力有限，但不需要远程服务）。失败时是否退回平台的默认组装（ADR-0030 的"失败走默认路径"）。
2. 候选集合的范围：是否包括已被压缩的原始事件、其他 Run 的事件、`scope: run` 之外的内容；与 `context.scope` 的关系。
3. 追加内容的大小上限与内容安全的成本（每次调用模型都要检查新追加的部分）。
4. 流式草稿的内容安全：监管若要求草稿也不得展示违规内容（ADR-0021 的重审条件），流式外部循环同样受限。
5. 外部服务自报用量的格式，以及报表中如何与平台计量区分展示。

## 必须验证

- 模拟测试：回放不请求策略服务与外部循环；策略服务或外部循环在写入前崩溃、重复请求时以写入日志的那次为准；状态恢复。
- 权限与来源：策略追加的内容在 `session.Provenance` 中是外部内容；策略无法使任何内容被推导为用户原话或平台来源；能力白名单与审批不受策略影响。
- 前缀稳定：默认策略（平台组装）下缓存命中不退化。
- 评测：新增使用自定义策略的用例（`evals/` 中按 ADR-0018 固定），以及流式外部循环的端到端用例。

## Considered Options

- **把上下文组装整个交给外部循环**：外部循环本来就拿到完整视图，可以自己裁剪后再调用它自己的模型。这对外部循环已经成立；本提案要解决的是内置循环（平台调用模型）的上下文也能由业务选择。
- **允许策略改写内容**（摘要替换原文、改写来源标注）：最灵活，但改写后的内容来源无法推导，写入闸门与注入判断失去依据（ADR-0052 第 4 条）。
- **流式时在连接层重试**：对订阅者不透明，会出现重复的草稿。

## Consequences

- 批准后修订 ADR-0041（第 1 条"平台照常组装上下文"与"第一版不流式"），并更新 m5 设计 §7、长 Run 设计与模型调用设计。
- 新增策略与流式的契约放在 `proto/`，只做向后兼容的修改。
- 上下文工程从"改平台"变为"登记一个策略"，与章程原则 1 一致；代价是每次调用模型可能多一次远程请求。

## 重审条件

- 批准、实施或放弃本提案时更新状态；
- ADR-0041 开始实现时，与本提案一并核对。
