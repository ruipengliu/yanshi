# 可替换的上下文策略与流式外部循环

> **已定稿（2026-11-16），尚未实现。** 方向于 2026-11-15 批准，"待回答的问题"已在下文"定稿的答案"一节中逐条给出，实施时以该节为准；本文不是"已经支持"。ADR-0041 的外部循环本身也尚未实现。分两期实施：A 期上下文策略不依赖 0041，等业务线提出需要时实施；B 期流式外部循环与 0041 一并实施。来源：[ADR 评审](../review/2026-11-14-adr-review.md) §3.4。
>
> **2026-11-24**：外部循环的契约由 [ADR-0062](0062-external-loop-contract.md) 定稿。B 期的 NDJSON 流式（Q7）、草稿与内容安全（Q5）、自报用量（Q6）、状态版本（第 7 条）不变；外部服务无状态、同一步可能被请求多次、调用与状态的平台侧保证以 ADR-0062 为准。A 期不受影响。

章程原则 1 要求"Agent 循环策略、上下文工程、模型选择、工具协议都是可替换插件"。ADR-0041 让业务线的外部服务决定每一步做什么，但留下两处不可替换：

- **上下文由平台固定组装。** 内置循环与外部循环拿到的都是 `runtime.Transcript` 组装的同一份视图：系统指令只放 AgentDef 的指令，召回放在 Run 的位置上，Run 内只在尾部追加，压缩与 `context.scope: run` 是仅有的调节手段（[长 Run 设计](../design/m2-long-runs.md)）。业务想按自己的知识选材（例如只带与当前项目相关的历史），只能写进指令或改平台。
- **外部循环不流式。** 第一版每一步返回整条回复（[m5 设计](../design/m5-inputs-triggers-loops.md) §7），客户端在外部服务想完之前看不到任何东西。

## 提议的决定

### 一、上下文策略

1. **平台治理不可替换，策略可以替换。** 平台始终负责：来源推导（`session.Provenance`）、能力白名单与审批、写入闸门、内容安全、按 Session 的可见性与删除。业务可替换的只是"给模型看哪些内容"。
2. **策略只能选择与追加，不能改写来源。** 业务线登记的上下文策略（与 MCP、外部循环同样按业务线登记，ADR-0041 第 4 条）在每个 Run 开始时（召回的位置），按引用从平台给出的候选（本 Session 默认视图中更早的 Run、召回、压缩摘要）中**选择**，并可以**追加**自己的文字。选中的内容保持时间顺序，策略不排序（定稿答案 Q9）。追加的内容一律推导为外部内容（与 MCP 结果相同），经内容安全检查、计入写入闸门与注入判断。策略不能把外部内容或他人的话标为用户原话，不能去掉平台写的说明（例如审批摘要、内容安全的占位），不能改动系统指令。
3. **策略的结果先记为 Event，再据此组装。** 与召回相同（ADR-0016）：选择的结果（引用与追加内容）写入日志，回放读日志、不再请求策略服务，`Worker.Step` 的确定性不变。
4. **请求前缀的稳定由策略自己负责，平台度量。** 策略改变已发送过的前缀会降低提供商的前缀缓存命中（AGENTS.md 的不变量）。平台不禁止，但评测报告的"缓存命中"列与计量按 AgentDef 区分，使代价可见；改动策略时须 `make eval` 比较。

### 二、流式外部循环

5. **草稿经实时增量推送，最终回复照常提交。** 外部服务可以按步流式返回；Worker 把收到的片段作为实时增量推送给订阅者（ADR-0013 的直接拉取，不进日志）。整条回复返回后，照常在写日志前送内容安全检查、写入 `AssistantMessage`。草稿是可被覆盖的（ADR-0021）。
6. **已输出过增量的步不在连接层重试。** 沿用[模型调用](../design/model-calls.md)的规则：订阅者已经看到部分输出时，重试会让它们看到两份；失败交给 Worker，下一步重新请求，连续失败计入出错预算，客户端丢弃未提交的草稿。
7. **状态带版本。** `state` 仍是外部服务给自己的不透明数据（至多 64 KiB，随回复写入日志、随 Session 删除），另加一个由外部服务填写的版本号，便于它在升级后识别旧格式。平台不解释它。
8. **用量分两份。** 平台按步计量，用于配额与计费（ADR-0019）；外部服务可以上报它自己调用模型的用量，平台只作为"业务线自报"的属性记录，用于报表，不参与配额判断。外部服务调用模型时的缓存由它自己负责。

## 待回答的问题（已于 2026-11-16 定稿，答案见下一节）

1. 上下文策略的接口：是每次调用模型前一次远程请求（延迟、可用性、失败时的默认路径），还是在 AgentDef 中声明式描述（能力有限，但不需要远程服务）。失败时是否退回平台的默认组装（ADR-0030 的"失败走默认路径"）。
2. 候选集合的范围：是否包括已被压缩的原始事件、其他 Run 的事件、`scope: run` 之外的内容；与 `context.scope` 的关系。
3. 追加内容的大小上限与内容安全的成本（每次调用模型都要检查新追加的部分）。
4. 流式草稿的内容安全：监管若要求草稿也不得展示违规内容（ADR-0021 的重审条件），流式外部循环同样受限。
5. 外部服务自报用量的格式，以及报表中如何与平台计量区分展示。

## 定稿的答案（2026-11-16）

以下答案经逐条讨论确定，修订上文"提议的决定"中与之冲突的表述；实施时以本节为准。

### 范围与分期

- **Q1 分两期。** A 期：上下文策略，不依赖 ADR-0041，可以单独实施。B 期：流式外部循环，与 0041 的外部循环一并实施。本次只定稿答案，不写代码；A 期等业务线提出需要时实施，B 期等 0041 开始实现时实施。

### 一、上下文策略（A 期）

- **Q2 接口是远程服务。** 策略是业务线登记的远程服务（不是 AgentDef 中的声明式描述），时限短，默认 2 秒。超时、出错或返回不合法时退回平台的默认组装，并记下原因（ADR-0030 的"失败走默认路径"）。
- **Q3 每个 Run 调用一次。** 只在 Run 开始时、召回的位置请求一次策略，结果写成 Event；Run 内各步不再请求，Run 内上下文仍只在尾部追加，Run 内的请求前缀保持稳定。
- **Q4 候选按整个 Run 选择，只在默认视图中选。** 候选是本 Session 默认视图（压缩之后）中更早的 Run、压缩摘要与本 Run 的召回；已被压缩的原始事件与其他 Session 不是候选。当前 Run 总是保留，不可去掉。`context.scope: run` 与策略互斥，同时声明是配置错误。
- **Q8 追加内容。** 只能是文字（媒体、卡片、卡片动作与旁听片段一律拒绝，这些只能由平台写入，ADR-0052）；每个 Run 合计至多 16 KiB；写入日志前做一次内容安全检查（每个 Run 只写一次，所以每个 Run 只多一次检查，各次模型调用不再重复检查）。审核拒绝或超限时整份策略结果作废、退回默认组装并记下原因。追加内容的来源一律推导为外部内容，放在 Run 的位置上（与召回同处），作为单独标注的一段业务上下文。
- **Q9 只选择，不排序。** 选中的更早 Run 保持时间顺序；召回可以去掉，保留的仍按原顺序。打乱时间顺序容易让模型误判先后，调用与结果的配对、摘要的位置也难以解释。已知代价：每个 Run 开始时的选择不同会让该 Run 第一次调用的前缀不命中缓存，按第 4 条计量，不禁止。
- **Q10 事件形态。** 新增一种事件 `ContextSelected`，在每个 Run 开始、该 Run 第一次调用模型之前写入，成功与退回共用：`run_id`、`strategy`（登记名）、`runs[]`（选中的更早 Run 的 ID）、`summary`（是否保留压缩摘要）、`recalls[]`（保留的召回 Memory 的 ID）、`appended[]`（追加的文字段）、`fallback`（退回原因；非空时其余字段为空，按默认组装）。`Transcript` 从投影读取，回放不再请求策略服务。它改动 `State` 与 `Apply`，须递增 `ProjectionVersion`；`Apply` 校验 `runs` 只含本 Session 更早的 Run、`appended` 只含文字。
- **Q11 发给策略服务的是摘要，不是全文。** 请求包含：本 Run 的输入文字；每个候选 Run 的 ID、时间、输入文字与最终回复文字（不含工具调用与结果）；是否有压缩摘要；每条召回的 ID、类别与文字。这仍是用户内容（输入可能含旁听中他人的话），数据义务与外部循环相同：业务线登记时确认保留与删除义务，外部地址只来自显式登记（ADR-0001）。策略也可以只按 ID 查自己的业务索引来决定。
- **Q12 治理看完整历史。** 来源推导（`session.Provenance`）、写入闸门与注入判断照旧读取整个 Session 的历史，不看策略选了什么：策略去掉一个含外部内容的更早 Run，不能让 Session 变"干净"（与 `scope: run` 的现行做法一致）。能力白名单与审批不受策略影响。选择只能让上下文变小，不能让规则变松。
- **Q13 与压缩、外部循环的关系。** 压缩不变：仍对本 Session 的历史做摘要，策略在压缩后的视图中选择；一个 Run 的视图超过窗口时走现有的"溢出先压缩"路径，策略不另设截断机制。AgentDef 同时声明 `loop` 与 `context.strategy` 时，发给外部循环的 `messages` 就是策略选择后的视图，组装只有一条路径。
- **Q14 声明与登记。** AgentDef 写 `context.strategy: <name>`；策略登记在 `contexts/*.yaml`，字段与 MCP、外部循环的登记一致：`name`、`business_line`、`url`、`headers`、`timeout`（默认 2 秒）。策略属于其他业务线，或与 `scope: run` 同时声明，Run 以配置错误失败（与外部循环相同）。契约放在 `proto/` 中（实施时新增 context_strategy.proto），以 HTTP+JSON 传输。

### 二、流式外部循环（B 期）

- **Q5 流式草稿的内容安全。** 与内置循环的流式输出同一条规则：草稿经实时增量推送、不进日志，整条回复在写日志前审核；ADR-0021 的重审条件触发时（监管要求草稿也不得展示违规内容），两者一起收紧。
- **Q6 自报用量的格式。** 外部服务在回复中可附 `reported_usage[]`，平台记为 `Kind="loop_reported"` 的用量记录，费用为 0，不计入配额，只用于报表；平台按步的计量记为 `Kind="loop"`，计入配额与计费（ADR-0019）。报表按 Kind 分开展示。
- **Q7 流式协议。** 外部服务以响应的 Content-Type 选择：`application/x-ndjson` 时逐行返回增量，最后一行必须是完整的 `LoopStepResponse`（缺少即视为该步失败）；否则按第一版的整条 JSON 处理。连接层不重试（第 6 条）。

### 对上文的修订

- 第 1 条"以什么顺序"、第 2 条"选择与排序"改为只选择（Q9）；第 2 条"在每次调用模型之前"改为每个 Run 开始时一次（Q3）。
- 第 2 条"经内容安全检查"的成本按 Q8：每个 Run 一次。

## 必须验证

- 模拟测试：回放不请求策略服务与外部循环；策略超时、出错、超限或审核拒绝时退回默认组装并写入 `fallback`；策略服务或外部循环在写入前崩溃、重复请求时以写入日志的那次为准；状态恢复。
- 权限与来源：策略追加的内容在 `session.Provenance` 中是外部内容；策略无法使任何内容被推导为用户原话或平台来源；能力白名单与审批不受策略影响。
- 前缀稳定：默认策略（平台组装）下缓存命中不退化。
- 评测：新增使用自定义策略的用例（`evals/` 中按 ADR-0018 固定），以及流式外部循环的端到端用例。

## Considered Options

- **把上下文组装整个交给外部循环**：外部循环本来就拿到完整视图，可以自己裁剪后再调用它自己的模型。这对外部循环已经成立；本提案要解决的是内置循环（平台调用模型）的上下文也能由业务选择。
- **允许策略改写内容**（摘要替换原文、改写来源标注）：最灵活，但改写后的内容来源无法推导，写入闸门与注入判断失去依据（ADR-0052 第 4 条）。
- **流式时在连接层重试**：对订阅者不透明，会出现重复的草稿。

## Consequences

- 实施时修订 ADR-0041（A 期修订第 1 条"平台照常组装上下文"，B 期修订"第一版不流式"），并更新 m5 设计 §7、长 Run 设计与模型调用设计。
- 新增策略与流式的契约放在 `proto/`，只做向后兼容的修改。
- 上下文工程从"改平台"变为"登记一个策略"，与章程原则 1 一致；代价是每次调用模型可能多一次远程请求。

## 重审条件

- 实施（A 期或 B 期）或放弃本提案时更新状态；
- 业务线需要按 Run 内各步调整上下文（Q3 不够用）、需要排序（Q9）或需要追加非文字内容（Q8）时重审；
- ADR-0041 开始实现时，与本提案一并核对。
