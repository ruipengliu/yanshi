# Memory 召回记录为 Event，Grant 按"业务线对 + 类别"授权

每个 Run 开始时，Worker 检索 EndUser 的 Memory（本业务线的，以及经 Grant 可读的其他业务线的），把结果作为 `MemoryRecalled` 事件写入日志，只用于当前 Run 的上下文。Grant 由 EndUser 授予，形式是"允许业务线 B 读取我在业务线 A 中这些类别的 Memory"，可以撤销、可以设置到期时间。Memory 存放在 PostgreSQL + pgvector 中。

我们没有选择"组装上下文时临时检索"：结果会随时间变化，破坏回放的一致性（ADR-0004），也无法留下访问记录。也没有选择"按单条授权"或"整个业务线授权"：前者让用户无从判断，后者粒度过粗，无法只共享偏好而不共享人际关系。

## Consequences

- 召回事件同时就是访问记录，EndUser 可以查看哪个业务线在什么时候用了什么。
- 撤销 Grant 不会删除 B 侧已经记录的召回（它们属于 B 侧的对话历史），但从下一个 Run 起不再召回；之前 Run 的召回不进入之后的上下文。
- 类别是平台固定的分类，扩展类别属于平台变更；敏感个人信息不在任何类别中，平台拒绝写入。
- 不新增存储组件；没有嵌入服务的环境退化为确定性的文本相似度检索。
