独立方案（提案）2026-11-07不约束本仓库的现有实现：现行实现仍以 docs/design 为准

机主全天佩戴，录音经手机批量上云。方案要回答三件事：哪些声音不该进转写和记忆，转写准不准（尤其专名），以及每句话是不是机主说的。原则是宁可漏记，不可错记。

§0结论

批处理链路领夹 → 手机暂存 → 按批上云 → 异步处理 → 回传 App。新鲜度为小时级，提供“立即同步”。
四级拒识级联越靠前越便宜，也越保守。设备和手机只丢非人声，像人声的一律上云。
三档处置拒绝只用于非语音和无语音帧的幻觉；播放声、不确定、疑似回放一律隔离 7 天，可放回。
8B 单路全量600M 只做对齐与可疑片段校验。级联路由每人每月只省约 ¥3估算。
三类热词解码前按上下文检索出偏置表，只解码一次；解码后拼音召回，再做闭集纠错。
机主判定一期纯声纹（门槛更严）；二期按 VPU 三态 × 声纹三档融合。记忆与待办只引用“证据级”原话。
VPU 的边界它分得清“机主”和“非机主”，分不清电视和在场的真人。90% 播放声召回一期大概率达不到。
约 ¥25/人/月按每天 5 小时、8B ¥0.10/小时自部署口径估算，落在 ¥23–27 内；对有效时长最敏感。
音频处理完即删摘要不在等待之列。代价是不能事后重跑；低置信区间保留文字候选。

§2总体架构

架构分三层画：L0 看全局和闸门位置，L1 看每段由什么组成，L2 看关键闸怎么判。每佩戴 1 小时，上云约 0.35 小时，送入 8B 约 0.25 小时。

五条设计原则

  1. 不可逆操作最保守：丢音频、不送识别、改写文字，证据充分才做。
  2. 越靠前越便宜，但越靠前越不许误杀人声。
  3. 处置只收紧不放宽；只有用户“放回”可以升级。
  4. 宁可漏记，不可错记；不确定区占比单独计量。
  5. 每一级都能单独开关，与“不做”配对评测。

§3硬件（领夹）

设备只做拾音、门控、压缩、缓冲、打时间和传感器特征；ASR、声纹、播放声判定都放云端。二期整机平均功耗估算 2.2–5.2 mW，建议电池 60–80 mAh。

麦克风阵列

方案提供什么结论
单麦相对机主基线的声级、直达/混响比一期现状
双麦（上向 + 外向）方向先验、相干性二期基线
三麦及以上更好的波束与定位不做：功耗、尺寸

近场线索：机主约 20 cm、他人约 1.5 m，声级差约 17.5 dB估算；近处他人和开大的电视会破坏它。

§4手机端

手机是中间处理层：拼时间线、校时钟、做 L1 拒识、记场景、调度上传、管删除链。L1 只丢高置信非人声，而且在上传前批量运行，优先在充电时进行。

分片与时间线

  • 上传分片固定 5 分钟设备时间（15,000 帧），不按语音切。
  • 主键 (device_id, boot_generation, frame_seq)，乱序与补传都能拼回原位。
  • 缺口不压缩时间轴；开启 DTX 时只按帧序号推算时间。
  • 原样保存设备码流，L1 只解一份临时 PCM。

时钟校准

  • 同步点：每次连接 + 连接中每 5 分钟。
  • 线性拟合 offset、drift_ppm；日漂移 ≤1.7 s估算。
  • 异常：重启（世代变化）、手动改时间、拟合残差过大 → 分段重拟合，标 sync_quality_ms。
  • 录音时刻还原误差 ≤200 ms目标。

L1 拒识

  • 只丢：VAD 高置信非语音，前后各留 500 ms 后仍为非语音；间隔 <2 s 的语音段合并。
  • 只打标签：声音事件（电视、音乐等）、本机外放区间。
  • 一期是第一道丢弃闸，挡掉全天约 75% 非语音假设；二期只复核。

平台机制待确认

  • iOS：BLE 中心后台模式接收；BGProcessingTask（可要求外接电源与网络）跑 L1；后台 URLSession 上传。
  • Android：connectedDevice 前台服务 + WorkManager 约束。

场景事件（随清单上云，按录音时刻关联）

设备离线缓冲时，“手机收到分片”可能比录音晚几个小时，所以按事件时间线记录，不在收到时取一次快照。

§5云端

云端在“转写库”处分成两段：前段需要音频，做拒识、转写、判定与裁决；后段只读文字，做入库与下游。

5.1 拒识级联

G3 证据来源判别力局限
声学回放特征回放检测模型，自建重录语料训练扬声器频响、压缩痕迹、房间混响好音箱近距离不明显；16 kb/s 抹掉细节
手机场景快照§4.4本机外放几乎确定不覆盖电视、电脑、别人的手机
空间特征（二期双麦）方向长时间不变、相干性低、混响大固定远场声源坐着不动的真人也是固定方向
交互特征（G6 计算）机主是否与该声源轮流发言电视不会接机主的话需识别之后才能算
VPU（二期）机主是否在发声只判机主有没有说话分不清电视和在场的真人

G4 幻觉防护

  • 无语音不送 8B（G2 保证）。
  • 健康检查：重复 ≥3、字速 >9 字/秒、压缩比、幻觉短语表（“谢谢观看”、字幕组署名…）、低置信、语种突变。
  • 可疑约 20%估算用 600M 重识别：距离小 → 保留；距离大 → 隔离；无语音帧 → 拒绝。
  • 不按“不通顺”删；不删与语音帧重叠的输出。

G6 内容门控的边界

对风格化内容（广告、播报、歌词、剧台词）有效；对“电视里的普通对话”和“在场真人的闲聊”基本无能为力，这部分只能靠声学与空间特征。90% 播放声召回要按内容类别分别报告。

回放机主录音手段残余
一期本机外放 + 声纹高 → 疑似回放；回放特征别的设备回放防不住
二期声纹高 + VPU 有效且静默 → 隔离VPU 失效时退回一期

模型职责处理量

5.3 热词：三类来源，三层机制

类别来源规模估算维护
公共运营整理的新词、热门实体1–5 万按版本发布；评测集上召回与误插入不回退才发布
行业按行业分包每包 0.5–3 万用户在引导页自选，可多选；不从录音推断行业
个人通讯录（近 90 天）、日历参会人与标题专名、项目、纪要中出现 ≥2 次的专名几百–几千自动收集，时间窗生效；可查看、删除；随用户删除

评测要点：三类分别报告召回率与误触发率，另报偏置表截断造成的召回损失、时间窗外误触发、行业包扩大后误触发的变化。误触发不达标时先缩小 N，再提高纠错门槛。

5.4 声纹注册（约 1 分钟）

  • 必须用领夹录：手机麦克风注册会造成信道失配。质量检查看信噪比、有效时长、各段嵌入的一致性。
  • 单独同意，与录音同意分开；可随时删除或重新注册，旧版本立即失效，未入库的片段转为不确定。
  • 不自动更新，防外放或冒认投毒；得分分布持续下移时提示重新注册。

5.5 专名纠错（默认关闭）

输出只能是 diff

{
  "edits": [
    {"start": 12, "end": 14,
     "from": "章威", "to": "张伟",
     "candidate_id": "c3",
     "reason": "上下文为会议参会人"}
  ]
}

原识别文字与 diff 一起保存，App 可查看原识别、一键撤销。

校验（任一不过即丢弃该条）

  • from 与原文 [start,end) 完全一致
  • to 必须是该候选词：闭集选择
  • 不碰否定、数字日期、情态、改口标记
  • 拼音相似度达到门槛
  • 每段最多 3 条
  • 满足按类别分级的证据门槛（下表）
类别额外证据要求
个人拼音匹配 + 上下文相关即可
行业还须满足其一：8B 与 600M 在此处不一致，或 8B 在此处置信度低
公共同“行业”，并且不能只凭拼音相近触发

5.6 机主判定

流程

  1. 当天匿名聚类（CAM++ / ERes2NetV2 一类），簇号只在当天有效。
  2. 片段级得分 + 簇级得分（簇累计 ≥10 s 语音后）。
  3. <1.5 s 短片段：簇得分高、离簇中心近、不与他人相邻或重叠时才随簇；否则不确定。
  4. 重叠段转为不确定。
  5. 近场特征只作辅助与否决，不能单独授予机主。

证据级 ≠ 时间线级

证据级条件：声纹 ≥T_evidence（高于 T_high）；二期还要求 VPU 有效且有发声；不在重叠或邻近重叠处；片段 ≥1 s。

理由估算：他人每天可能说 2–3 小时，1% 误判就是每天 1–2 分钟被标成机主，足以每周产生数条错误的“我答应的”待办。

阈值只在调参集选定；T_high、T_evidence 按误判上限定，不随召回放宽；T_low 按召回定。

5.7 三档裁决与下游差异

接受隔离拒绝
存文字是，按用户留存设置是，7 天后自动删除否，只记时长与原因
App 时间线正常显示折叠、标原因、可放回只显示“已过滤 X 分钟”
纪要进入不进入—
待办可引用（按 G8 核对）不可—
记忆证据级机主原话可写入不可—
搜索可搜只在隔离区内可搜—

5.8 入库闸门（G8）

产物规则
纪要只读接受档；机主与他人的话都可作上下文
机主的待办（我答应的）至少引用一段证据级机主原话；否则“未核实”：照常展示，不按期限提醒
他人的待办（对方答应的）至少引用一段他人原话；否则“未核实”
记忆只从证据级机主原话抽取关于机主本人的事实；他人话里关于机主的说法不写成事实；从他人话中得出的内容不进长期记忆（除非用户确认）
溯源每条待办和记忆记录引用的片段 ID，用于撤回与污染率评测

§7删除链

设备等手机回执、手机等云端回执、云端等文字落盘。音频在需要音频的环节完成后即删，纪要、待办、记忆不在等待之列。

放弃了什么

模型升级后不能重转历史音频；误拒或误判无法回到声学层复核。

为什么接受

长期保存全天录音是最大的隐私风险源，还包括大量他人的声音；需求明确要求删除链。

怎么缓解

  • 上线前充分评测
  • 低置信区间保留文字 top-3 候选
  • 隔离区 7 天纠正窗口
  • 不设保留音频的后门

其他保护：日志与指标只记 ID、时长、计数与分数分布；传输 TLS；暂存与对象存储按用户数据密钥加密。

§10分阶段路线

一期在现有设备上把软件链路做完整，必须能独立上线；二期验证 VPU 与播放声可分性；三期做模型级优化与降本。

一期

做：手机端全套、云端 G2–G8、8B + 600M、声纹注册与一期规则、三类热词、纠错（评测后开）、三档与隔离区、评测集。

退出标准目标

  1. S1 上限 <2%
  2. S2 时间线级 ≤1%，证据级 ≤0.5%（过渡）
  3. R1 ≥98%，R3 <2%
  4. O1 ≥85%（过渡）
  5. CER 近场 <8%；远场、全天按基线冻结
  6. R2 按类别报告并给出差距
  7. 删除链故障注入后无遗留音频
  8. 实测成本 ≤¥27/人/月

二期

做：双麦 + VPU/骨导（两套对照）+ IMU 原型 10–20 台；G0；VPU 特征上报；融合规则；空间特征；回放检测训练；功耗实测。VPU 验证必须用真人自然发声。

退出标准目标

  1. VPU 命中 ≥95%，外部声误报 ≤2%，“无效”识别 ≥95%；不达标换形态再测，仍不达标退回一期规则
  2. O1 ≥90%，S2 时间线级 ≤1%、证据级 ≤0.2%
  3. S4 疑似回放拦截 ≥95%
  4. R2 ≥90%，“电视普通对话”单独结论
  5. 平均功耗 ≤5 mW，续航 ≥24 h
  6. 开启播放跳过时，真人误拒增量 ≤0.2 个百分点

三期

做：8B 领域适配（16 kb/s、远场、口音）；偏置专项训练；以 VPU 为条件的判定模型取代手写融合表；扩充重录语料；VAD/事件蒸馏到手机；8B 量化与批处理；可选家人自愿注册“已知他人”。

退出标准目标

  1. CER 全场景达标
  2. O1 ≥92%，S2 不回退
  3. 8B ≤¥0.08/h 或成本 ≤¥22/人/月
  4. 每次更新通过回归

§11风险

影响最大的四项：VPU 信号不稳、同音色家人、旁观者同意、声纹合规。可能性与影响的分级是本文的判断估算。
