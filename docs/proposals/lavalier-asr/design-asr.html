详细设计 · 识别

云端音频段：拼接与作业调度，VAD 复核与识别窗口（G2），播放检测（G3），8B 主干转写，600M 辅助与健康检查（G4）。这一段是唯一接触音频的地方，中间结果只在内存。

读法。每节按同一模板：职责与边界、原理、流程、数据结构与接口、算法、参数、失败与恢复、测试与验收、未决项。“作业”指一次音频作业：在一个进程里跑完 G2–G5 再落盘（§5.11）；本页写 G2–G4，G5 与落盘见说话人与热词与裁决、文字与删除。共同约定：区间一律左闭右开；身份与去重用设备帧坐标 (device_id, boot_gen, seq, sample_offset)，UTC 只用于展示、场景关联与截止时间，时钟重拟合不改变任何 ID；文字跨度用 Unicode 码点索引；概率可以为空并带覆盖状态，缺失的证据不编码成 0；模型、预处理、规范化、阈值与校准器分别版本化，模型升级后旧校准器不能默认沿用。

职责与边界

四个对象分开：

  • 拼接器（每用户单写者）只处理清单、帧覆盖、乱序、缺口与等待期限。它优先用 L1 明确丢弃的 ≥1 秒区间作安全边界，不能从清单推断保留音频里的 300 ms 停顿，也不选能量最低点：这两件事归 G2。连续会议或 L1 被跳过时 10 分钟内可能没有这种区间，此时在 10 分钟处、世代末端或序号空洞前按帧取暂定边界；作业照常运行，由 G2 在边界前找停顿，停顿之后的部分作为尾部顺延给下一段，所以暂定边界不会切进识别窗口的核心区。
  • 两级队列：立即同步优先，常规按最晚开始时间；派发带租约与防护令牌。
  • 作业状态与对象删除状态分成两条状态机：一个作业可以读多个对象，一个对象也可以被多个作业读。

原理

  • 确定性 ID 解决“重复创建”，租约解决“谁在执行”，防护令牌解决“过期执行者能否提交”，三者缺一不可。
  • 切分提议由 G2 给出、由拼接器冻结。 作业领取后先解码、跑 G2，得到“本次定稿到哪里、哪段尾部顺延、需要读哪些上下文”的最小提议，用 CommitPlan 交拼接器原子地冻结；此后 G3–G5 在内存里接着跑，下一个作业可以并行开始。冻结的计划含归属切点与识别窗口边界；重试时重新解码、重新计算 G2 的证据（语音掩码、质量），但不改切点、窗口与范围归属。执行配置不在冻结范围内：它带自己的代次 exec_gen，热词删除或撤权、8B 阻塞超 12 小时降级时，用 RebindExec 原子换代并作废当前租约；接管者按同一组冻结窗口全部重新解码。这样撤权不会让旧快照永远提交不了，切点也不因换配置而移动。所有归属切点都量化到设备帧边界（20 ms），覆盖账因此只记整帧；sample_offset 只用于窗口内部的样本映射。
  • 同设备、同启动世代的作业按顺序分配。 下一段等前一段的计划冻结后再分配，这样前一段产生的尾部一定在下一段分配之前并入；冻结之后 G3–G5 仍可并行。
  • 删除看覆盖账，不看水位。 [0,100) 与 [200,300) 完成了，不能把进度记为 300 后删掉还含 [100,200) 的对象；下一作业还要读的 400 ms 左上下文也算依赖。
  • 截止时间驱动调度。 常规截止 = 录音结束 + 3 小时；同步截止 = 上传完成 + 10 分钟。按“最晚开始时间 = 截止 − 预计处理时长”派发，负载自然摊到低谷。离线数小时后补传的数据达不到端到端 3 小时，“录音到上传”与“上传到可见”分开统计，不靠改起点掩盖。

算法

def on_chunk_stored(c):                                    # 拼接器，每用户单写者
    register_coverage(c)                                   # L1 丢弃 → l1_dropped；设备缺口 → source_gap
    try_assign(c.device_id, c.boot_gen)

def try_assign(dev, gen):                                  # 拼接器；分片到达、计划冻结、尾部到期时调用
    with user_txn(user_of(dev)):
        rng = next_unassigned_range(dev, gen)              # 未分配、连续可用的帧；序号空洞处停止
        for hold in waiting_tails(dev, gen):               # 先处理到期或被强制释放的独立尾部，不等前一段冻结
            due = hold.release_at_ms <= now_ms() or hold.force_release
            if due and not (rng and adjacent(hold, rng)):  # 不紧邻下一批（中间有空洞或没有下一批）：单独成作业
                job = create_job(input_ranges=hold.ranges, queue=hold.queue_class, final_release=True,
                                 visible_deadline_ms=hold.visible_deadline_ms)
                hold.state, hold.assigned_job_id = "assigned", job.job_id
                transfer_read_dependencies(hold, job)      # 同一事务转移依赖
        if unfrozen_job_exists(dev, gen): return           # 前一段未冻结：等它，紧邻的尾部才不会被越过
        if not rng: return
        hold = waiting_tail_before(rng)                    # 只能是紧邻 rng 之前、仍在等待的尾部
        start = hold.ranges[0].start if hold else rng.start
        end = last_safe_boundary(rng, max_audio_min=10)    # ≥1 s 的 L1 丢弃区；没有就在 10 分钟、世代末或空洞前取暂定边界
        queue = max_priority(queue_of(rng), hold.queue_class) if hold else queue_of(rng)
        deadline = min(deadline_of(rng), hold.visible_deadline_ms) if hold else deadline_of(rng)   # 合并取最高优先级、最早截止
        job = create_job(input_ranges=[(start, end)], queue=queue, visible_deadline_ms=deadline,
                         final_release=False)                # 同 ID 已存在则返回既有作业
        add_read_dependencies(job, input_and_context(start, end))   # 首次读音频之前登记
        if hold:                                           # 同一事务：并入尾部、转移依赖
            hold.state, hold.assigned_job_id = "assigned", job.job_id
            transfer_read_dependencies(hold, job)

def commit_plan(job, proposal):                            # 作业跑完 G2 后调用
    with user_txn(job.user_ref):
        if job.plan: return job.plan                       # 重试：沿用冻结的计划
        require_lease(job, proposal.lease_epoch); require_erasure_epoch(proposal.erasure_epoch)
        require(proposal.exec_gen == job.exec_gen)         # 执行配置已换代：本次尝试作废
        require(job.state == "running")                    # 终态、擦除取消的作业不能冻结
        require(disjoint(proposal.commit_ranges, proposal.tail_ranges))
        require(union(proposal.commit_ranges, proposal.tail_ranges) == union(job.input_ranges))
        require(all(on_frame_boundary(r) for r in proposal.commit_ranges))
        if proposal.tail_ranges:
            hold = TailHold(ranges=proposal.tail_ranges, first_deferred_at_ms=inherit_or_now(proposal),
                            release_at_ms=release_deadline(proposal, job))
            add_read_dependencies(hold, proposal.tail_ranges + proposal.read_ranges)  # 尾部独立持有依赖
        job.plan = freeze(proposal); job.state = "planned"
    try_assign(job.device_id, job.boot_gen)                # 计划冻结后才分配下一段

def persist_result(req):                                   # ①
    with user_txn(req.user_ref):
        job = load_job(req.job_id)
        if job.state == "persisted": return already_committed(job.result_digest)
        require_lease(job, req.lease_epoch); require_erasure_epoch(req.erasure_epoch)
        require(req.exec_gen == job.exec_gen)
        require(job.exec.bias != "applied" or job.exec.bias_revoke_epoch >= current_bias_revoke_epoch(job.user_ref))  # 撤权与换代之间的竞态兜底
        require(req.bias_table_refs == [(t.win_id, t.bias_snapshot) for t in job.exec.bias_tables or []])     # 各窗口用的就是当前代的表
        require_exact_coverage(req.coverage, job.plan.commit_ranges)
        write_segments(req.segments); update_clusters_with_version_check(req.cluster_updates)
        write_coverage(req.coverage); release_read_dependencies(job.job_id)
        job.state = "persisted"; emit_id_only("job.persisted", job.job_id)
        for c in job.source_chunks:
            if can_delete(c): emit_id_only("chunk.deletable", c.chunk_id)   # 交删除链（详设 18）

def rebind_exec(req):                                      # 热词撤权（详设 12）、8B 降级时调用
    with user_txn(req.user_ref):
        job = load_job(req.job_id)
        if seen(req.request_id): return previous_result(req.request_id)          # 同键重放：不再作废租约
        if job.state not in ("queued", "running", "retry_wait", "planned"): return   # 已落盘或终结：不换
        if req.expected_exec_gen != job.exec_gen: return conflict(job.exec_gen)
        new_exec = job.exec.merge(req.changes)             # 只改请求涉及的维度：降级不会覆盖刚换上的撤权快照
        require(new_exec.bias_revoke_epoch >= current_bias_revoke_epoch(job.user_ref) or new_exec.bias != "applied")
        if new_exec == job.exec: return no_change(job.exec_gen)
        job.exec, job.exec_gen = new_exec, job.exec_gen + 1
        job.lease_epoch += 1; job.state = "retry_wait" if job.state != "queued" else "queued"
        # 计划（切点、窗口）保持不变；接管者用新配置把全部冻结窗口重新解码

def can_delete(c):
    return (union(coverage(c)) == c.logical_range and not active_read_dependencies(c)
            and not unassigned_tail(c))

def release_deadline(p, job):                               # 尾部最迟何时单独识别；已过即立即释放
    est = estimate_remaining(tail=p.tail_ranges)           # 识别 + G5 + 文字管线，近期 P90
    return min(p.first_deferred_at_ms + minutes(20),       # 常规最多等 20 分钟，起点不因转交而重置
               job.visible_deadline_ms - est,              # 不让尾部拖过 3 小时 / 10 分钟截止
               fail_deadline(p.source_chunks) - est,      # 48 小时失败期限
               earliest_hard_expiry(p.source_chunks) - est - minutes(30))   # 72 小时强删前留余量
  • 尾部释放：下一批到达、20 分钟到期、立即同步、会话结束（领夹断开或电量告警）任一发生即释放。release_at_ms 登记定时器，到点调用 try_assign；没有下一批时尾部单独生成 final_release = true 的作业，G2 不再顺延它（propose 里的 dec.is_final_release 取自作业的这个字段）。连续说话没有停顿时，尾部退到最后一个已完成识别窗口的边界，长度不超过一个窗口（详设 6），不会顺延整个作业。尾部等待（20 分钟）与“缺口还在路上”（2 小时，详设 16）是两种状态；缺口不能当作静音。
  • 调度：sync 池按最早截止派发；同步预留容量空闲时借给常规，在各资源池的模型批边界收回（不等整个作业结束，也不拆开正在跑的批）。常规按最晚开始时间派发，同用户最多 2 个作业并行。立即同步是对已有作业的优先级提升，不生成新的 job_id。预留与公平性覆盖 CPU、8B、600M 三个池。
  • 领取与续约：租约 120 秒、心跳 30 秒；续约失败立即停止提交。旧 worker 即使算完，也会被 lease_epoch 拒绝。失去租约不释放读依赖：接管者仍需要音频。
  • 计时锚点：48 小时失败、72 小时强删都以首次上传时间为准，不因重试、转尾部、换 worker 重置。72 小时强删是隐私兜底，可以越过正常完成条件，随后只为未完成范围登记 cloud_failed，已落盘结果保留。

测试与验收

  • 重复、乱序、重叠清单；同 chunk_id 不同内容必须报冲突。
  • 租约过期后两个 worker 同时提交，只能成功一次；时钟重拟合不改变作业 ID；立即同步提升优先级不重复转写。
  • 前一段未冻结时下一段不分配；尾部到期时刻已过的作业立即释放尾部；没有下一批时到期尾部单独成作业且不再顺延；8B 与热词同时故障时执行配置两个维度都降级；计划冻结后撤权，换代后能提交、旧尝试被拒；10 分钟连续说话没有 L1 丢弃区时按暂定边界切出作业。
  • 多个作业覆盖同一对象、尾部与上下文仍被引用时不可删除；G2 全部拒识、空载荷、局部解码失败也能闭合覆盖账，不会永久卡住删除。
  • 负载：按一天的到达曲线回放 1 万用户的清单，常规 P90 ≤3 小时、同步 P90 ≤10 分钟（§9）。

与提案的差异

  • s-stitch 的“在 ≥300 ms 停顿处切”改由 G2 承担，拼接器只按已知静音切作业。
  • §5.12 的 frames_persisted_upto 由覆盖账取代；§5.11 的作业状态与对象删除状态拆成两条。
  • §5.14 的“桶内超过 24 小时的对象数应为 0”是告警线，不是硬上限；硬上限是 72 小时。

职责与边界

  • 解码：按清单的 payload.runs 把每个 chained Ogg Opus 逻辑流解码为带来源坐标的 PCM，核验清单与载荷一致。
  • G2：在云端重做 VAD，得到语音段与非语音段（非语音 → 拒绝 non_speech，不送 8B）；把语音组成识别窗口；给拼接器提议本作业定稿到哪里（详设 5 的 CommitPlan）。
  • 不做：说话人分段（详设 10）、播放判定（详设 7）。

原理

  • 三条时间轴不能互相代替：设备时间（缺口、轮次、场景、交互、删除覆盖）、解码音频时间（实际存在的 PCM 样本）、模型输入时间（加了上下文的窗口）。L1 丢弃的区间在设备时间上存在、在解码音频里不存在。
  • Ogg Opus 的 pre_skip 与 granule 用 48 kHz 单位；设备把 pre_skip 设为“编码延迟 + 预卷样本数”（详设 4），所以解码接口返回裁掉 pre_skip 之后的 PCM，其中已经没有预卷样本，第一个样本对应 runs.core_from 帧的起点。业务层不能再减一次预卷，否则会丢字（RFC 7845 §4.2）。尾部同理：设备多带一个后续包、用末页 granule 裁尾（RFC 7845 §4.4），解码器必须执行末尾裁剪；样本数应等于核心区长度减 runs.tail_short_samples（取不到后续包时尾部缺的编码延迟，48 kHz 单位，16 kHz PCM 上除以 3）。缺的样本补零并标 concealed，最后一帧照常按整帧进覆盖账。多数情况下这 ≤20 ms 落在核心区的非语音余量里；但连续讲话跨 5 分钟硬封口、立即同步截断或 L1 被跳过时可能是语音，所以它只进 unknown、不当语音证据也不当静音，片段在 low_support_spans 里标出可能被截掉的字尾。
  • 两种语音区间分开存。 原始语音掩码 speech_raw（滞回的直接输出）用于找停顿、算字速、判无语音；送识别的保留区间 keep 是它加前后余量的结果。在加过余量的区间上找停顿，800 ms 的真实停顿会被两侧共 1100 ms 的余量填平。
  • 平滑不能吞掉短回应。 “前后各 0.5 秒的双向上下文”若实现成 1 秒均值滤波，150 ms 的“嗯”会被平均到约 0.15、低于启动阈值。所以用短时中值滤波去毛刺，再用双阈值滞回；高置信的短峰单独保留为可疑语音。双向的好处体现在离线可以向后看：结束判定等 200 ms 确认，而不是看到一帧低值就结束。
  • 识别窗口越长，8B 上下文越足、组批效率越高；越长也越容易漂移或幻觉。15–45 秒是打包目标，不是准入门槛；短回应并入相邻窗口，不单独成窗、也不为凑长度补造语音。
  • 一期不压缩静音。 窗口里只放语音段及其间的短停顿；长于停顿阈值的非语音本来就是窗口边界，不需要压缩。压缩已知静音作为变体。

def decode(obj, manifest):
    verify_sha256(obj, manifest.payload.sha256)                    # 不符 → 对象校验失败，不当静音
    out = []
    for run in manifest.payload.runs:
        pcm = opus_decode_stream(obj.stream(run.stream_serial))   # 返回裁掉 pre_skip（含预卷）之后的 PCM
        short = run.tail_short_samples // 3                       # 清单按 48 kHz 记，PCM 是 16 kHz
        if len(pcm) != expected_samples_16k(run.core_from, run.core_to) - short:   # 清单与样本数不一致
            raise TimelineMismatch(run)                            # 不偷偷拉伸 PCM
        pcm = pad_zeros(pcm, short)                                # 尾部缺的 ≤20 ms 补零，SampleMap 记 concealed：
        out.append(map_samples(pcm, run, concealed_tail=short))    # 覆盖账仍按整帧记，这段只进 unknown，不当语音也不当静音
    return Decoded(out)

def g2(dec, frozen=None):
    W, raw_all, keep_all = [], [], []
    for region in dec.contiguous_valid_regions():                  # 真实缺失与 concealed 处断开 VAD 状态
        p_raw = vad(region.pcm)                                    # 适配器给出模型原生步长（Silero 512 样本，FSMN 10 ms）
        p = median_filter(p_raw, ms=50)
        raw = hysteresis(p, on=0.60, off=0.35, end_confirm_ms=200, min_speech_ms=150,
                         rescue=lambda seg: max(p_raw[seg]) >= 0.85)  # 高置信短峰保留为可疑语音
        if not raw: continue                                       # 整段非语音：不切窗
        keep = clip(pad(raw, pre_ms=400, post_ms=700), region)
        raw_all += raw; keep_all += keep
        if not frozen:
            W += make_windows(region, raw, keep, max_in_s=min(45, MODEL_MAX_S), ctx_ms=400)
    if frozen: W = frozen.windows                                  # 重试：证据重算，窗口与切点不动
    valid = dec.valid_original_ranges()
    return G2Result(speech_raw=raw_all, keep=keep_all,
                    non_speech=complement(keep_all, within=valid),  # 只在有效原始音频里取补集
                    unknown=dec.invalid_ranges() + dec.concealed_ranges(), windows=W,
                    proposal=None if frozen else propose(W, raw_all, dec))

def make_windows(region, raw, keep, max_in_s, ctx_ms):
    max_core = max_in_s * 1000 - 2 * ctx_ms                        # 45 s 上限包含上下文
    out, start = [], keep[0].start
    while start < keep[-1].end:
        cands = pauses(raw, start + 15_000, start + max_core, min_ms=300)   # 停顿在原始掩码上找
        if cands:
            best = max(cands, key=lambda q: (len(q), -abs(mid(q) - (start + 30_000)), -q.start))
            cut, why, ctx = mid(best), "pause", 0                  # 最长停顿；并列取更近目标长度、再取更早
        elif speech_end_from(keep, start) <= start + max_core:
            cut, why, ctx = speech_end_from(keep, start), "end", 0
        else:
            cut, why, ctx = argmin_energy(start + max_core - 5000, start + max_core, win_ms=100), "forced", ctx_ms
        cut = snap_to_frame(cut)                                   # 归属切点量化到 20 ms 帧边界
        out.append(Window(core=(start, cut), read=(start - ctx_prev(out), cut + ctx), cut_reason=why))
        start = next_speech_from(keep, cut)
    return out

def propose(W, raw, dec):                                          # 给 CommitPlan 的提议
    if dec.is_final_release or not W or not ends_in_speech(raw, dec.end):
        return Proposal(commit=dec.input_ranges, tail=[], windows=W)
    last = W[-1]                                                   # 末窗可能被作业边界截断
    p = last_pause(raw, after=last.core.start, min_ms=300)
    cut = snap_to_frame(mid(p)) if p else last.core.start          # 无合适停顿：退到上一个完成窗口的边界
    if cut <= dec.input_start:                                     # 整个作业只有一个无停顿的窗口
        return Proposal(commit=dec.input_ranges, tail=[], windows=W)   # 直接定稿，不顺延零长度提交
    windows = [w for w in W if w.core.end <= cut] + trim_window(last, end=cut)
    return Proposal(commit=[(dec.input_start, cut)], tail=[(cut, dec.input_end)],
                    windows=windows, read=[(cut - 400, cut)])      # 下一作业读 400 ms 左上下文
  • 核心区去重在 600M 词级对齐之后做：每个词取原始时间中点，只保留在唯一包含它的核心区那个窗口的假设；只在相邻窗口的重叠上下文里做受时间约束的匹配，不按相同字符串全局去重（否则“对对对”“不要，不要”会被删）。时间戳不可用时保留边界不确定标记，不凭字符串强删。
  • 尾部提议：作业末尾以语音结尾、且不是最终释放的尾部时，只有末窗可以顺延：在末窗里找最后一个 ≥300 ms 的原始停顿；没有就退到末窗起点（上一个完成窗口的边界）。顺延长度因此不超过一个窗口（≤45 s）。整个作业只有一个无停顿窗口时直接定稿。
  • 全部非语音：G2 全判非语音时照样提交覆盖账，驱动删除，不生成空片段。
  • 质量标记：削波比例、长时间零值、解码错误只计量，不据此删内容；可确定的损坏范围登记缺口 decode_error。

契约：

职责与边界

  • 分开回答：是否含经扬声器重放的语音；是否含现场真人语音；两者是否同时存在；是否有媒体底噪（音乐、笑声、掌声）。
  • 只打标签。 处置由 G6、G7 决定。外放远端会议应被正确识别为重放，同时仍可由 G6/G7 判为参与者；所以“经扬声器播放”与“应该记录的对话”是两个问题。
  • 不做：判断内容是否相关（G6）；判定疑似回放机主录音（需要声纹，在 G5 与 G7 合成）。

原理

  • 扬声器重放会留下痕迹：小扬声器的低频滚降与高频谐振、功放与压缩失真、房间二次混响。线性或常 Q 倒谱（LFCC、CQCC）把频响细节展开，轻量卷积网络（LCNN、ResNet 一类）在其上学“经过扬声器”与否。
  • 局限：分类器可能学到扬声器、麦克风、房间与编码链的偶然差异，在未见环境上不泛化（ASVspoof 2021 对物理回放的分析报告过这类鲁棒性问题）。好音箱近距离重放与真人难分；16 kb/s Opus 抹掉部分高频细节。所以训练与评测都用 Opus 编码后的领夹录音，按未见扬声器、房间、节目分开报。
  • 字段语义分开：p_playback_acoustic 只含声学证据；p_playback_fused 才融合场景先验。p_live 与 p_playback 不互补，混合声是单独训练的一个输出，不用两者相乘冒充。
  • 一期单麦不能可靠地把窗口级回放概率分给窗口里的每个说话人；片段级聚合时只用与该轮次重叠的窗口，并记下证据分辨率的限制。
  • 聚合保留位置。 一个轮次前 28 秒是真人、末 2 秒出现电视，若只存 max 与 any，短暂证据会扩展到整个轮次，删掉音频后也无法恢复位置。所以片段除标量外还保留按 1 秒量化的证据区间（回放、混合、媒体底噪各自的高证据区间）与有效覆盖比例。窗口概率的加权均值不是校准过的轮次概率：片段级分数另用片段级校准器（按轮次长度分组）。

原理：偏置的两种形态

两者的强度、候选空间与置信度含义都不同，不能共用参数或校准器，分别评测。

  • 前缀树浅融合（有剪枝前打分接口时）：把偏置词按 8B 的分词器建成前缀树（带失败链接处理重叠前缀）。搜索分 S(y) = log P(y|x) + B(y)，偏置分定义为

B(y) = β · Σ_{y 中已完成的词条出现} w(词条) + Φ(s(y))

其中 s(y) 是 Aho–Corasick 自动机读完 y 后的状态，即 y 的最长一个仍是某词条前缀的后缀，所以任一时刻只有一个活跃前缀，不存在取 max 还是 sum 的问题；Φ(s) = min(λ·depth(s), Φ_max)，depth 是该前缀的 token 数。每扩展一个 token 的增量 ΔB = B(y·t) − B(y)，按定义直接算。走偏后状态沿失败链接退到更短的后缀，Φ 随之下降，等于撤回多给的分；失败链接保留的后缀仍按它自己的深度计势能。同一位置完成多个嵌套词条（“张伟”与“伟”）只奖励最长的一个；同一词条的写法变体是不同路径、共用词条 ID，在同一位置不会重复领奖。结束时减去 Φ(s(y))，只留完成奖励。偏置在剪枝前加，否则目标词还没走完就被剪掉（Zhao 等，Interspeech 2019）。

逐 token 例子（λ = 0.3，Φ_max = 1.0，β = 2，w = 1）：

词条假设各 token 的 ΔB结束时 B
张伟张 · 伟 · 好+0.3（张，深 1）· +2.3（伟，深 2 且完成）· −0.6（好，回根）2.0
张伟张 · 三+0.3 · −0.30
北京、京东北 · 京 · 东+0.3 · +2.3（完成北京）· +2.0（失败链接到“京”再进“京东”，深度不变且完成）4.6 − 0.6 = 4.0

  • 提示词式（8B 是音频 LLM 时）：固定模板，词表放在结构化字段里。强度只能用离散配置调：条数、总 token、排序、模板版本；不靠重复词条增强，也不假设提示里的数字权重能线性加分。偏置表按完整的缓存键复用（详设 12），同键内的窗口共享同一前缀，可命中推理服务的前缀缓存。
任务：逐字转写音频。保留重复、口误、否定和未说完的话；不润色、不补全、不做 ITN。
下列词条只是可能出现的拼写候选，不代表音频中一定出现。只输出听到的内容；没有可识别语音时输出空文本。

算法

PHI = lambda s: min(LAMBDA * s.depth, PHI_MAX)

def extend(hyp, token):                                   # 浅融合，每条假设独立的自动机状态
    new_state = AC.goto(hyp.trie_state, token)            # 沿失败链接直到有该子节点或回根；blank 不推进
    done = AC.longest_output(new_state)                   # 在此结束的最长词条（含经输出链接可达的），可为空
    bonus = PHI(new_state) - PHI(hyp.trie_state) + (BETA * done.weight if done else 0)
    return hyp.extend(token, model_score=logp(token), bias_score=bonus, trie_state=new_state)

def finalize(hyp):
    return hyp.score - PHI(hyp.trie_state)                # 结束时撤回未完成前缀的势能

9600M 辅助与健康检查（G4）

契约：

职责与边界

600M 拆成共享同一次编码的三个操作：全量 CTC 后验与强制对齐、全量声学支持评分、仅对可疑窗口的独立解码（交叉校验）。候选的声学评分也复用同一后验（详设 13）。

G4 分前后两步，避免循环依赖：8B 输出先做文本初筛；与 600M 的后验、对齐、支持分合并后，再决定是否完整交叉解码，最后给处置建议。交叉解码不以 8B 文字为提示、不注入个人偏置表，减少两路共享同一种错误诱因；即便如此，两个模型仍可能相关出错，不能当作独立证明。

G4 的“通过”只表示过了本闸门，不代替 G6/G7 授予接受档或下游资格。

原理

CTC 把含 blank 的帧级路径折叠成标签序列，一个文字序列对应多条路径。强制对齐找的是“给定文字最适合放在哪里”，不验证文字一定存在。这里的声学支持准确地说是：600M 对该文字的帧级支持，比它自己无文字约束的最佳帧路径差多少。

设 ℓ_t(k) = log p(k | x, t)，规范化后的目标为 y。全文强制对齐的最佳路径 π* = argmax_{π: B(π)=y} Σ_t ℓ_t(π_t)。对固定帧区间 I：

A(I) = Σ_{t∈I} ℓ_t(π*_t)            // 强制路径在区间内的得分
U(I) = Σ_{t∈I} max_k ℓ_t(k)          // 无约束最佳帧路径（逐帧取最大），不是概率和最大的文字序列
g_frame(I) = (A(I) − U(I)) / |I|     ≤ 0
g_label(I) = (A(I) − U(I)) / max(1, 区间内目标标签数)

两个归一化一起进校准：大量 blank 会稀释单个错词的帧均值，按标签数归一能把一个错掉的“不”字显出来。局部区间由全文对齐确定：取各目标标签的非 blank 占用帧，相邻标签之间的 blank 按中点分配；原文与候选用同一区间比较，不让候选自选更有利的起止帧。同音词、共享的模型错误与重叠语音都可能得到高支持，所以高支持不取消其他风险标记（D47）。

文字规范化

保留三份：asr_text（8B 原文，不覆盖）、alignment_text（适配 600M 词表的副本，带到原文跨度的可逆映射）、comparison_units（交叉比较用的固定单位）。

  1. Unicode 规范化、大小写、空白与标点处理都版本化并保留跨度映射。
  2. 对齐副本可去标点，但不能去掉“不、没、未、not”等语义单位。
  3. 简繁转换只用于对齐副本。数字、日期、缩写需要展开时，用受限的读法候选图（一对多），不改写展示文字。
  4. 同音字不折叠成同一比较单位，否则人名错误会被掩盖。
  5. 600M 词表不支持的 token 标为不可评分，不能静默删掉后把其余部分的成功当成全文成功；不支持的语种返回 unsupported。

def score_support(logp, target):
    path = ctc_viterbi(logp, target)          # 扩展序列插 blank；相同相邻标签之间必须经过 blank
    if path is None: return unavailable("no_valid_path")
    deficit = gather(logp, path.labels) - logp.max(axis="labels")
    out = []
    for span in spans_from_alignment(path):   # 非 blank 占用帧 + 按中点分配的 blank
        d = deficit[span.frames].sum()
        out.append({"g_frame": d / len(span.frames), "g_label": d / max(1, span.n_labels),
                    "dur": span.duration, "lang": span.language})
    return calibrate_and_mark(out)            # 低于阈值的连续单位 → 低支持区间；一个字也算

def disagreement_level(cc, rest, g2):         # 长度基准固定为 8B 的比较单位数与原始语音时长
    if cc.status != "ok": return "none"
    n8, speech_s = len(cc.units_8b), duration_s(g2.speech_raw, within=rest.source_range)
    if n8 >= 10 and speech_s >= 2.0:
        return "large" if cc.disagreement > 0.35 else "none"
    if n8 >= 5:
        return "large" if cc.edits.total >= 3 and cc.disagreement > 0.45 else "none"
    return "short_mark" if cc.edits.total > 0 else "none"     # 8B 不足 5 个单位：只标记，不隔离

def no_speech_spans(asr, g2, aux):            # 只拒绝落在可靠非语音里的跨度
    if aux.alignment_status != "ok": return []                  # 对齐失败、部分对齐、不支持都不拒绝
    mask = dilate(g2.speech_raw + g2.unknown, ms=TOL_MASK)    # 保守掩码：未知区当作可能有语音
    out = []
    for u in aux.aligned_units:
        if u.timing_uncertainty_ms > MAX_UNC: continue          # 时间不可靠的单位不参与
        r = dilate(u.source_ranges, ms=u.timing_uncertainty_ms)
        if within(r, g2.non_speech) and not overlaps(r, mask):
            out.append(u.text_span)
    return merge_adjacent(out, min_units=2)   # 至少连续 2 个单位才拒绝，单字只交给低支持

“对齐可靠”的计算定义：alignment_status == ok，且该单位的 timing_uncertainty_ms ≤ MAX_UNC。强制对齐成功本身不证明文字存在，所以这里只用它的时间位置，不用支持分。窗口前部是真人、尾部是无声插入时，只拒绝尾部跨度，前部照常走后面的规则。

拒绝跨度的清除：no_speech_spans 给出的跨度在 PersistResult 之前从 asr_text、alternatives、候选证据与坐标映射中删掉，后面的码点重新编号；片段只留被删跨度的时长与原因（v-nohall）。整段都被拒绝时不生成片段，覆盖账记 non_speech。

交叉比较的单位：中文按汉字，英文按固定词法规则，混说按固定的 MER 单位；标点与大小写另报；数字同时保留词面差与规范化值差；否定、日期、人名另列关键字段差异，全段差异低也不掩盖局部否定词的变化。d = Levenshtein(u_8B, u_600M) / max(|u_8B|, |u_600M|, 1)。

低支持的标定：收集真实正确文字、真实 ASR 错误与关键字段错误（人工造错只作补充）；按说话人与会话划分；调参集上使正确真人文字的误触发 ≤5%，约束内最大化否定、数字、日期、人名错误的捕获率；测试集冻结阈值后分报 token 误触发率、受影响片段率、取消资格比例与关键字段召回。“约 20% 送交叉校验”是容量估算，超过时告警、排队、扩容，不能把剩下的当作通过。

失败与恢复

  • 600M 不可用：不能产出“高支持”。超过 12 小时按提案降级：可疑片段标 low_confidence 并记证据缺失原因；对齐退回 8B 时间戳（若有）。8B 与 600M 都给不出时间信息时，不伪造词级归属与核心区去重，继续等待或最终登记失败。
  • 8B 已降级为 600M 时，600M 的另一遍输出不再称为独立交叉校验。
  • 600M 不支持某语种：只取消对应证据，不按识别差异隔离该语种。
  • 有语音但 8B 空输出：标为潜在漏识别，不当作非语音完成。

测试与验收

  • 窗口前半真人、后半无声插入，只拒绝后半；8B 3 字、600M 10 字只标记不隔离；长窗口中的“对对对”不进幻觉集合；对齐 partial 时不拒绝。
  • 最小对照：“要 / 不要”“可以 / 不可以”“周二 / 周四”“十五 / 五十”；同音人名、词表外的正确词、英文缩写、数字读法、中英切换；真重复与模型循环；真实说出的幻觉短语与无声插入；远场、口音、耳语、重叠下的正确文字；两模型一致但同时错、两模型分歧但 8B 正确；blank 占比很高时一个错误否定词仍能触发局部检查。
  • 指标：A5 ≤1 事件/小时；低支持的真人误触发 ≤5%目标；A6、G4 新增误隔离、交叉校验触发比例、共同错误漏检、候选覆盖率（报告）；600M 各子操作（编码、对齐动态规划、候选评分、完整解码）的实测成本分开报。

与提案的差异

  • c-600m 与 §5.10 补上声学支持的精确定义（逐帧最大的无约束路径、blank 分配、两种归一化）。
  • §5.1 的“gzip 压缩比约 2.4”改为 zlib 口径，并按语种重标；字速阈值按语种分开。
  • §5.1 的“无语音帧”补时间容差：只在音频有效、对齐可靠、保守语音掩码仍无覆盖时拒绝。
  • §13 的“600M 是否有 CTC 头”是一期开工前必须关闭的依赖：没有就另选支持所需语种的 CTC 模型并重新核算成本。
