详细设计 · 端侧

领夹的采集、缓冲与传输，手机的时间线拼接、时钟校准、L1 拒识、暂存与上传。只写一期；二期部件（外向麦、VPU、IMU、G0）只保留契约。

读法。每节按同一模板：职责与边界、原理、流程、数据结构与接口、算法、参数、失败与恢复、测试与验收、未决项。技术中立：字段、状态机与伪代码是约束；标“建议”的库与芯片能力只是参考实现。参数给初值和标定方法，初值都须在原型上实测后改定。

1采集与传输协议（领夹 → 手机）

契约：

职责与边界

  • 领夹把 Opus 帧写进 Flash，按块加密；与手机连接时把未回执的帧按序发出；收到手机回执后销毁该块密钥，空闲时擦除整块。
  • 手机先把帧加密落盘、再回执（落盘失败不回执）。领夹不知道 UTC，只提供启动世代、帧序号与 RTC 计数；时间映射在手机做（详设 2）。
  • 不做：领夹不解码、不做 VAD（一期）、不重传已回执的数据。用户擦除下发到领夹的“按区间清除”也走本协议（CMD 消息）。

原理

  • 帧序号是时间，不是记录号。 每 20 ms 的音频占一个序号，编码失败、Flash 写错也照样占号，只是没有数据，另报缺口。这样缺口不会压缩时间轴，云端可以用“有序号空洞但没有缺口记录”判断数据还在路上。
  • 序号与 RTC 双锚。 帧序号由音频采样时钟推进，RTC 由 32.768 kHz 晶振推进，两者各有几十 ppm 的误差。每页（约 1 秒）记一次 RTC 计数，手机按页插值把序号映射到 RTC、再映射到 UTC，采样时钟的漂移就不会累积成秒级误差。
  • 按块加密，销毁密钥即删除。 NAND 擦除慢且要整块进行；每个擦除块用独立随机密钥，回执后把密钥清零，数据立即不可读，擦除可以等到空闲时做。密钥存在 MCU 内部 NOR Flash：NOR 可以不经擦除把 1 编程为 0，“写 0 覆盖”就是一次原地销毁。
  • 累计回执，且只认当前绑定的手机。 链路在一条连接内可靠、按序，手机只需回执“本世代已落盘到第几帧”。断线重连后领夹从回执点续发；手机按主键去重，重复帧无害。回执是删除许可，所以和链路层确认分开：手机必须在帧、索引与本地密钥都落盘后才发；回执带绑定代次 receiver_epoch（每次重新配对 +1），旧手机的回执一律拒绝。
  • 只有手机端落盘才算安全。 回执后领夹删除，手机成为唯一副本；手机随后损坏导致的丢失是 D33 选择的代价，不在本协议里补救。

  • 一页只放序号连续的帧；遇到缺口就封页，下一页 flags.bit0 = 1，缺口另写一条 GAP 记录（页类型用 magic 区分）。
  • 16 kb/s CBR 时每帧 40 字节，一页约 48 帧（约 0.96 秒）；64 页一块约 61 秒。128 MiB 共 1024 块，扣除坏块预留（按数据手册上限约 2%）与控制区后约 1000 块、约 16.5 小时估算（原先的“约 17 小时”只算了裸码流）。容量按实测包长分布复核，40 字节只是 CBR 下的估算。
  • 页内容一律用 AEAD（AES-CCM，16 字节标签；MCU 无硬件 CCM 时用软件实现）：页头作附加认证数据、明文可读（启动扫描要读），帧区为密文；nonce = block_idx(u16) ‖ block_epoch(u16) ‖ page_idx(u8) ‖ 0 填充到 13 字节。crc32 只用于快速发现撕裂页，认证靠标签。

密钥表（MCU 内部 NOR Flash）

密钥区是日志结构：若干 NOR 页，每页 64 个槽，槽 = {block_idx u16, epoch u16, key[16]}。块转为 WRITING 时由 TRNG 生成密钥，追加写进下一个空槽；销毁时先在控制日志写删除意图 {block_idx, epoch}，再把该槽的 key 编程为全 0、读回验证，最后在控制日志记“已销毁”。槽有三态：全 1（空）、随机值（有效）、全 0（已销毁）；启动时先完成所有未完成的删除意图，再按槽状态恢复。

一页的槽全部销毁后整页擦除回收；空槽不够而某页仍有少量有效密钥时，把有效密钥复制到新页、在控制日志登记迁移，再擦除旧页（旧副本随擦除消失）。内部 Flash 的擦写寿命按每天约 1.4 轮写满 1024 块估算足够，须查具体 MCU 手册确认。

控制状态（内部 Flash，掉电保持）

boot_gen u32（上电时先 +1 并写回，写失败不开始录音；允许跳号，禁止回退。恢复出厂若会清零它，必须同时更换 device_id）；receiver_epoch u32（当前绑定手机的代次）；acked = {gen u32, seq_upto u32}（只作启动加速，真值仍以密钥表为准）。

NOR 原地写 0 要求 MCU 允许对已编程的字再编程一次（不少 MCU 限定擦除前同一字最多写 2 次），选型时核实；不允许时改为每个密钥槽占一个可独立擦除的小扇区。

链路层用 LE Secure Connections 绑定加密，DATA 发明文页（链路已加密），手机收到后用自己的密钥重新加密落盘。传输优先 L2CAP CoC（iOS 11+、Android 10+ 提供接口），不可用时回退到 GATT 通知加应用层窗口（32 KiB 未确认上限）；两者用同一套消息与回执语义。消息长度设上限，不按对端声称的长度分配内存。

流程

  1. 连接建立（或重连）后领夹发 HELLO，手机先下发并确认所有待执行的 CMD（用户擦除），再开始收数据（§7：重连后先清除再上传）。手机对比自己已落盘的 (gen, seq_upto)；比领夹的 oldest 还新的部分立即 ACK，领夹跳过已落盘的数据（处理“手机落盘了、ACK 丢了”）。
  2. 校时：手机连发 8 次 TIME_REQ，记录发出与收到时的 UTC，取往返最短的一次作为样本（详设 2）。连接期间每 5 分钟再采一次。
  3. 领夹请求短连接间隔（15–30 ms）与 2M PHY，按 (gen, seq) 从旧到新发 DATA；缺口发 GAP。积压清空后请求长连接间隔（500–1000 ms，外设延迟 4），只维持连接。
  4. 手机每收约 2 秒数据或 64 页，落盘并 fsync 后发 ACK。领夹把被 seq_upto 完全覆盖的 SEALED 块转为 KEY_ZEROED。
  5. 常态（手机在身边）下，新数据每 60 秒成批发一次，而不是逐帧推流：每分钟约 120 KB，按 25–60 KB/s 的实得吞吐射频活动约 2–5 秒。
  6. 部分块的封口：停录、世代结束（关机前）时，当前 WRITING 块就地封口为 SEALED（剩余页不再写），这样已回执的半块也能销毁密钥。立即同步不需要封口领夹的块。

发送与回执（领夹）

def on_connected(link):
    link.send(Hello(...))
    for page in flash.pages_from(oldest_unacked()):          # 按 (gen, seq) 升序
        if page.is_gap: link.send(Gap(page.gen, page.seq_from, page.seq_to, page.cause))
        else:           link.send(Data(decrypt(page)))
        if link.credits == 0: link.wait_credits()               # CoC 流控

def on_ack(epoch, gen, seq_upto, last_page_crc):
    if epoch != receiver_epoch or not crc_matches(gen, seq_upto, last_page_crc):
        return reject()                                         # 旧手机或两端错位：不删
    if seq_upto <= acked_watermark(gen) or seq_upto > sent_upto(gen):
        return ignore()                                         # 重复或越界的回执
    for blk in sealed_blocks(gen=gen):                          # 只处理该世代；旧世代须各自回执
        if blk.last_seq_end <= seq_upto:                        # 整块都已落盘
            keytab.zeroize(blk.idx)                               # NOR 原地写 0
            blk.state = KEY_ZEROED                                # 擦除留到空闲
    persist_acked(gen, seq_upto)

def on_write_page_full():
    nxt = next_block()
    if nxt.state != FREE:                 # 有未回执数据：不覆盖
        stop_recording(); led_alert(); report_on_next_hello("flash_full")

last_page_crc 是 seq_upto 之前最后一页的规范明文（DATA 中的页头字段 + 帧区，小端）的 CRC32C，两端用同一字节序列计算。

启动扫描：块内页按顺序写，所以每块二分查找最后一个已编程页（全 1 为空页），再从该页往前验证认证标签，得到有效页前缀；撕裂页（crc 或标签不对）视为该块写入的终点，前面的页照常可用。读错误的块标坏块，其中已写数据报 flash_error 缺口。1024 块每块约 7 次读，<1 秒。

测试与验收

  • 单测：页编解码与 crc；累计回执覆盖判定；启动扫描在各种块状态组合下恢复正确；序号缺口生成 GAP。
  • 故障注入：写页、销毁密钥、擦除各点随机掉电 1000 次，校验 (gen, seq) 无重复、已回执块不可解密、未回执块可完整读出。
  • 链路：断线重连、ACK 丢失、手机进程被杀，三者组合下手机端拼出的时间线与领夹原始序列逐帧一致。
  • 验收：设备侧真实丢帧率（报告）；回执后到密钥清零 P99 <5 秒；读出 Flash 原始块确认已回执数据不可解密（§5.14）。

未决

  • 一期是否能改现有领夹固件，Flash 容量与 MCU 型号（§13）。不能改时，至少需要帧序号、世代与 RTC 锚点三项，否则详设 2 的时间还原无法达到 ≤200 ms。
  • 用户擦除按块粒度执行时，块内不在擦除范围的音频会一起销毁：建议登记为新缺口原因 user_erase，需要在 §6.1 的 cause 枚举中补上。
  • 领夹侧的保留上限。 写满停录只限制能录多久，不限制旧录音在领夹上留多久：领夹长期连不上手机时，旧块会无限期留存。RTC 掉电归零，跨世代算不出绝对年龄，所以建议按领夹通电运行时间计：控制日志每小时记一次累计运行时长，块写入时记下当时的累计值，差值超过 7 天即销毁密钥并登记缺口 device_expired。长期断电期间不计时，数据保持加密；§7 的对外承诺须照此措辞，不能写成绝对 7 天。

2时间线拼接与时钟校准（手机）

契约：

职责与边界

  • 把领夹的帧按 (device_id, boot_gen, seq) 放回时间线，与到达顺序无关；生成缺口记录；把每帧映射到 UTC，给出误差上界 sync_quality_ms。
  • 时钟模型按启动世代分段：RTC 在掉电后归零，不同世代之间没有可比的计数。
  • 不做：不按语音切分（上传分片固定 5 分钟，详设 4）；不修改帧内容。

原理

  • 每个世代内，RTC 计数与 UTC 近似线性：utc = a + b × rtc，b 偏离标称值的部分就是晶振漂移（±20 ppm，约 1.7 秒/天）。连接时采到的同步点足以拟合 a、b；离线期间的帧用同一条直线内插或外推。
  • 同步点的误差来自 BLE 往返时延的不对称。连发 8 次取往返最短的一次，误差上界是该次往返的一半，通常是几十毫秒。
  • 帧序号到 RTC 的映射用页头的 rtc_first 分段线性插值，消掉采样时钟与 RTC 之间的漂移。
  • 两级映射：RTC → 手机单调时钟 → UTC。 校时样本记录的是手机单调时钟；单调时钟到 UTC 的映射另行维护（系统时间，经跳变检测与服务器时间校验）。用户改手机时间只影响第二级，不会污染领夹漂移的估计。手机重启会换一个单调时钟域，两台手机的单调计数也不能混在一起拟合。
  • 误差上界是一个预算，不只是拟合残差。 往返时延的不对称无法消除（RFC 5905 同类限制），离线越久漂移不确定性越大：±20 ppm 在 8 小时内就是 ±576 ms。所以 ≤200 ms 只对离线前后都有同步点、可插值的区间成立，外推区间如实报更大的 sync_quality_ms。

算法

def to_utc(gen, seq):
    rtc = interp(anchors[gen], seq)                 # 相邻两页锚点线性插值，越界按 20 ms/帧外推
    seg = segment_for(gen, rtc)
    utc = seg.a_ms + seg.b * rtc
    q = quality(seg, rtc)
    return utc, q

def sample_point(p):                               # 四时间戳：扣掉领夹处理时间
    rtt = (p.m4_ns - p.m1_ns) - (p.r3 - p.r2) * NS_PER_TICK
    if rtt < 0 or rtt > 200e6: return reject(p)
    return Point(rtc=(p.r2 + p.r3) / 2, mono_ms=(p.m1_ns + p.m4_ns) / 2e6, half_rtt_ms=rtt / 2e6)

    S = [sample_point(p) for p in samples[gen] if p.accepted]
    # 第一级拟合 RTC → 手机单调时钟（按手机启动域分组，斜率共享），第二级再套 MonoToUtc；
    # 下面为简洁写成单级，y 取的是 mono_to_utc 之前的单调时刻。
    if len(S) >= 6 and span_minutes(S) >= 30:
        a, b = weighted_least_squares(x=[s.rtc for s in S], y=[s.mono_ms for s in S],
                                      w=[1 / max(s.half_rtt_ms, 5) ** 2 for s in S])
        r = residuals(S, a, b)
        if max(abs(r)) > 500:                      # 时间跳变：在最大残差处分段，各自重拟合
            return split_and_refit(S)
        return Segment(a, b, rms=rms(r), state="fitted")
    if len(S) >= 1:                                # 跨度不足：只定偏移，斜率借用本设备的历史漂移
        b = nominal_b * (1 + device_drift_ppm_median / 1e6)
        a = median(s.utc_ms - b * s.rtc for s in lowest_rtt(S, 3))
        return Segment(a=a, b=b, state="offset_only")
    return Segment(state="unsynced")              # 本世代从未连上手机

def quality(seg, rtc):
    if seg.state == "unsynced": return None        # 清单里写 null，云端按“时刻未知”处理
    dist_s = distance_to_nearest_sample_s(seg, rtc)
    drift_unc_ppm = 10 if seg.state == "fitted" else 20  # 区间内温漂可以是非线性的：端点吻合不证明中间准；
                                                         # 初值按 32.768 kHz 音叉晶振在体温附近的温漂包络估，须实测替换
    return utc_source_unc_ms(seg) + min_half_rtt_ms(seg) + seg.rms_ms + dist_s * drift_unc_ppm / 1000
  • 墙上时间跳变检测：相邻样本的 Δutc − Δmono 超过 1 秒，说明手机时间被改；后一个样本起改用服务器时间修正后的 UTC，修正量写进样本，utc_source = "server"。
  • 未同步的世代（领夹离开手机期间重启，重启后又在重连前没电）：只知道它位于前后两个世代之间。上界取下一个世代首个锚点的 UTC，下界取上一个世代末帧的 UTC，按时长从后往前排；state = "unsynced"，sync_quality_ms = null，云端不用它对齐日历与场景事件。
  • 拼接：收到 DATA 时按主键写入（已存在则跳过）。分片只在每个序号位置都有数据或已持久化的 GAP 时才能封口，累计回执也只推进到这样的连续前缀。
  • 换机：新手机（receiver_epoch 变了）在为某个世代封第一个分片前，先查云端已有的分片边界（GET /v1/chunks?device_id=&boot_gen=）：已被旧手机上传的序号范围直接回执给领夹、不再上传，新分片从已有边界之后起算，避免同一 chunk_id 出现两种内容。

  • 手机进程被杀：样本与锚点都在暂存库，重启后重新拟合，结果确定。

  • 仿真：给定晶振漂移（±20 ppm、温漂 ±3 ppm）、BLE 往返时延分布、离线 0–17 小时、中途重启。验收看两件事：所报误差上界的覆盖率（实际误差落在 sync_quality_ms 内的比例 ≥99%），以及 sync_quality_ms ≤200 的录音时长占比（目标 ≥95%目标），后者防止靠大量标“未知”过关。

3L1 拒识（G1，手机）

契约：

职责与边界

  • 在手机上对每个上传分片跑 VAD，只丢高置信非语音的长区间；其余（含疑似语音、短回应、远处人声）一律上传。输出保留区间与丢弃区间，写进清单 l1。
  • 不做：不做声音事件分类、不判断播放声、不判断说话人（都在云端）；不重新编码音频。
  • 一期它是第一道丢弃闸，误丢就是永久丢失，所以阈值偏向召回。

原理

  • 轻量神经 VAD（如 Silero VAD、FireRedVAD 一类，建议，非约束）对 16 kHz 音频逐窗输出语音概率，在 CPU 上远快于实时。领夹录音以近场机主为主，非语音的长区间（安静、走路、键盘）概率很低，丢掉它们省掉约 65% 的上传与云端算力假设。
  • 误丢的主要来源是短回应（“嗯”“对”）和远处的轻声。三层余量对付它：判“非语音”用很低的语音阈值；保留区间两侧各扩 500 ms；间隔 <2 秒的语音段合并。合起来，只有原始长度 ≥3 秒、且全程概率都低的区间才会被丢。不用常见 VAD 后处理里“短于 250 ms 的语音段删掉”的规则：短回应正是要保护的。
  • VAD 输出的分数没有经过校准，阈值 0.1 不意味着误丢概率 10%；阈值只能在留出集上按误丢预算选。
  • “没算完”一律保留。 模型没跑完、解码出错、后台时间不够、过热、低电量，都按保留处理，交云端 G2；L1 只在确实算出“高置信非语音”时才丢。
  • Opus 帧之间有解码状态。丢掉中间的帧后，云端从每个保留区间开头重新初始化解码器；500 ms 的余量覆盖了重新收敛的几帧。

数据结构

manifest.l1 = {
  model_version: "silero-v5@onnx-1",          // 模型与参数的版本，参数变了也要变

}

max_p 是被丢区间内的最大语音分数，只用来监控分数分布的漂移；真实误丢率无法从已丢弃音频上的模型自身分数得出，只能靠离线留出集测。

算法

def l1_chunk(frames, carry):                      # carry：上一分片尾部的 VAD 状态与未定区间
    pcm, bad = opus_decode_stream(frames, reset_at=gaps(frames))  # 缺口处重置解码器；bad 为解码出错的帧
    probs = vad.run(pcm, state=carry.vad_state)                  # Silero 一类在 16 kHz 下每 512 样本（32 ms）一个分数
    maybe = [p >= THETA for p in probs]
    maybe |= mask(bad) | mask(first_ms(resets(frames), 1000))   # 解码出错与重置后 1 秒视为可能语音
    maybe = dilate(maybe, PAD_MS)                                # 两侧各扩 500 ms
    maybe = close_gaps(maybe, MERGE_MS)                          # 短于 2 s 的非语音间隔填平
    maybe |= shorter_than(~maybe, MIN_DROP_MS)                   # 不足 1 秒的候选丢弃区间不丢
    kept = to_frame_intervals(maybe, round="outward")            # 32 ms 窗 → 20 ms 帧，向外取整
    # 分片末尾 2.5 s 的判定依赖下一分片：先按“保留”处理，不跨分片回改
    kept = union(kept, tail(frames, PAD_MS + MERGE_MS))
    return kept, complement(kept), new_carry(probs, vad.state)
  • 增量运行：BLE 每落盘约 2 秒就把新 PCM 送进 VAD，分片封口时只需收尾，不依赖系统择机执行的后台任务。iOS 在 BLE 后台唤醒的时间片内运行；Android 在 connectedDevice 前台服务内运行。
  • 分片边界：分片末尾的 2.5 秒一律保留，宁可多传几秒。
  • 执行预算：每次后台机会先完成接收与回执，再按 250 ms 的 CPU 片段跑 VAD，单次总时长不超过 2 秒（系统更早收回则更早停）。到上传触发时仍未算完的区间整体保留。
  • 跳过条件：电量 <20% 且未充电、过热、模型加载失败或预算不足时，status = "bypassed" 并记原因，未算完的部分整片上传，由云端 G2 兜底。iOS 后台唤醒的执行时间约 10 秒（Apple Core Bluetooth 后台指南）且不保证每次都有，所以 D20 只是执行优先级，不是调度保证。

失败与恢复

  • VAD 崩溃或模型加载失败：整片上传、记 skipped_error；不重试到天荒地老，以免阻塞上传。
  • L1 运行中进程被杀：VAD 与解码器的内部状态不持久化。原始帧在载荷提交前都还在，重启后从未定稿处往前 2 秒重新解码与推理；前一分片的原始帧已删时，本分片开头 1 秒按“重置保护”一律保留。
  • 模型版本升级：只影响新分片；清单里的 model_version 用于线上按版本分开统计。

测试与验收

  • 单测：扩边、合并、窗到帧的向外取整；缺口处解码器重置；分片尾部保留规则。
  • 离线评测：留出集上的误丢率（全部语音、短回应、远处人声分开报）与丢弃率；与云端 G2 的同一指标对照。
  • 设备测试：低端安卓机与旧款 iPhone 上，每 5 分钟分片的 CPU 时间与耗电估算。
  • 验收：L1 误丢预算（单侧 95% 上界 ≤0.5%）达标后才启用丢弃，未达标时只记录、不丢；短回应保留率 ≥99%目标；所有未算完与异常路径都保留。节省比例（约 65%假设）只报告，不作门槛，也不用它反推阈值。

未决

  • 不同手机上 ONNX 运行时（CPU、NNAPI、Core ML 后端）的数值差异会让同一音频的分数略有不同；一句短回应的分数全都略高于阈值时，换一个运行时就可能整句被丢，扩边保护不了没被检出的语音。所以每个支持的运行时都要在留出集上单独验收，未验收的运行时只跑、不丢。

4暂存、清单与上传（手机）

契约：

职责与边界

  • 把收到的帧加密暂存，按 5 分钟设备时间封成上传分片；L1 后生成只含保留帧的载荷与 §6.1 清单；按调度条件上传；按云端回执删除。
  • 暂存上限 2 GB、最长 7 天，超出时删除并登记 phone_expired 缺口。隐私上限优先于完整性。
  • 不做：不在手机上重编码；不保留已上传且已回执的任何音频。

原理

  • 原始帧与载荷分开。 原始帧文件只活到 L1 完成；载荷只含保留帧。丢弃的帧在 L1 后立即删除，不等上传。
  • 载荷在手机端就加密，上传密文。 每个分片一把随机密钥 K，载荷用 K 加密后既是暂存文件、也是上传对象；commit 时把 K 经 TLS 交给网关，网关用用户数据密钥包裹后存进元数据库。这样后台上传不需要明文临时文件，云端删除 K 就让对象立即不可读，与对象删除互为兜底。这是对 §5.12 的补充，详设 18 的删除链据此设计。
  • 分片 ID 是幂等键。 chunk_id = device_id:boot_gen:seq_start，重试、重装 App 后重传都落到同一条记录上。同一 ID 再次 prepare 时，清单摘要不同就是冲突（409），不覆盖。
  • 分片内不会有“还在路上”的空洞。 领夹按 (gen, seq) 顺序发送、手机累计回执，分片只在连续收到的范围上封口；分片之间的空洞（换机、手机丢失）才由云端按“序号空洞且无缺口记录”处理。所以清单不需要修订版本，一个分片只上传一次。
  • 迟到的直传不能复活音频。 预签名地址在有效期内可以重复使用（S3 文档明确如此），网关拒绝新的 prepare 挡不住旧地址再 PUT。所以云端在发“音频已删除”回执前，要等该分片签发过的所有直传地址都已过期（≤15 分钟）、在途请求超过上限时长，再做一次最后清扫（详设 18）。手机端加密是纵深防护：对象是用 K 加密的密文，K 包裹后存在与短期音频桶同等待遇的密钥表里（不进备份、不做时间点恢复），删除时一并销毁；已终结的分片拒绝再次 commit。

载荷格式：每个保留区间封成一个独立的 Ogg Opus 逻辑流，按序号顺序串接（chained Ogg，RFC 7845）；每个流前面多带最多 4 帧（80 ms）紧邻的前序包作解码预卷：前序包须是本分片内、原始帧仍在的帧；分片开头或世代开头取不到时按实际可得的帧数带（可以是 0）。OpusHead.pre_skip 设为“设备编码器的原始延迟 + 预卷样本数”（48 kHz 单位），granule 位置按 RFC 7845 从流起点以 48 kHz 计；runs 记录映射：{stream_serial, seq_from, seq_to, core_from, core_to, preroll_frames}。预卷只用于解码收敛，不转写、不计量；保留区间两侧本来就有 500 ms 的非语音余量，预卷不足也不会切掉语音。Ogg 内的 granule 时间只在流内有意义，录音时刻一律从 runs 与清单 clock 还原。原 Opus 包字节不变、不重编码。整个文件再用 K 做分段 AEAD（64 KiB 一段，AES-256-GCM，段号进 nonce）。

清单：§6.1 全部字段，外加 payload.enc = {alg: "aes256gcm-seg64k"}、payload.runs、sealed_reason、receiver_epoch；payload.bytes/sha256 指上传的密文，另带 plain_sha256 供云端解密后校验。user_ref 由网关从认证上下文取得，不信任清单里的值。

流程与算法

def on_frames_persisted(gen, seq_upto):
    c = current_chunk(gen)
    if c.frames >= 15000 or gen_changed(): seal(c, "full" if c.frames >= 15000 else "gen_end")

def seal(c, reason):
    c.state = SEALED; c.sealed_reason = reason
    run_l1(c)                                   # 详设 3；分片尾部规则在此生效
    K = random_key()
    c.payload_path = write_encrypted_ogg(kept_frames(c), K)    # 写完 fsync
    c.wrapped_k = day_key(c.sealed_day).wrap(K)                 # K 由当天的钥匙串 / Keystore 密钥包裹
    c.manifest_json = build_manifest(c)         # clock、gaps、l1、scene 在此刻定稿
    with db.transaction():                       # 载荷、包裹的 K、清单与状态同一事务提交
        c.state = PAYLOAD
    delete(c.raw_path); destroy_key(c.raw_key)   # 提交之后才删原始帧及其密钥

def scheduler_tick(now):
    ready = chunks(state=PAYLOAD)
    effective_min = sum(kept_minutes(c) for c in ready)
    oldest_h = hours_since(min(capture_utc_start(c) for c in ready), now)   # 按录音时刻算；时钟未同步时用接收时刻并记降级
    if user_requested_sync:  run(ready + [truncate_current()], network="any", queue="sync")
    elif effective_min >= 30 or oldest_h > 2:
        run(ready, network="wifi" if oldest_h <= 4 else "any", queue="regular")

def upload(c):
    r = POST("/v1/chunks:prepare", manifest=c.manifest_json, queue=c.queue)
    if r.state in ("stored", "processing", "done"):  c.state = COMMITTED; return
    if r.state == "deleted":                          finish(c); return    # 早已处理完
    put_file(r.upload_url, c.payload_path)             # 后台上传任务
    POST(f"/v1/chunks/{c.chunk_id}:commit", sha256=c.payload_sha256, bytes=c.payload_bytes,
         k=keystore.unwrap(c.wrapped_k))
    c.state = COMMITTED

def on_receipt(rc):                                    # GET /v1/receipts?after=cursor
    if rc.kind in ("audio_deleted", "failed_gap_recorded"): finish(rc.chunk)

def finish(c):
    delete(c.payload_path); c.wrapped_k = None; c.state = DONE; purge_row_later(c)
    if all_done(c.sealed_day): delete_day_key(c.sealed_day)  # 当天的分片都已终结：销毁包裹密钥，残留副本一并失效
  • 截断：立即同步时封口当前分片（sealed_reason = "sync"），下一分片从截断处起算。
  • 超期与容量：7 天是硬期限，期限从首次落盘起算、重试不顺延；每小时与每次启动检查，超期即删并写 pending_gaps(cause="phone_expired")。2 GB 是背压而不是删除条件：总量（原始帧、载荷、临时文件合计）到上限时停止向领夹发回执，领夹继续缓冲，不提前删未到期数据。
  • 缺口上报：手机过期删除的范围用独立的幂等接口 POST /v1/gaps {device_id, boot_gen, ranges, cause} 上报，不修改已 prepare 的清单；只报从未成功 commit 的范围，云端已存的不报。L1 把整片都判为非语音时，照常 prepare 一个 payload.bytes = 0 的清单。
  • 平台：iOS 用后台 URLSession 从文件上传，常规批设 allowsCellularAccess = false 与 discretionary，立即同步不设；Android 用 WorkManager，常规批约束 UNMETERED，立即同步用加急任务。直传地址 15 分钟过期，过期后重新 prepare。
  • 并发与顺序：同一设备按 seq 从旧到新、最多 2 个并发；立即同步队列优先。

失败、降级与恢复

崩溃点恢复
封口后、载荷写完前原始帧还在；重跑 L1 与载荷生成（新 K），结果相同（K 不同无妨，尚未上传）
载荷已写、原始帧未删启动时发现 PAYLOAD 状态仍有 raw 文件，直接删
PUT 完成、commit 前重新 prepare：网关见对象已存在但未 commit，返回新地址或直接允许 commit；重放 commit 幂等
commit 已成功、响应丢失再次 prepare 返回 stored，转 COMMITTED
回执丢失回执按游标拉取，可重复；收到“已删除”的分片不再上传；游标失效时按未终结的 chunk_id 批量查状态
回执已处理、载荷未删启动时清理 DONE 状态的残留文件
手机换机或重装暂存随 App 数据一起丢；领夹中未回执的数据由新手机接收；丢失部分由云端按“序号空洞且无缺口记录”在 48 / 72 小时后登记

测试与验收

  • 状态机：每个状态转移前后各杀一次进程，最终状态与无故障时一致，云端无重复分片。
  • 网络：上传中途断网、地址过期、网关 503、商店后台限制（iOS 低电量模式、Android Doze）。
  • 隐私：任何时刻磁盘上不存在明文音频文件；finish 后载荷与包裹的 K 都不存在；超期删除生效且缺口上报。
  • 迟到写入：云端删除后，用仍在有效期内的旧地址再 PUT，确认对象不可解密且在巡检周期内被删。
  • 验收：流量约 50 MB/天估算（20 小时佩戴、保留 35%、16 kb/s）；常规批从录音到可见 P90 ≤3 小时（含上传等待），按有 WiFi、仅蜂窝、系统限制分组报告；立即同步 P90 ≤10 分钟（§9）。

未决

  • commit 时交出 K、云端包裹存储，需要网关与删除服务配合（详设 5、18），并在 §6.1 的 payload 中加 enc 字段。
  • iOS 后台 URLSession 在 App 被用户强制退出后不会继续；此时只能等用户下次打开 App。
  • 只有蜂窝网络、且用户不点立即同步的人，要等最旧分片超过 4 小时才上传，达不到“P90 ≤3 小时”：需要决定是放宽蜂窝条件，还是把这类用户排除在该指标之外。
  • 手机长期关机或 App 长期挂起时，无法保证恰好在第 7 天删除；§7 的对外措辞应写成“恢复运行后立即删除超期数据”，或引入带有效期的密钥（平台能力待查）。
