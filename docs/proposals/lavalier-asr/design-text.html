详细设计 · 裁决、文字与删除

相关性门控（G6）、三档裁决与写入资格（G7）、对话单元、入库闸门（G8）与溯源，以及删除服务与删除链。除删除链的前半段外，这里都只读文字。

读法。每节按同一模板：职责与边界、原理、流程、数据结构与接口、算法、参数、失败与恢复、测试与验收、未决项。贯穿本页的约定：上下文就绪、片段裁决、单元定稿、产物核验、删除完成是五个独立的状态，各有版本，不能互相代替；否则会出现循环依赖、旧结果覆盖新结果，或删除后被异步任务写回。引用一律带版本：segment_id + segment_rev、unit_id + generation + input_revision；片段有两种版本：evidence_rev（文字、身份、来源证据等输入变了才递增）与 decision_rev（档位、资格等派生结果）；上下文摘要只看前者，写一次档位不会触发自己的重算；唯一例外是别的片段在本片段上下文里的可见性（正文或隔离占位），它随对方的档位变化，算作本片段的上下文输入。文字有两个视图：base（8B 原文 asr_text 叠加用户编辑，不含专名纠错等模型编辑）与 display（base 再叠加已接受的模型编辑）；两个视图各有修订号：base_rev 只在用户编辑时递增（同时递增 evidence_rev）；display_rev 在任一视图变化时递增。G6 与资格核验只引用 base_rev，模型纠错只动 display_rev，不会让 G6 的快照过时。模型编辑一律记成“base 上的区间 → 替换文字”，display 坐标经这张表可以逆映射回 base。用户在界面上的编辑先逆映射；与某条模型编辑重叠时，把该模型编辑的整个替换块按用户修改后的样子提升为一条用户编辑（base“张三”→ display“张小三”，用户把“小”改成“大”，生成的用户编辑是“张三 → 张大三”，前后未改的字保留），原模型编辑作废。文字跨度一律写明视图与该视图的修订号（base_rev 或 display_rev），再加码点；详设 10、13 里的 text_revision 就是这里的 base_rev（纠错候选都在 base 上计算）；擦除代次统一叫 erasure_epoch；身份级别沿用详设 10 的 none | timeline | identity_evidence，用户确认另记来源 user_confirmed。所有持久化命令带 request_id、预期版本与 erasure_epoch，同键同内容返回原结果，同键不同内容返回冲突。资格取 pass | fail | unknown | deferred，不是布尔值。LLM 调用只读文字与元数据，输出先按模式校验，不合格重试一次后丢弃（§5.13）；模型不能提交 verified、speaker、提醒开关这类权威字段，它们由代码派生。

14相关性门控（G6）

契约：

职责与边界

G6 回答两个不同的问题，输出分开：

输出含义谁用
p_media_content属于待排除的媒体内容（电视、视频里的台词与广告）的概率G7 判来源风险
p_related属于机主正在参与、记录或明确要保留的对话的概率单元的参与者与背景、产物资格
kind广告、播报、歌词、普通对话、引用、口述记录等描述性标签展示与统计

三者不能互相替代：真人引用广告词可以相关；外放的远端会议是物理回放，但相关；电视里的普通对话没有明显的媒体文风。

  • 片段级结论；“某簇是参与者”只是单元内的汇总，不写成簇的永久属性。同一人一部分话相关、一部分是跟邻座闲聊，是正常的。
  • 不做：改说话人、认定声学证据级、补写文字、直接授予待办或记忆资格；读音频（G6 没有音频访问权，但不必等手机回执）。

原理

  • 文风判断对风格化内容有效，对“电视里的普通对话”和“在场真人的闲聊”帮不上，后两类要看互动：称呼（“小王你……”）、问答配对、语义承接、互动间隔，加上声源证据（G3 纯声学分、场景外放）。
  • 两个作用域，打破循环。 单元的切分用到相关性，相关性又要上下文；所以先在不依赖正式单元的时间窗上算 base，供 G7 与切分使用；单元关闭时，对上下文变了的片段再算一次 unit_final，确定参与者与背景。同一个输入快照内，unit_final 不反向驱动自己的边界：发现需要改档位或切分，就产生一个新的输入修订事件，由调度器重开，不在一个事务里迭代到“看起来稳定”。
  • LLM 给的数字不是概率。 先把 LLM 原始分与结构化特征用逻辑回归融合成一个标量，再对这个标量做保序回归；校准效果只能在留出数据上验证，换了部署分布要重新检查（Guo 等，ICML 2017）。
  • 簇先验只用窗口里除目标片段之外的可靠判断，且有最小支持量；本轮输出不反复喂回下一轮放大。

流程

WAIT_CONTEXT → READY → RUNNING → COMMITTED；模式两次不合格 → DISCARDED；服务不可用 → 排队；输入版本变化 → STALE；命中擦除屏障 → ERASED。

就绪规则（base）：

  1. 目标片段已经由 PersistResult 提交。
  2. 取目标前后各 60 秒的片段，合计 ≤2,000 token，目标本身不得被截掉。
  3. “右侧上下文到齐”由覆盖账与 G5 处理进度证明（右侧 60 秒的帧都有终结结果，或已登记缺口），不能由“目前没查到后文”推断。已知录音结束可以关闭右边界；缺口终结等待，但快照标 forced_partial。
  4. 等待截止 = min(开始等待 + 15 分钟, 可见截止 − 后续处理预算)；已在等待的片段被立即同步提升时立即解除等待。超时用 forced_partial 快照，相关性允许弃权。上传按“累计 30 分钟有效音频或最旧分片超过 2 小时”触发，右侧上下文常常要等下一批，所以单元关闭时的 unit_final 是兜底。
  5. 每个快照登记依赖范围（interval_utc 与 missing_ranges）。覆盖账在这些范围有新的终结结果（迟到分片、缺口终结）时，唤醒依赖它的全部目标，含已隔离、不在任何单元里的目标，在新快照上重跑 base 与 G7；这是被不完整上下文误隔离的片段恢复的入口。
  6. 单元关闭时，对上下文快照与 base 不同（迟到文字、边界变化、用户编辑）的片段补跑 unit_final；输入摘要只由实际读取的文字、身份、来源证据、覆盖与上下文的 evidence_rev 算出，相同就复用，结果相同也不产生新的修订事件。
  7. G6 读 base 视图（8B 原文叠加用户编辑，排除模型编辑），快照记下所读的 base_rev；专名纠错（默认关闭）在 G6 之后、G7 之前运行，只产出 edits、只改 display，不触发 G6 重算；用户改字改变 base，产生新的 base_rev 与 evidence_rev，在单元关闭时进入 unit_final；目标已隔离、不在任何单元里时，evidence_rev 变化直接唤醒它的 base 快照重算。

已隔离的片段在别人的上下文里只给占位。决定占位与否的是不依赖 G6 的声学档位 acoustic_tier（只取非语音、无语音幻觉、交叉识别分歧、疑似回放四个原因中最严的一档，不含播放融合，因为融合用到 G6 的分；这四个原因在 PersistResult 时都已确定，所以由同一个函数在落盘时派生并随片段保存，G6 构建快照时直接读取，G7 裁决时复用，不等 G6），不是最终档位。只因播放融合被隔离的片段（如电视）在 G6 上下文里仍给正文，这反而帮 G6 判断“此处在放电视”；G8 与纪要仍按最终档位只给占位。否则否则 A 的档位取决于 B 是否可见、B 又取决于 A，可能来回翻转。邻接片段的声学档位变化时，引用它的快照因 visibility 变化而失效、重算；因上游硬条件已隔离、无需再读文字的目标，G6 记 not_evaluated，不伪记为“不是媒体”。

算法

def classify(snap):
    assert_current(snap)
    items = load_exact_revisions(snap)
    raw = llm_json(SMALL_LLM, PROMPT_PREFIX, render(items, snap), schema=G6_SCHEMA, retries=1)
    if raw is None: return commit_if_current(snap, discarded(items))
    require_refs_in(raw, items)                                  # 输出只能引用快照里的片段与跨度
    out = []
    for it in raw.items:
        x = features(it, snap.completeness)                     # LLM 原始分 + 结构化特征 + 声源证据 + 是否机主（强先验，不直接定结论）+ 缺失掩码
        pm, pr = ISO_MEDIA(LR_MEDIA(x)), ISO_REL(LR_REL(x))      # 先融合成标量，再保序校准；按完整度分组
        if it.user_engagement:      eng = it.user_engagement     # 用户设置的参与者 / 背景优先
        elif it.insufficient:       eng = "undetermined"
        elif pr <= T_BACKGROUND:    eng = "background"
        elif pr >= T_PARTICIPANT:   eng = "participant"
        else:                       eng = "undetermined"
        out.append(G6Result(it, p_media_content=pm, p_related=pr, engagement=eng))
    return commit_if_current(snap, out)                         # 快照已过时就丢弃，不覆盖新结果
  • 提示词：指令与输出模式放在稳定前缀，窗口内容放在末尾，以利用前缀缓存。只分类、不改写；电视或视频里的对话即使像真人对话也按媒体判；线上会议外放的远端发言与机主有问答往来，按参与者判。
  • undetermined 的去向：只在时间线显示，不进纪要上下文、不支撑待办与记忆。邻座闲聊进了上下文，纪要会准确复述它，蕴含核验也会通过，但仍然违反 N3；标“来源不确定”解决不了“不相关”。代价是中间区里的真参与者进不了纪要，所以另报 undetermined 比例与它造成的 N2 损失。机主本人的话只是强先验：用户把一段改标为机主，不会顺带让相关性通过。
  • 幂等键：(scope, target_refs, context_refs /* 带 evidence_rev、base_rev 与 visibility */, completeness, 簇先验摘要, model_version, prompt_version, calibration_version, policy_version)；只用 segment_id + 管线版本 不够，旧上下文的结果会覆盖新结果。

失败与恢复

  • 小 LLM 不可用：排队，片段暂不可见；音频删除不受影响，也不延长音频保留。
  • 两次模式失败或弃权：不改档位、不标背景；相关性记 unknown，不进纪要上下文、已核实待办与记忆（§5.13）；时间线照常由 G7 决定。

测试与验收

  • 同一录音按顺序、逆序、分批、缺一批到达，完整快照的最终结果一致。
  • 电视台词与机主真实问答交错；引用广告；边听边说；外放远端会议；只有机主一句话的会议不能把其他人全判背景；簇里多数相关、某段转向邻座，片段结论能覆盖簇先验。
  • 指标（§5.10）：N3 纪要混入 ≤5%；参与者误判为背景 ≤3%目标；ECE ≤0.05目标；另报弃权率与产出覆盖率。对照：同特征的微调小型文本分类器，在同一风险上限下比覆盖率、费用与缺上下文时的表现。

与提案的差异

  • c-g6 需要前后文，d-unit 又依赖 G6：补 base / unit_final 两个作用域。§6.2 的 engagement 在单元关闭时才定，切分用的是 base。
  • §5.11 的幂等键补上下文版本。c-g6 的“音频已删除”改为“无音频访问权”：文字管线由 job.persisted 触发，不等删除。

15三档裁决与写入资格（G7）

契约：

职责与边界

G7 输出两样东西：档位（接受 / 隔离 / 拒绝）与能力限制（四种产物在四个维度上现在能确定什么、还要等什么）。

  • 四维按 D45：身份、文字可靠性、相关性、语义支持。来源安全由档位这个前置条件表达：只有接受档往下走。
  • 片段在 G7 完成后才对 App 可见（segment.final）。
  • 不做：参与者与背景（单元关闭时）；某句话是否足以证明某条待办（此时还没有动作、承担人、期限，G8 才能定）。

原理

  • 硬条件直接定档，概率先融合再定档。 播放声、媒体内容这些概率判断，如果每条各设一个保守阈值再取并集，真人误隔离会层层累加、突破 R4；所以融合成一个概率，再在合并后的 R4 上限下选阈值。各模块概率不直接相乘，G3 的融合分与它的全部输入也不重复计入。
  • 融合的训练标签是“应排除的无关播放内容”，不是“物理上经过扬声器”，否则外放会议天然被误隔离。免提通话期间屏蔽“本机正在外放”这一证据，其他独立证据照用。
  • 只收紧不放宽指一次裁决之内：多个原因合并时取最严，缺失证据不当作通过。上下文快照变了（例如后文到齐，证明那是远端会议）就在新快照上从头裁决，不与旧档位比严，这样完整快照的结果与到达顺序无关；旧快照上的误隔离因此能自动恢复。用户“放回”是单独的、可审计的授权覆盖，只覆盖那一次裁决；参与者与背景、资格随新上下文重算。
  • 全部原因都记，包括没算的。 每个原因记 hit | miss | unknown | not_evaluated；G2 判为非语音的内容没有文字，后面的原因记 not_evaluated，不为了补原因去跑无意义的识别，统计也不把“没算”当“未命中”。

low_confidence、说话人未知、相关性未知、背景发言都不能单独触发拒绝或隔离。

按区间处置。 G3 的证据区间（1 秒分辨率）经字对齐映射到文字跨度：高证据区间 ≥2 s 且能对齐时，把片段切成子片段（ID = segment_id + ":" + 起点码点，稳定），各自裁决；对不齐或区间太短时整段按融合分处置。“真人 28 秒、电视 2 秒”因此只隔离电视那 2 秒的字。证据区间不含逐秒概率，融合特征只用片段级校准分与区间覆盖比例，不从区间重建时长加权概率。

def decide(seg, g6, policy):
    ev = [eval_nonspeech(seg), eval_no_speech_spans(seg),        # 来自 G2、G4，按跨度
          eval_disagreement(seg.g4), eval_replay(seg.g5)]
    x = playback_features(
        acoustic=seg.g3.p_playback_acoustic, acoustic_span_ratio=ratio(seg.g3.playback_acoustic_spans),
        coverage=seg.g3.valid_coverage, mixed=ratio(seg.g3.mixed_spans), media_bg=seg.g3.p_media_content,
        media_content=g6.p_media_content if g6.ok else None, related=g6.p_related if g6.ok else None,
        scene=mask_phone_playback_during_speakerphone(seg.scene), missing_masks=True)
    p = CAL_PLAYBACK(x)                                          # 逻辑回归；树模型作对照
    ev.append(ReasonEvaluation("playback", "hit" if p >= TAU_ISO else "miss", "quarantine", score=p))
    acoustic_tier = derive_acoustic_tier(ev)                    # 与落盘时同一函数（不含播放融合），结果应与已存值一致
    model_tier = most_severe_hit(ev, default="accept")          # 一次裁决之内取最严；不与旧快照的档位比
    eff = apply_scoped_override(model_tier, seg.user_actions, ev) # 放回只覆盖那次裁决
    hints = capability_hints(seg, g6, eff, semantic_support="deferred")
    return commit_atomically(seg, ev, model_tier, eff, hints,   # 档位、可见性、资格、索引任务、出站事件同一事务
                             expected_rev=seg.rev, erasure_epoch=seg.erasure_epoch)
  • 关键字段：否定词、数字、日期时间、人名（个人热词与称呼规则识别）；G7 先给出片段里关键字段与低支持区间的交集，G8 再按实际引用的跨度判。
  • 拒绝档只记时长与原因，不存文字；拒绝跨度不得残留在 asr_text、候选、编辑历史或全文索引里。隔离档存文字 7 天，从首次进入这次隔离计时，重试、重新生成、重复消息都不刷新期限；只在隔离区可搜，不进单元。
  • 混合声无法对应到具体文字时，不因某一秒的最高回放分而隔离整轮，保留混合与来源不确定标记，由融合的工作点决定。

16对话单元

契约：

职责与边界

  • 单元调度器（每用户单写者，带防护令牌）把接受档片段组织成对话单元：成员、边界、关闭、重开与代次；单元关闭时确定参与者与背景、判断是否生成纪要、触发 G8。
  • 两层结构：事件单元（日历会议、连续交谈、明确的口述记录）是纪要的单位；主题分段是单元内的章节，供抽取与纪要分节使用。
  • 不做：重新聚类声纹；从名字推断跨日身份；把主题变化当作说话人变化。隔离档片段不参与切分、不进任何单元，只以“时段 + 原因”的占位出现。

原理

  • 上传批只服务传输，识别窗口只服务 8B；纪要要按“一场对话”生成。按批会把会议切碎，按天会让立即同步失去意义。
  • 边界证据的优先级：明确的录音结束、不同的会议实例、确认的长静默 > 非会议中的参与者换组 > 主题变化。同一日历会议实例保持一个单元（D16），会议里的话题变化只形成章节。一期非会议的长事件也只按主题分节、不拆单元：拆单元会把“请求—接受”“承诺—改口”切到两边，核验所需的证据就不在一起了。按主题拆单元是变体，用 N1 与跨边界任务遗漏比较后再定。
  • 参与者比较排除机主：机主在每场对话里都在，算进去集合永远有交集。两边都是空集、未知簇占比高、跨 day_id 的簇号不可比时，都是证据不足，不能判为“没有交集”。
  • 关闭要等在路上的数据：覆盖账里有未终结的区间（帧序号空洞、作业未落盘），说明数据还没到；等满 2 小时就带 possibly_incomplete 关闭，补到后重开。等满只是允许关闭，不登记 never_arrived 或 phone_lost（那两个按详设 5 的规则登记）。
  • 主题低谷借鉴 TextTiling（Hearst 1997）的思想，在句向量上找；这不是直接套用原算法就能得到对话边界的准确率。

def boundary_between(left, right, coverage):
    if different_meeting_instances(left, right): return "meeting_boundary"
    if same_meeting_instance(left, right): return None           # 会议内只分节
    if right is None: return None                                # 尾部的关闭由 tail_boundary 处理
    if observed_no_accepted_speech(left.end, right.start, coverage, min_minutes=10):
        return "silence"                                         # 静默必须是覆盖账证明的，不是“数据没到”
    a = reliable_others(left.last_minutes(5))                    # 排除机主；只算相关的他人
    b = reliable_others(right.first_minutes(5))
    if enough(a) and enough(b) and comparable_namespaces(a, b) and disjoint(a, b):
        return "participant_change"
    return None

def tail_boundary(u, coverage, now):                           # 最后一场对话后面没有新片段时，定时触发
    if coverage.recording_ended_after(u.end_utc_ms): return "recording_end"   # 明确的录音结束优先于同一会议
    if u.meeting_instance_ref and now >= meeting_end(u) + minutes(10): return "meeting_boundary"
    if coverage.watermark_utc >= u.end_utc_ms + minutes(10) and no_accepted_speech_after(u, coverage):
        return "silence"                                         # 覆盖水位证明后面 10 分钟确实没有接受档语音
    return None

def close_if_ready(u, now):
    if not u.boundary: return WAIT
    unresolved = unresolved_coverage_before(u, u.boundary)
    if unresolved and now < u.gap_wait_started_at + hours(2): return WAIT   # 起点是首次因该缺口阻塞关闭，重试不刷新
    if any(s.g7_pending for s in arrived_segments(u)): return WAIT          # 小 LLM 故障不能当成没有语音
    rerun_g6_unit_final(u)                                       # 只补跑上下文变了的片段
    snap = freeze_members_and_engagement(u)
    u.one_sided = one_sided(u); u.generation_gate = generation_gate(u)
    return atomic_close(snap, possibly_incomplete=bool(unresolved), generation=u.generation + 1)

def reopen(u, cause):                                            # 同一事务
    u.generation += 1; u.state = "open"
    suspend_outputs(u, previous_generation=True)                 # 旧代次产物立即暂停、取消提醒；新一代发布后再替换

def generation_gate(u):
    if not has_valid_sources(u): return "sources_expired"          # 来源全部到期或被擦除：先于会议、口述例外
    if u.type in ("calendar_meeting", "dictation"): return "ok"
    n = count_distinct_sentence_anchors(u, speaker="owner", grade="timeline")  # 按句锚计数，不按片段行数
    return "ok" if n >= 3 or has_owner_dictation(u) else "owner_lt3"           # “记一下”“提醒我……”一类口述

  • 立即同步：按手机报告的 SyncCut 临时关闭，不能用云端当时收到的最大帧代替，否则未传到的尾部会漏出此次同步。截点之后 10 分钟内又有语音，或属于同一会议实例，就重开该单元。

17入库闸门（G8）与溯源

契约：

职责与边界

  • G8 是“抽取建议 + 确定性核验 + 原子发布”：单元关闭后，对可作上下文的片段抽取带原文跨度的言语行为，核验后生成纪要、待办、记忆候选。模型只提议，不直接写最终的待办或长期记忆。
  • 输入由服务端构造：已关闭单元的确切片段版本、资格、用户确认与隔离占位。背景不进上下文；未知说话人只在相关性通过时进纪要上下文，不能成为任何待办的支持来源。
  • 维护溯源：片段降级、改字、删除、单元重开时，暂停、重核或撤回受影响的产物。
  • 不做：记忆系统本身的存储、召回与问答。

原理

  • 六步：原子言语行为抽取 → 实体与指代解析 → 承诺关系绑定与状态归并 → 期限解析 → 逐字段蕴含与四维校验 → 纪要、待办、记忆发布。一步生成纪要时，承担人与日期最容易在压缩中丢失或张冠李戴。
  • 蕴含核验确认“引用文字支持结论”，不证明 ASR 文字就是实际说过的话，所以必须与身份、低支持区间、相关性联合使用（Kryściński 等，EMNLP 2020 的思路；结果不能直接当作中文领夹场景的效果承诺）。同一生成调用里的“自评通过”不算独立核验。
  • 承担人与说话人分开：“这个交给小王”是机主的原话，任务是小王的；待办四类按承担人与说话人的组合定义，各有证据门槛（§5.8）。
  • 业务状态与核实状态分开：持久的业务状态是 requested | acknowledged | declined | conditional | active | completed | withdrawn | superseded | conflicted；“接受”是一个事件，不是状态，它把 requested、acknowledged 推进到 conditional 或 active。承诺有两种起点：请求（request 新建 requested）与主动承诺（commit：说话人给自己定的明确承诺，如“我明天交”，新建 active 或 conditional）；核实状态 unverified | verified | user_confirmed | invalidated。“知道了”证明知悉，不证明接受；user_confirmed 也不意味着所有来源维度都通过。
  • 只有原行为人能撤回：原请求者撤回自己的请求、原承诺者撤回自己的承诺；第三人说“他不做了”不能直接取消他人的承诺。跨设备录音的时间有重叠不确定时，不靠到达顺序认定哪句是后来的改口，无法确定就标冲突。

def g8(unit_id, gen, digest):

    if snap.generation_gate != "ok" and not snap.manual: return
    acts = []
    acts, gaps = [], []
    for w in overlapping_windows(snap.context_segments, core_tokens=1500, overlap_tokens=300):
        out = llm_json(MID_LLM, PREFIX_G8, render(w, placeholders=snap.quarantine_placeholders),
                       schema=ACT_SCHEMA, retries=1)
        if out is None:                                         # 两次模式不合格：不用半成品
            gaps.append(w.core_range); continue                 # 记抽取覆盖缺口，单元标“部分生成”
        acts += keep_core_owned(validate_spans(out.acts, w), w)  # 跨度必须真实存在；重叠区的行为归核心区所在窗口

def apply_act(state, act, link):                                # 按下面的转移表；表外的组合一律标冲突
    if state is None:                                           # 还没有关联的承诺：只有两种行为能新建
        if act.kind == "request" and act.modality == "definite": return Commitment.requested(act)
        if act.kind == "commit" and act.assignee_is_speaker and act.modality in ("definite", "conditional"):
            c = Commitment.self_committed(act, conditional=(act.modality == "conditional"))   # 状态由情态定
            if act.modality == "conditional" and not act.condition: c.condition = "unresolved"    # 有条件但条件没抽出：禁止提醒
            return c
        return None                                             # 其余行为找不到对象：不新建，记为未关联
    if link.ambiguous:               return state.conflict(act) # 有多个候选、领先不足 0.15
    if not link.found:               return state.unlinked(act) # 找不到对应的请求或承诺：不改状态
    if act.kind == "acknowledge":    return state.acknowledged() if state.status == "requested" else state  # 不升级、也不让已接受的降级
    if act.kind == "accept" and can_accept(act, state):
        nxt = state.accept(conditional=(act.modality == "conditional"), evidence=act.source_refs)   # 状态由情态定
        if act.modality == "conditional" and not act.condition: nxt.condition = "unresolved"        # 禁止提醒
        return nxt
    if act.kind == "revoke":
        return state.withdraw(act.source_refs) if is_original_actor(act, state) else state.unresolved_revocation(act)
    if act.kind == "amend":
        return state.replace_fields(act) if explicit_amendment(act, state) else state.conflict(act)
    return state.apply_non_destructive(act)

期限解析（确定性规则，带版本）：

  • 锚点是发言时的当地自然日，不是上传日，也不是 04:00 起算的 day_id：11 月 8 日 03:30 说的“明天”按规则是 11 月 9 日。凌晨（00:00–05:00）说的“明天”口语上可能指睡醒后的当天，这种情况把 11 月 8 日放进 alternatives 并标歧义，不进提醒。
  • “下周三”固定为以周一为首日的下一自然周的周三；政策带版本。
  • 保留实际精度：“周三”“下午”“月底”不偷偷补成 23:59；只有日期没有时刻时，提醒时刻是用户偏好，不回写成原话的期限。
  • “收到材料后三天”存为事件相对期限，触发事件未确认就不生成绝对日期。夏令时重复或不存在的当地时间保留歧义，不自行挑一个 UTC 时刻。
  • 时区名与当时的 UTC 偏移都存（RFC 9557）。规则解析不了，LLM 只给候选，再校验日历有效性、锚点与引用。

纪要与记忆的另外两条限制：纪要上下文允许低支持文字，不代表纪要可以确定地复述其中的低支持姓名、数字或日期，这类字段在纪要里省略或标“不确定”；记忆只自动接受本人事实，假设、愿望、引用、临时状态与他人评价不转为本人长期事实。

失败与恢复

  • 模式两次不合格：不用半成品，该窗口记一个抽取覆盖缺口，单元标“部分生成”。核心区在缺口之前、且关系可能延伸到缺口里的承诺（同一承担人或对象在缺口前后出现，或缺口在承诺之后 10 分钟内），记 extraction_gap_affects，不能取得核实状态，也不提醒；无法界定影响范围时，暂停整个单元的自动核实与提醒。模型不可用：排队。
  • 生成期间单元重开或擦除：CommitOutputs 因代次、输入摘要或擦除代次不一致返回 stale / erased，结果丢弃。
  • 生成期间来源正常到期：到期与擦除不同，不改变上面三个版本，所以 CommitOutputs 另查来源的存在与到期时刻，命中返回 source_expired；产物读取路径也检查依赖的到期时刻，到期删除与发布并发时不会留下失去依据的产物。收到 source_expired 后，单元按剩余的有效来源产生新的输入修订并重新生成（单元回到 generating）；剩余来源不满足生成门槛时，generation_gate 记 sources_expired，单元以“无纪要产物”转 published（App 显示不生成的原因），不停在 generating。
  • 提交成功、响应丢失：按 request_id 返回原结果，不重复发布。

18删除服务与删除链

契约：

职责与边界

  • 删除服务判定哪些数据可以删、挡住迟到写入、执行删除、核验结果、推进各端进度、瘦身元数据。
  • 三种完成状态分开：识别结果已提交（覆盖账里该范围的结果已持久化）；云端音频已删除（对象与可写入口都处理完，可以发回执让手机释放暂存）；三端擦除已完成（云、手机、领夹都确认清除了指定范围）。
  • 领夹的正常释放依据是手机可靠落盘后的帧回执（详设 1），不等云端识别；用户擦除另向两端下发范围清除命令。
  • 到期删除：隔离档 7 天、接受档按用户设置、簇质心业务日结束后 12 小时；用户擦除与注销。不做：领夹与手机端的删除实现（详设 1、4），但给它们下发命令并跟踪进度。

原理

  • 先写后删，先删后报。 结果没落盘就删音频，会丢数据；回执早于删除，手机会删掉最后一份可重传的副本，而云端还留着音频。顺序固定后，每个崩溃点都能由巡检补齐。
  • 可删看覆盖账，不看最大序号：对象实际包含的全部有效帧都有终结结果（识别、非语音、已登记的失败缺口或擦除），且没有仍合法持有这些字节的作业或尾部（详设 5 的读依赖）。
  • 先立刻删，再等入口静默，最后清扫。 识别完成的对象立即删除，以缩短实际保留；预签名地址在有效期内可以重复使用，且过期检查发生在请求开始时（S3 文档以下载为例说明）；过期前开始的上传能否跨过过期时刻写入，要按存储适配器实测，不当作已知保证。所以“音频已删除”要等全部已签发地址过期、在途写入也确定结束，再清扫一次、确认不存在，才成立。
  • 存储适配器契约：必须提供以下之一，否则不能确认删除状态：（a）可靠的屏障：“该范围没有未完成的写入，且不再接受新写入”；或（b）经过验证、强制执行的单次请求最长时长，等全部授权过期再加这个上界，清理未完成的分块上传，再最后清扫。盲目多做两次 HEAD 不能替代。
  • 擦除是屏障，不是一次性删除。 先写擦除记录，再删数据；所有写入方“先写、后查”擦除记录，读路径也检查屏障。跨存储能保证的是：屏障生效后不再对用户可见，物理清除按可核验的进度推进。

算法

def delete_processed_audio(obj):
    with user_txn(obj.user_ref):
        cur = load_for_update(obj.id)
        require_terminal_coverage(cur.frame_ranges); require_no_active_read_dependencies(cur)
        close_upload_grants(cur); cur.state = "delete_fenced"   # 此后 prepare / commit 返回 deletion_pending：禁止新上传，手机仍不能释放
    delete_all_keys(cur)                                        # 先缩短实际保留
    if not all_grants_expired(cur) or not storage_writes_quiet(cur):   # 适配器契约 (a) 或 (b)
        return schedule(delete_processed_audio, obj, at=quiet_deadline(cur))
    abort_incomplete_multipart(cur); delete_all_keys(cur)       # 最后清扫
    proof = verify_authoritative_absence(cur)                   # 查询超时、鉴权失败不等于“不存在”
    with user_txn(obj.user_ref):
        recheck_fence_and_grants(cur); require(proof.ok)
        audio_keys.delete(cur.chunk_id)
        cur.state, cur.cloud_audio_deleted_at = "verified_absent", now()
        create_receipt_once(cur); outbox.add_id_only("receipt", cur.receipt_id)   # 手机按游标拉取，可重复

def guarded_write(cmd):                                         # 所有写入方：网关、作业、文字管线、G8、索引、提醒
    fence = read_erasure_state(cmd.user)
    require(cmd.erasure_epoch == fence.epoch and not fence.covers(cmd.dependencies))
    staged = write_staged(cmd)                                  # 外部索引、缓存先写不可见状态
    with user_txn(cmd.user):
        cur = read_erasure_state_for_update(cmd.user)
        if cur.changed_since(fence, cmd.dependencies): register_cleanup(staged); return ERASED_OR_STALE
        activate(staged)
    if dependencies_now_erased(cmd.dependencies): withdraw_and_delete(staged); return ERASED   # 外部副作用后再查一次
    return COMMITTED

def erase(user, scope):
    scope = expand_to_chunk_boundaries(user, scope)             # 每片一把 K：音频范围按分片边界向外扩，结果里展示实际范围
    with user_txn(user):                                        # 屏障与可恢复的擦除计划同一事务落盘
        e = erasures.insert(user, scope, erasure_epoch=next_epoch(user))
        plan = erasure_plan(user, scope)                        # 列出全部子任务：对象、文字、单元、簇、热词、端侧命令
        persist(plan)
    cancel_in_flight(user, scope)                               # 作业、G6/G7/G8；取消失败时其提交也被屏障拒绝
    for obj in objects_in_scope(user, scope):                   # 强删路径：不走正常的覆盖检查
        release_read_dependencies_and_tailholds(obj, scope)
        terminate_coverage(obj, scope, outcome="erased")        # 未完成的覆盖终结为 erased，扩出来的部分登记 user_erase 缺口
        enqueue(DeletionTask(obj, trigger="user_erase"))
    delete_text_in_scope(user, scope)                           # 片段正文、原始 ASR、候选、编辑历史、全文与向量索引、缓存
    delete_units_and_outputs(user, scope)                       # 单元、抽取中间结果、产物、引用副本、提醒任务、确认快照
    delete_affected_centroids(user, scope)                      # 受影响的簇 = 范围内片段引用的 cluster_id（含与机主匹配的簇）；
                                                                # 质心无法减去被擦除样本：删除质心、目录项失效、目录版本 +1 同一事务；
                                                                # 簇 ID 保留给范围外仍引用它的文字，不复用
    revoke_derived_hotwords(user, scope)                        # 由被擦除内容派生的个人热词，递增 bias_revoke_epoch
    if scope.kind in ("all", "voiceprint"): voiceprints.revoke(user)
    device_commands.add(user, kind="ERASE", ranges=frame_ranges_in_scope(user, scope))   # 手机转发给领夹
    # cloud_progress 由各子任务核验完成后汇总（对象确认不存在、索引与缓存清除确认），排队不算完成；
    # 云端全部完成 → device_pending；两端确认后才 completed
  • 巡检四类账（每小时）：元数据认为该删、对象仍在；对象存在却没有有效清单或提交记录；对象已不存在、但没有删除确认或回执；已发回执的对象又出现。第四类是高优先级异常：检查未登记的授权、在途写入与旧客户端重传。
  • 永久失败：作业失败满 48 小时，登记 cloud_failed 缺口，走同一删除流程，回执 outcome = failed。72 小时不能只靠生命周期规则：接近上限仍有未完成作业的对象，主动取消租约、给剩余覆盖登记失败并删音频；超过上限记为保留违约，不因“后台还在删”而显示达标。
  • 到期的文字：到期时刻起立即不可读（读路径检查 expires_at），清理事件即时发出，小时巡检只负责补漏。同一事务把依赖它的自动产物转为 suspended 并排队删除（溯源表的“来源正常到期删除”一行），在途的 G8 发布由 CommitOutputs 的来源复核挡住。
  • 手机销毁 K 要处理密钥表的历史页、日志、缓存与任何可恢复副本；只删包裹密钥所在的一行，不能未经验证就声称不可恢复（NIST SP 800-88）。
  • 注销：用户擦除完成后销毁该用户的数据密钥，遗漏在任何地方的密文一并失效；擦除任务的控制记录（不含正文与可恢复密钥）不随之销毁。设备离线时保持 device_pending，重连后先清除、再恢复相关上传。恢复备份、重建索引之前先应用擦除记录。

测试与验收

  • 在 PersistResult、首次删除、等待授权过期、最后清扫、记录不存在、生成回执前后逐点杀进程：无遗留音频、无重复片段、回执最终送达。
  • 一片被多个作业覆盖、尾部尚未处理时不能提前删。回执丢失、重复拉取、重复端侧确认。
  • 删除后用仍在有效期内的旧地址 PUT；过期前开始、过期后结束的上传；未完成的分块上传：巡检周期内被删且不可解密。
  • 擦除与 G6、G7、G8、用户改字、热词更新、索引写入、提醒发送并发；云端完成而设备离线时状态仍显示设备待清除；清单瘦身后的重传、乱序旧事件与过期租约提交不能复活数据。
  • 不变量：没有未覆盖的帧被正常释放；没有旧代次结果越过屏障；没有已撤回的产物继续提醒；“三端完成”必有三端的完成依据。
  • 监控：音频最大滞留时长、落盘到删除 P99、删除到回执 P99（含等待地址过期的约 15 分钟）、到期未删条数为 0。

与提案的差异

  • §5.11 把作业状态与音频对象状态串在一起：按详设 5 拆成两条状态机。s-del 的“全部帧落盘”与 §5.12 的 frames_persisted_upto 改为覆盖账。
  • c-receipt 补语义：释放音频不代表产生文字，也不代表三端都已删完。
  • §5.14 的每小时删除与“到期未删条数为 0”区分“到期不可读”与“物理清除延迟”。
  • §7 的“识别完成后立即删除，三端都不保留”按可核验的阶段表述（回执传输、离线设备、在途上传）；§5.12 清单长期保留与 §7 场景快照随音频删除的冲突，按上面的瘦身表解决。
