# 按住说话：语音识别与播报

> 状态：已实现（服务端接口、调试控制台的对话视图；三个 SDK 的封装待做） · 依赖：[Call](./m3-call.md)、[计量与配额](./m4-quota-usage.md)、[内容安全](./m4-moderation.md) · 代码：`internal/speech`、`internal/realtime/volc`（`asr.go`、`tts.go`）

## 1. 目标

按住说话是半双工的语音输入：用户按住按钮说一句，松开后发出，回复读出来。它和 [Call](./m3-call.md) 互补。Call 用端到端的实时语音模型，适合连续对话；按住说话走"识别 → 文本模型 → 合成"的级联，Agent 的文本模型只看到文字。

- **模型只看文字。** 录音先识别成文字，作为普通的文字输入提交。不把音频交给模型（[模型调用](./model-calls.md) §4 中模型直接听的语音消息仍然可用，控制台不再使用它）：
  - 文字进入日志后，其他设备、之后的 Run、召回与压缩都能直接使用它；
  - 内容安全检查与键入的文字相同，不必检查音频；
  - 不要求 Agent 的模型能听音频。
- **语音不留存。** 录音与合成的语音只在请求中经过，既不进日志，也不存为工件（ADR-0005 对媒体流的约定同样适用于这里）。识别出的文字只返回给发起的客户端，由客户端作为输入提交，之后与键入的文字没有区别。

## 2. 接口

两个无状态的 HTTP 接口，都针对一个 Session：鉴权与该 Session 的其他接口相同，配额用尽时拒绝（429）。

| 接口 | 请求 | 响应 |
|---|---|---|
| `POST /v1/sessions/{id}/transcriptions` | 请求体为一段录音（WAV、MP3、OGG 等），至多 `speech.MaxAudioBytes`（4 MB） | `{"text": "…"}`；没有识别出话语时 `text` 为空 |
| `POST /v1/sessions/{id}/runs/{run}/speech` | 无 | `audio/wav`：Run 最后一条有文字的模型输出的朗读 |

- **播报只读 Run 的回复，不接受任意文字。** 被朗读的是已写入日志、检查过的模型输出；接口不能被用来合成任意内容。Run 不在投影中时 404，Run 还没有文字回复时 409（例如只调用了工具或只展示了卡片）。
- **朗读前改写。** 去掉 Markdown 的标题、列表与强调记号，链接只读文字，至多 `speech.MaxSpeakRunes`（600）字，截在最后一个句末。
- **未配置时 501，提供商失败时 502。** 日志只记 Session 与 Run 的 ID，不记文字（ADR-0015）。

## 3. 提供商

`speech.Provider` 有两个方法：`Recognize` 返回文字与时长，`Synthesize` 返回 PCM 与采样率。当前实现是豆包语音（`volc.Speech`），与实时语音共用 `VOLC_SPEECH_API_KEY`：

- **识别**用录音文件识别极速版（`volc.bigasr.auc_turbo`）：一次请求交上整段录音、同步返回文字。按住说话的录音只有几秒，用不着流式识别。静音返回空文字（结果码 20000003），不报错。
- **合成**用语音合成 2.0（`seed-tts-2.0`），24 kHz，默认音色 `volc.TTSVoice`。AgentDef 的通话音色（`call.voice`）属于实时语音模型，语音合成不一定有，所以不沿用。

## 4. 计量

用量的 kind 为 `speech`，模型引用为 `volc/asr-flash`（识别）与 `volc/seed-tts-2.0`（合成）。用量表只有 token 列：识别的输入"token"记为音频秒数（向上取整），合成的输出"token"记为朗读的字数。价格表按每百万秒、每百万字配置这两个条目（[计量与配额](./m4-quota-usage.md) §2）。每次请求一条用量，ID 由服务端生成。

## 5. 控制台

对话视图的 🎤 按住说话：

1. 松开后识别。识别失败或没有识别出话语时提示，什么也不发。
2. 识别出的文字作为文字输入发出，与输入框中已有的文字、附件一起提交。
3. 这一轮 Run 完成时请求朗读并播放，播放时显示"🔊 停止播报"。
4. 再次按住说话时停止正在读的回复，也不再读还没回来的那一轮。Run 失败或被中断时不读。
