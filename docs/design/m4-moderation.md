# M4 内容安全

> 状态：已实现（接口与检查点，提供商为模拟实现；**上线前须接入真实提供商**，见 [上线检查清单](../launch-checklist.md)）· ADR-0021

## 1. 目标

对 EndUser 的输入与模型的输出做内容安全检查，违规内容不展示给用户、不进入模型上下文、不写入日志。检查由可替换的提供商（`moderation.Moderator`）完成；本阶段只有模拟实现（关键词），真实提供商（如云厂商的内容安全服务）上线前接入，届时只替换提供商，不改动检查点。

不做：人工复审工作台；按业务线定制的审核策略（提供商可以按 `BusinessLine` 区分，但配置方式随真实提供商确定）。

## 2. 接口

```go
type Moderator interface {
    Check(ctx, Request) (Verdict, error)
}
type Request struct {
    Stage        Stage   // input | output
    BusinessLine string
    Text         string  // 输入文本；输出时为回复文本与调用参数
    Images       []Image // 输入中的图片工件（artifact ID 与 MIME 类型），由提供商自行读取
}
type Verdict struct {
    Block  bool
    Labels []string // 提供商给出的违规类别，用于统计与审计，不含原文
}
```

## 3. 检查点

| 检查点 | 位置 | 违规时 | 提供商不可用时 |
|---|---|---|---|
| 用户输入（新 Run 与插话） | Service.Submit，写日志之前 | 拒绝，HTTP 422；输入不写入日志 | 拒绝，HTTP 503 |
| 模型输出（回复文本与调用参数） | Worker，模型返回之后、写日志之前（计量之后） | 回复替换为固定的拒答文本，丢弃全部调用，并写入 `ContentModerated`；Run 正常完成 | Step 出错重试；持续不可用时按 StepErrorBudget 使 Run 失败 |
| Call 的转写（用户的话、助手的话） | `service.AppendTranscript`，写日志之前（[Call](./m3-call.md) §6） | 不写日志；中止进行中的回复、停止播放；用户的话违规时说出拒答 | 同违规 |

- **Call 播出的语音**边生成边播放，只能依赖厂商的严格审核；我们的检查在助手整句生成时进行（早于播完），违规时中止剩余的播放（ADR-0027）。
- **失败即拒绝**：内容安全服务不可用时不放行。
- **调用参数也检查**：模型可能以用户的名义发送消息、写文件、保存 Memory，这些内容由调用参数携带。
- **调用结果暂不单独检查**：设备、沙箱、MCP 的结果进入模型上下文，但由其衍生、展示给用户的内容都经过输出检查。上线前评估是否需要对外部来源（MCP、网页）的结果单独检查。
- **上下文压缩的摘要不检查**：它不展示给用户，内容来自已检查过的输入与输出。

### `ContentModerated` 事件

`{run_id, attempt, stage, labels}`，不含原文。它与替换后的 AssistantMessage 同批提交，记录"这一轮的输出被拦截"，供审计与统计；违规原文不进入日志。

### 流式草稿

实时增量（ADR-0013）在模型生成过程中推送，此时尚未检查。增量本来就是草稿，客户端以提交的 AssistantMessage 为准；输出被拦截时，客户端收到替换后的拒答文本，须用它覆盖草稿。监管若要求草稿也不得展示违规内容，需要真实提供商支持流式检查（按片段检查、违规时取消生成），列入上线检查清单。

## 4. 模拟提供商

`moderation.Mock`：命中关键词列表即拦截，标签为 `mock`。默认列表只包含测试用的标记词（如 `【违规测试】`），可用 `serve -moderation-terms <文件>` 替换。它不具备真实的识别能力，**只用于开发与测试**；`serve` 使用它时启动日志打印警告，指标 `yanshi_moderation_mock` 为 1。

## 5. 观测

- `yanshi_moderation_checks_total{stage, result}`，result 为 allow | block | error；
- `yanshi_moderation_duration_seconds{stage}`。

日志只记录 Session、Run ID 与标签，不记录内容。

## 6. 验证

- 单元测试：输入拦截时日志中没有该输入；输出拦截时日志中只有拒答文本、没有调用、有 `ContentModerated`；提供商出错时输入返回不可用、输出重试。
- 模拟测试：模拟提供商按随机源拦截或报错；不变量：被拦截的输出原文从不出现在日志中，每个 `ContentModerated` 之后的 AssistantMessage 是拒答文本且没有调用；覆盖统计包含输入拦截、输出拦截与提供商错误。

## 7. 验证结果

- 单元测试：违规输入（新 Run 与插话）返回拒绝且日志不变；提供商出错时输入返回不可用；输出在提供商出错时不写入、恢复后违规回复被替换为拒答文本、调用被丢弃、有 `ContentModerated`，日志中没有违规原文。
- 模拟测试：模拟提供商按文本散列拦截约 1/12 的输入与输出，故障模式下 3% 的检查返回错误。300 个种子中拒绝输入 719 次、拦截输出 154 次、提供商错误 345 次，不变量全部成立。变异检验：去掉输出替换、去掉输入检查，分别被"被拦截的输出 / 输入出现在日志中"发现。
