# xinli 的领夹如何配合语音识别

> 状态：设计（未实现） · 依赖：[xinli 的语音识别选型与评测](./xinli-asr-selection.md) §3.5；[Persona 架构](./persona-architecture.md) §4.1（采集与识别）；ADR-0036（旁听只收文字、说话人标签由内核外部给出） · 术语：[xinli 应用层术语](../../apps/xinli/CONTEXT.md) 的 Recognizer、采集会话、采集世代、佩戴者发声信号

硬件可改善远场拾音、减少静音上传，并为佩戴者判定提供额外证据；能改善多少、能否节省声纹成本，须由真实设备评测确认。本文写领夹与手机上的 HostApp 需要提供什么、怎么交给识别，以及怎么验收。它不是完整的硬件规格书：电池、结构、外观、蓝牙芯片选型只在影响识别时提及。文中的数值都是初始建议，以[选型评测](./xinli-asr-selection.md)的结果为准。

## 1. 为什么硬件能帮上

| 问题 | 硬件可提供什么 | 仍须验证什么 |
|---|---|---|
| 佩戴者与他人 | 振动、近场与佩戴状态，帮助判断佩戴者是否在发声 | 发声证据不证明转写文字来自佩戴者，尤其是重叠与媒体声 |
| 他人远场语音 | 多麦克风与声学前端改善信噪比 | 是否同时损失远场短回应、否定和自然重复 |
| 识别成本 | VAD 减少无语音上传 | 漏识、余量、误触发与复核后的完整账单 |
| 时间 | 设备帧序号和时钟同步 | 漂移、断连、静音裁切后能否还原原始时间轴 |
| 媒体语音 | 结合振动与声源线索辅助拒绝误归属 | 佩戴者同时发声、声学/机械耦合、重放的误触发 |

**硬件不替代文字来源的证明。** ASR 始终要转写佩戴者与他人的话。是否需要供应商声纹、能否由独立组件完成身份判定，按完整配置实测；不因硬件存在就把 `speaker_0` 或最大音量的说话人当作佩戴者。

## 2. 链路与分工

```
领夹 ──蓝牙──▶ 手机 HostApp ──HTTPS──▶ 采集服务（Recognizer：ASR、融合、声纹）──▶ Persona
 拾音、前端处理       缓冲、按静音分片、上传          识别、说话人判定
 VAD、佩戴者发声信号   元数据组装、补传                 文字片段（speaker、text、at）
 编码、打时间、本地缓冲
```

- **领夹**：采集与端侧信号处理，产生音频、VAD 区间与佩戴者发声信号，带时间戳。
- **HostApp**：接收与缓冲，按静音分片，附元数据上传；断网时缓冲并补传，识别后再按文字采集契约组批与排序（[xinli-captures.md](./xinli-captures.md) 的有序文字采集一节）。
- **采集服务**：识别与融合。说话人标签的最终判定在服务端做，硬件信号是它的输入之一；判定逻辑集中在一处，便于评测与更换供应商。
- 领夹不建模为内核 Device 或 Node（ADR-0036）；本文的信号与元数据都只在应用层流转，不进内核。

## 3. 佩戴者发声信号（最重要）

**佩戴者发声信号**是领夹按帧给出的"此刻佩戴者本人在说话"的概率或标记，与音频按同一时间轴对齐。

### 3.1 来源

以下是待比较的方案，不预先按可靠性排定：

1. **振动传感。** 骨传导拾音单元或加速度计可捕捉与佩戴者发声相关的振动。衣物、接触、机械冲击和外部声源耦合可能影响结果，须在真实佩戴中测误检与漏检。
2. **双麦克风近场特征。** 不同朝向、声级与到达方向可提供声源线索；近处他人、反射和佩戴位置变化可能破坏这些特征。
3. **单麦近讲特征。** 声级与频谱只作为辅助，不单独授予 `wearer`。

### 3.2 输出

- 初始帧长 10–20 ms，每帧提供概率或标记，与音频同一时间轴；记录模型/固件版本。
- 提供佩戴状态与信号有效性：未佩戴、接触不良、丢帧、时间不同步分别标记。未知不能默认为有效；信号失效时只使用已经验收的备用判定路径，否则归为 `other`。
- 信号随音频上传，数据量与计算、电量成本一并测量。

### 3.3 服务端融合

目标是判断**哪些识别文字属于已知佩戴者**，不是只判断某段时间佩戴者有没有出声。首轮直接验收这项识别能力，不等下游大模型纠正。

1. 先用设备帧与时间映射对齐信号、音频、ASR 说话人分段/词。校验佩戴状态、接触与信号质量；无效输入不得当作正证据。
2. 将佩戴者发声信号与片内分离、重叠检测、声源分离或注册声纹等证据结合，核对**文字到说话流、说话流到佩戴者**的两层对应。帧占比高只能作为特征，不能直接输出 `wearer`。
3. 对重叠或边界按可验证的词/发声边界细分；仅在对应关系足够可靠时标 `wearer`。若混合转写无法拆清，整段降为 `other`，并在评测中记录拒识及漏失；不把其中的外部文字整体升级。
4. 每个分片重新验证佩戴者身份。片内编号、首位说话者、音量或发言最多者均不能代替身份依据；佩戴者可能整片未发言。
5. 信号不可用或冲突时，可退到已通过同样门槛的“分离＋佩戴者声纹”路径。没有可靠备用证据时保持 `other`，不自动把某个局部编号认作佩戴者。

“全部降为 other”虽然减少误升级，也会丢失佩戴者内容，须同时通过 A10 的召回门槛。融合阈值只在调参集选择；真实重叠、媒体声和未发言留出样本决定是否达标。

### 3.4 已知的难点

- 重叠说话：佩戴者与他人/媒体同时发声，ASR 可能混合转写或只转写更响的声源；即使发声信号完全正确，也可能发生文字误归属。
- 非言语振动：咳嗽、笑、咀嚼、走路、衣物摩擦会误触发，须与 VAD 联合判断。
- 耳语与低声：振动弱，可能漏判。
- 以上在 §9 的测试中单列场景。

## 4. 麦克风与声学前端

- **麦克风**：双麦是待验证的基线方案，用于 §3.1 第 2 项；与单麦在相同场景对照，信噪比与最大声压级要能同时容纳佩戴者的近讲（不削波）与他人的远场（不淹没在底噪里）。
- **采样**：16 kHz、16 bit 起，这是主流 ASR 的输入规格；更高采样率是否有收益由实测决定；实际输入须满足所选接口及声纹组件的要求。
- **降噪要克制。** 激进的降噪会产生 ASR 不熟悉的失真，常常比不降噪更差。前端降噪、AGC 的强度做成可配置，由评测决定；必要时保留一路未处理的音频。
- **AGC**：避免快速增益起伏（"抽吸"），佩戴者近讲与他人远场的声级差很大，固定增益与慢速 AGC 作为对照配置，不预设哪种更稳。
- **风噪与摩擦**：防风网罩、拾音孔朝向与机械隔振在结构阶段解决；事后靠算法去除代价高。
- **声道**：默认上传一路混合声道加佩戴者发声信号。多声道的输入支持、是否按声道收费及分离兼容性逐家核实；两路（佩戴者波束、环境）只有在文字来源对应和效果收益经验证后才采用。

## 5. 端侧 VAD

VAD 决定送多少音频去识别，是成本的重要杠杆（[选型评测](./xinli-asr-selection.md) §3.2），同时决定会不会漏掉话。

- **偏向召回。** 漏掉一句"好的，我周五前给你"就是漏记一条承诺，多送几秒静音只是多花一点钱。
- **前后余量**：语音起点之前保留约 300–500 ms，结束后延迟一段再关闭，避免切掉首字与尾字。
- **抗噪**：在 §9 的各类环境中测漏检率（尤其是首音节）与误检率；误检会把噪声送去识别，并可能引出幻觉文字。
- **统计**：分别记录原始录音、VAD 后含余量的送识别时长和实际计费时长（只记时长，不记内容），作为成本模型中使用画像的真实数据（[评分表](./xinli-asr-scorecard.md) §3）。
- VAD 判为静音时可评估无线电/主控休眠；保留检测与前置缓冲所需电路，唤醒延迟不得截掉首音节，节电效果实测。

## 6. 编码、传输与时间

- **传输基线**：评估 BLE 自定义传输或 LE Audio，并记录实际音频配置、丢包恢复与手机后台行为。经典蓝牙通话链路的带宽/编码限制须单独对照，不把系统协商结果假定为无损原音。
- **编码**：Opus/LC3 为候选传输编码，16 kHz 单声道为初始基线。供应商不支持设备编码时，由 HostApp/采集服务解码或转码；质量、耗时和费用计入完整配置。按[选型评测](./xinli-asr-selection.md) §5.1、§9.1 扫描码率。
- **时钟**：每次连接同步并保留设备单调帧序号到 UTC 的映射，检测漂移、重启和手机时间变化。`at` 来自录音实际时刻，不是上传/识别完成时刻；业务日用固定时区。
- **静音裁切**：保存每段保留音频在原始时间轴上的起止位置与采样偏移。ASR 的压缩音频偏移先映回原录音，再分配时间与业务日；不能用“分片起点＋压缩后的偏移”直接计算。
- **本地缓冲**：设备与 HostApp 缓冲加密，容量和最大期限明确；接收方持久保存后才确认设备可清除。识别完成后删除音频与发声信号，待正式接受的文字按采集协议单独持久保存。
- **擦除、到期、注销**：清理相关设备/手机缓冲和在途任务。设备离线时，恢复连接先同步生命周期状态，再决定是否上传；服务端拒收旧世代或失效会话的迟到结果。不能因设备暂时离线就认为物理清除已经完成，也不能给旧内容换新世代重交。

## 7. 分片与元数据

现有 `recognition.ChunkRef` 用于识别接口的分片引用；真实音频处理及下表中的音频、传感与时间映射扩展尚未实现，已有采集身份字段按现有契约复用。实现时在应用层设计临时存储与删除流程，不把音频写进内核。

- **切点与最大等待**：优先在静音处切，但连续说话也要有最长等待/长度；比较 2、5、10 分钟及边界平移，不能为等待静音无限延迟。
- **重叠是独立变体**：基线不重叠；若边界漏字明显，可增加有限重叠并在提交前去重。保留原时间轴，区分重叠带来的重复与真实重复发言，额外计费计入成本。
- **音频分片不等于文字批次**：超过 2000 字的片段先按可还原时间的边界拆段，再按业务日和每批 1–200 段组批；文字采集 `seq` 跨午夜连续，与音频分片序号分开。分片完成可乱序，正式提交仍遵守有序采集契约。

| 元数据（待实现） | 用途 |
|---|---|
| 分片 ID、音频帧/分片序号 | 音频去重、缺口检测与补传 |
| 原采集会话、业务日对应的采集世代 | 约束迟到识别结果；跨日逐日检查，不能更新旧请求世代 |
| 原始起止 UTC、时区、设备时钟映射 | 还原 `at` 与业务日，检测漂移 |
| 保留区间到原音频的采样偏移映射 | VAD 裁切、重叠去重与时间还原 |
| 采样率、编码、码率、声道布局 | 解码与识别参数 |
| VAD、发声信号、佩戴状态与有效性 | 融合及质量诊断 |
| 固件、前端、注册声纹/融合配置版本 | 区分配置变化，结果可复算 |

音频及细粒度信号只在识别完成前缓存；用于待提交文字的最小身份/时间与批次元数据随待提交状态保留。`202 staged` 不算接受，只有 `accepted` 后清待提交正文。重试复用原批次，不能重识别后在同一序号提交异文。日志只记必要 ID、时长与计数；评测原始响应另在受控数据集中保存并按授权删除。

## 8. 对声纹与合规的影响

- **能否省去佩戴者声纹是待验证假设。** 只有“无声纹＋硬件融合”完整配置在重叠、媒体、未佩戴、未发言及跨天真人场景均通过 A3/A7/A10，才可据此减掉声纹。需要声纹时按处理依据注册并提供删除，不因接口支持而默认启用。
- **他人身份可后置。** 片内区分不等于跨片认出同一人；跨天他人身份单独评测并取得相应处理依据，不成为首期硬门槛（[选型评测](./xinli-asr-selection.md) §3.3）。
- **录音可感知、可停止。** 录音指示与物理静音作为产品要求评估；硬件开关、指示状态及缓冲清除行为均实测，不以软件显示代替实际状态。

## 9. 验收

重录台用于麦克风、编码、远近场和媒体播放对照；**佩戴者发声信号、声纹与最终融合须用真人自然发声验收**。假人嘴部扬声器不能产生真人胸腔振动，播放器声音也不能作为真实佩戴者的正例。真人小样本尽早开始，合成/重录用于扩充覆盖。

| 项 | 指标 | 必测场景 |
|---|---|---|
| 发声信号本身 | 误检、漏检、不可用率、校准与时间偏差；不只报帧级准确率 | 衣物/接触/位置、不同日期、耳语、咳嗽笑声、咀嚼、走路与摩擦 |
| 融合后的文字归属 | A3 他人→wearer、A7 媒体→wearer、B3 佩戴者召回/误拒；文字来源对齐 | 重叠、媒体同时播放、整片无佩戴者发言、仅短回应、相似音色、跨片编号互换 |
| 失效与回退 | 佩戴状态误判、信号失效后的误归属/召回 | 桌面、口袋、包内、接触不良、信号丢帧或时间错位 |
| VAD | 首尾音节/整句漏识、远场短回应召回、误触发、送识别与计费时长 | 安静、会议、餐厅、车内、街道与长静音 |
| 编码与前端 | 关键错误率、CER、近/远场遗漏，开关/码率对照 | 同一录音与现场录音，AGC、降噪、压缩、削波 |
| 分片与时间 | 边界漏字/重复、原始时间偏差、跨日拆批 | 连续讲话、长静音、时钟漂移、断连补传 |
| 工程与删除 | 端到端新鲜度、峰值恢复、旧世代结果拒收、各处缓冲清除 | 重启、乱序、擦除、到期、解绑与注销 |
| 续航 | 实际运行时长、唤醒耗时与漏音 | 完整典型画像，传输与信号处理均启用 |

每个候选至少比较“分离＋佩戴者声纹”和“同配置＋硬件信号”；无声纹变体单独登记。有无硬件均使用相同门槛，缺失信号回退也属于被测方案。A3/A7/A10 看完整融合结果，B4 仍衡量片内区分，不能用发声信号准确率替代。

报告分子/分母、按佩戴者与会话分组的置信区间、独立样本覆盖及拒识。音频帧不当作独立安全机会；几个小时零误识不足以证明通过。验收方法遵循[选型评测](./xinli-asr-selection.md) §7、§9.5，首轮不调用整理 Agent。

## 10. 对选型的影响

| 证据 | 决策 |
|---|---|
| 无声纹融合配置在全部必测场景达标 | 可不购买供应商的佩戴者声纹能力；仍须转写双方并提供必要的说话人区分 |
| 硬件只在部分场景有效 | 保留经过验收的身份回退路径；未知降为 `other`，召回损失照计 |
| 单麦或硬件证据不足 | 使用独立通过验收的分离＋佩戴者判定方案，或继续补测；不凭硬件类型临时修改评分权重 |
| 只有片内分离，未完成佩戴者判定 | 仅作转写组件比较，不能直接用于 xinli 的可信说话人标签 |

不提供某项能力的便宜 ASR 可以与独立组件组合，但应把整套链路的费用、延迟、误识和删除能力作为一个候选。

## 11. 待决问题

- 领夹形态与佩戴位置是否适合振动传感；双麦能否提供足够的辅助证据，两者均须实测。
- 蓝牙方案（BLE 自定义传输或 LE Audio）与手机平台的后台限制。
- 设备本地缓冲的容量，以及断连多久后停止录音。
- 前端降噪、AGC 与码率的最终配置（由 §9 的测试决定）。
- 录音指示与物理静音开关的形式（与法务、产品一起定）。
