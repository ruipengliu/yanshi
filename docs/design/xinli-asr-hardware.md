# xinli 的领夹如何配合语音识别

> 状态：设计（未实现） · 依赖：[xinli 的语音识别选型与评测](./xinli-asr-selection.md) §3.5；[Persona 架构](./persona-architecture.md) §4.1（采集与识别）；ADR-0036（旁听只收文字、说话人标签由 HostApp 给出） · 术语：[xinli 应用层术语](../../apps/xinli/CONTEXT.md) 的 Recognizer、采集会话、采集世代、佩戴者发声信号

ASR 最难做好的几件事——区分佩戴者与他人、远场与噪声、为静音付费——在声源处用物理手段解决，比在云端用模型解决便宜且可靠。本文写领夹与手机上的 HostApp 需要提供什么、怎么交给识别，以及怎么验收。它不是完整的硬件规格书：电池、结构、外观、蓝牙芯片选型只在影响识别时提及。文中的数值都是初始建议，以[选型评测](./xinli-asr-selection.md)的结果为准。

## 1. 为什么硬件能帮上

| 问题 | 只靠云端 ASR | 硬件配合后 |
|---|---|---|
| 佩戴者与他人 | 说话人区分加声纹，跨分片不稳定；他人→佩戴者错误是安全问题（ADR-0036） | 佩戴者发声时身体振动、离麦克风最近，可直接测出（§3） |
| 他人的远场语音 | 信噪比低，字错率高 | 多麦克风前端改善拾音（§4） |
| 识别成本 | 全天录音按时长计费 | 端侧 VAD 只送有人说话的部分（§5） |
| 时间戳 | 依赖上传时刻推算 | 设备按帧打时间，`at` 可靠（§6） |
| 背景媒体语音的注入 | 电视、外放的话可能被标成佩戴者 | 媒体声不会引起佩戴者的身体振动，振动信号天然不受它影响 |

其中第一项收益最大：佩戴者判断可靠时，ASR 只需要把他人的话转写准、他人之间分开即可，不必再依赖佩戴者声纹，可选的方案更便宜，合规负担也更小（§8）。

## 2. 链路与分工

```
领夹 ──蓝牙──▶ 手机 HostApp ──HTTPS──▶ 采集服务（Recognizer：ASR、融合、声纹）──▶ Persona
 拾音、前端处理       缓冲、按静音分片、上传          识别、说话人判定
 VAD、佩戴者发声信号   元数据组装、补传                 文字片段（speaker、text、at）
 编码、打时间、本地缓冲
```

- **领夹**：采集与端侧信号处理，产生音频、VAD 区间与佩戴者发声信号，带时间戳。
- **HostApp**：接收与缓冲，按静音分片，附元数据上传；断网时缓冲并按序补传，与有序采集会话的序号契约一致（[xinli-captures.md](./xinli-captures.md) 的有序文字采集一节）。
- **采集服务**：识别与融合。说话人标签的最终判定在服务端做，硬件信号是它的输入之一；判定逻辑集中在一处，便于评测与更换供应商。
- 领夹不建模为内核 Device 或 Node（ADR-0036）；本文的信号与元数据都只在应用层流转，不进内核。

## 3. 佩戴者发声信号（最重要）

**佩戴者发声信号**是领夹按帧给出的"此刻佩戴者本人在说话"的概率或标记，与音频按同一时间轴对齐。

### 3.1 来源

可单独或组合使用，按可靠性排序：

1. **振动传感（骨传导拾音单元或加速度计）。** 佩戴者说话时胸腔、锁骨附近会振动，他人的声音和媒体声不会。它的有效性取决于与身体的接触：领夹夹在衣领上时接触不如耳机稳定，须在不同衣物、佩戴位置上实测（§9）。
2. **双麦克风的近场特征。** 一只麦克风朝向嘴部，一只朝外或朝下。佩戴者距离几厘米到十几厘米，两只麦克风的声级差与到达方向明显；他人在一米以外，两只麦克风的声级接近。
3. **近讲能量。** 单麦克风时只能用声级与频谱特征粗判，易受近处他人与大声环境干扰，只作为补充。

### 3.2 输出

- 帧长 10–20 ms，每帧一个 0–1 的概率（或经阈值后的标记），附设备时间戳。
- 同时给出**佩戴状态**：未佩戴（放在桌上、口袋里）时振动与近场特征都失效，信号标为不可用，服务端退回纯 ASR 判定。佩戴状态可由加速度计姿态或接近传感器判断。
- 信号随音频分片一起上传（§7），数据量很小。

### 3.3 服务端融合

采集服务把 ASR 的分段与佩戴者发声信号按时间对齐：

- 分段内佩戴者发声帧占比高 → `wearer`；低 → `other`，他人之间的区分沿用 ASR 的说话人区分；
- 介于两者之间（重叠说话、边界）→ 按句再切分，仍不能判定时标为 `other`。**宁可把佩戴者的话标成他人，不把他人的话标成佩戴者**：前者是漏记一条承诺，后者让外部内容被当作用户原话；
- 信号不可用时，退回 ASR 的说话人区分与佩戴者声纹。

### 3.4 已知的难点

- 重叠说话：佩戴者与他人同时说，振动只说明佩戴者在说，不说明另一个声音是谁。
- 非言语振动：咳嗽、笑、咀嚼、走路、衣物摩擦会误触发，须与 VAD 联合判断。
- 耳语与低声：振动弱，可能漏判。
- 以上在 §9 的测试中单列场景。

## 4. 麦克风与声学前端

- **麦克风**：至少两只 MEMS 麦克风，满足 §3.1 第 2 项；信噪比与最大声压级要能同时容纳佩戴者的近讲（不削波）与他人的远场（不淹没在底噪里）。
- **采样**：16 kHz、16 bit 起，这是主流 ASR 的输入规格；更高采样率对识别帮助有限，只增加流量。
- **降噪要克制。** 激进的降噪会产生 ASR 不熟悉的失真，常常比不降噪更差。前端降噪、AGC 的强度做成可配置，由评测决定；必要时保留一路未处理的音频。
- **AGC**：避免快速增益起伏（"抽吸"），佩戴者近讲与他人远场的声级差很大，固定增益或慢速 AGC 更稳。
- **风噪与摩擦**：防风网罩、拾音孔朝向与机械隔振在结构阶段解决；事后靠算法去除代价高。
- **声道**：默认上传一路混合声道加佩戴者发声信号。识别多数按声道计费，两路（佩戴者波束、环境）只在评测证明值得时采用。

## 5. 端侧 VAD

VAD 决定送多少音频去识别，是成本的第一杠杆（[选型评测](./xinli-asr-selection.md) §3.2），同时决定会不会漏掉话。

- **偏向召回。** 漏掉一句"好的，我周五前给你"就是漏记一条承诺，多送几秒静音只是多花一点钱。
- **前后余量**：语音起点之前保留约 300–500 ms，结束后延迟一段再关闭，避免切掉首字与尾字。
- **抗噪**：在 §9 的各类环境中测漏检率（尤其是首音节）与误检率；误检会把噪声送去识别，并可能引出幻觉文字。
- **统计**：记录每天的有效语音时长（只记时长，不记内容），作为成本模型中使用画像的真实数据（[评分表](./xinli-asr-scorecard.md) §3）。
- VAD 关闭期间无线电与主控可以休眠，这也是续航的主要来源。

## 6. 编码、传输与时间

- **不用经典蓝牙通话链路（HFP）。** 它的窄带模式只有 8 kHz，宽带模式也只有 16 kHz 且编码质量有限，对识别损失很大。用 BLE 自定义传输或 LE Audio，在设备端编码。
- **编码**：Opus 或 LC3，16 kHz 单声道。码率越低识别越差，具体码率用评测的码率扫描确定（[选型评测](./xinli-asr-selection.md) §5.1 的声学模拟与 §9.1 的不变性测试）。
- **时间戳**：设备每次连接手机时同步时钟，音频帧带序号与设备时间；HostApp 把它换算为带时区的时间，写进片段的 `at`。时钟漂移要能检测与校正，承诺的改动时间与"明天""下周三"的换算依赖它。
- **本地缓冲**：手机断连时领夹在本地缓冲（容量按断连时长的预期确定），加密存储，手机确认收到后立即删除。HostApp 侧同样只缓冲到识别完成（[Persona 架构](./persona-architecture.md) §4.1）。
- **擦除与注销要能到达设备。** 用户擦除一段原文或删除一天时，领夹与 HostApp 中该时段尚未上传的缓冲也要清除，与采集世代的语义一致（[xinli-captures.md](./xinli-captures.md) 的擦除一节）；解绑设备或注销账号时清空设备上的全部缓冲。

## 7. 分片与元数据

HostApp 把音频切成分片交给识别，每个分片对应一个 `recognition.ChunkRef`。

- **在静音处切。** 用 VAD 区间选切点，不在句中切；分片之间不重叠，避免重复文字。
- **分片长度**是新鲜度与说话人区分效果之间的权衡：太短，ASR 的说话人区分缺少上下文；太长，"随时提问"等得久。由评测决定，初始可取几分钟一片。
- **每个分片的元数据**（只含识别需要的字段）：

| 字段 | 用途 |
|---|---|
| 分片 ID、序号 | 去重与按序补传 |
| 起止时间（UTC）与时区 | 片段的 `at`、业务日归属 |
| 采样率、编码、码率、声道布局 | 识别参数 |
| VAD 区间 | 跳过静音、校准成本 |
| 佩戴者发声信号与佩戴状态 | §3.3 的融合 |
| 固件与前端配置版本 | 评测与回归时区分硬件变化 |

元数据与音频同样只在识别完成前保留；日志与指标中只记分片 ID 与时长（ADR-0015）。

## 8. 对声纹与合规的影响

- **佩戴者声纹可能不再需要。** 佩戴者发声信号可靠时，判定佩戴者不依赖声纹，可以不采集佩戴者这一项生物识别信息；需要时作为信号不可用时的后备，经单独同意注册。
- **他人仍是难点。** 跨分片、跨天识别同一个他人仍需要声纹或聚类，硬件帮不上；能否这样做取决于法务结论（[选型评测](./xinli-asr-selection.md) §3.3）。
- **让旁人知道在录音。** 录音指示灯、物理静音开关（切断麦克风供电，而不只是软件静音）便于旁人知情和佩戴者随时停止，是商业化时合规与信任的一部分，也减少不同意被录的他人进入原文。

## 9. 验收

在[选型评测](./xinli-asr-selection.md) §5.2 的重录台上进行：设备戴在假人或真人身上，假人嘴部的扬声器扮演佩戴者，1–3 米外的扬声器扮演他人与媒体声。振动传感须用真人佩戴验证，仿真嘴不会引起胸腔振动。

| 项 | 指标 | 场景 |
|---|---|---|
| 佩戴者发声信号 | 帧级准确率；他人与媒体声误判为佩戴者的比例 | 安静、会议、餐厅、车内、街道；不同衣物与佩戴位置；重叠说话、耳语、咳嗽与笑、走路 |
| 融合后的说话人判定 | 他人→佩戴者比例、佩戴者→他人比例，与不用硬件信号的纯 ASR 对比 | 同上，配合每个 ASR 候选 |
| 佩戴状态 | 未佩戴误判为佩戴的比例 | 放在桌上、口袋、包里 |
| VAD | 语音漏检率（首音节单列）、误检率、每天送识别的时长占比 | 各类环境 |
| 编码码率 | 不同码率下的承诺关键错误率 | 码率扫描 |
| 前端处理 | 降噪、AGC 开与关的承诺关键错误率 | 各类环境 |
| 续航 | 全天佩戴（VAD 开启）的实际时长 | 典型使用画像 |

**并入选型评分。** 每个 ASR 候选都跑"有硬件信号"与"无硬件信号"两组：前者在佩戴者判断上通常大幅领先时，评分表的 A3（他人→佩戴者比例）与 B3、B4 以融合后的结果计，不提供说话人区分的便宜方案也能进入短名单。

## 10. 对选型的影响

| 硬件结论 | ASR 侧的要求 |
|---|---|
| 振动或双麦信号可靠（融合后 A3 达标） | 不要求供应商区分佩戴者；只需他人的转写与他人之间的区分；佩戴者声纹可省 |
| 信号只在部分场景可靠 | 信号可用时融合，不可用时退回供应商的说话人区分与佩戴者声纹 |
| 只有单麦、无振动传感 | 完全依赖供应商的说话人区分与声纹，评分表中 B3、B4 的权重应上调 |

## 11. 待决问题

- 领夹的形态与佩戴位置能否保证振动传感的接触；不行时以双麦为主。
- 蓝牙方案（BLE 自定义传输或 LE Audio）与手机平台的后台限制。
- 设备本地缓冲的容量，以及断连多久后停止录音。
- 前端降噪、AGC 与码率的最终配置（由 §9 的测试决定）。
- 录音指示与物理静音开关的形式（与法务、产品一起定）。
