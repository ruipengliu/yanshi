# 对照记录：领夹 ASR 提案与现行转写设计

> 状态：已裁决（2026-11-14），产品负责人确认全部按建议取舍，已改入 `docs/design` · 对照双方：[领夹 ASR 整体方案](../proposals/lavalier-asr/index.html)（提案，2026-11-07，自述“不约束本仓库的现有实现”）与 [xinli 的声音转写方案](../design/xinli-transcription.md)（现行设计，2026-11-01）及其依据 ADR-0036、ADR-0037、ADR-0043、ADR-0048、ADR-0050 · 术语以 [xinli 应用层术语](../../apps/xinli/CONTEXT.md) 为准

两份文档描述的是同一条链路：领夹录音，经手机上传，在云端识别并判定说话人，交给 xinli 整理。代码没有因提案而变化，但现在有两个互相矛盾的事实源。本文逐条给出取舍，目标是只留一份设计：**提案并入 `xinli-transcription`，作为它的下一版；不另起一套系统。**

取舍的总原则：

- **分层不动。** 提案的 G2–G7（VAD、播放检测、识别与校验、说话人、相关性、三档）全部落在应用层的采集服务（`apps/xinli/recognition`）；G8 不另建 LLM 管线，落到现行的 `xinli-day` Run 与 Persona 变更集（ADR-0043）。
- **内核不认识的细节留在业务线。** 原文存放在业务线（ADR-0050），业务线可以保存比内核更细的状态（未知说话人、隔离、低支持），交给内核的可信页仍只有现行字段。
- **提案更严的地方，采纳提案；需要推翻已接受 ADR 的地方，一期沿用现行。**

## 1. 对照表

“ADR”一列：**否**表示按建议取舍不需要 ADR，只改设计文档；**条件**表示建议的取舍不需要 ADR，但如果产品选了另一边就需要。

## 2. 结论

- 按建议取舍，**一期不需要新的 ADR**：提案的增量（三态说话人、隔离、低支持、热词、覆盖账、对话单元）都能在应用层与 Persona 内完成，内核契约不变。
- 下面五处是**有条件的 ADR**，都对应“选了另一边”：用户设置长期保留（修订 ADR-0037）；让模型看到未知或低支持标记、强制执行文字可靠性（扩可信页与 `memgate`）；擦除时自动撤回 Memory（修订 ADR-0050）；向三方开放原文（修订 ADR-0048）；评测后选定自建 ASR（新增 ADR）。
- 需要产品确认的是 #4（`wearer` 门槛与 T1 的关系）、#5（他人簇质心，须法务）、#20（保留期）。

## 3. 裁决

2026-11-14 产品负责人确认：

1. 提案并入 `xinli-transcription`，`docs/design` 是唯一事实源。
2. #4：可信页的 `wearer` 只给满足 T1 的证据级；时间线级的机主只在 App 显示。
3. #5：他人日内簇质心在法务确认后保留到业务日结束后 12 小时；确认之前在识别完成后删除。
4. #20：一期沿用 7 天原文期限，隔离档受同一期限约束；不提供用户可设的长期保留。

其余各条按表中“取舍”执行；标为“条件”的 ADR 均未触发。
