# yanshi 技术总览

> 面向评审者与后续开发者的自包含技术读本。
> 内容对照的提交：`bcb006d`（2026-10-12）。此后代码若有变化，以代码为准。

yanshi 是公司内部的**分布式 Agent 运行时基础设施**，承载多条 C 端业务线：业务线只需声明"Agent 做什么"，平台负责让 Agent 在云端、手机、电脑之间**长时间、可靠、安全、低成本**地运行。

本套文档把项目的设计思路自顶向下讲一遍：从目标与约束出发，到核心模型、执行引擎、能力与多端、信任边界、存储与部署、质量保障，最后是全部架构决策的来龙去脉和尚未解决的问题。它**不依赖**仓库中其他文档就能读懂，也不摘录代码——逻辑用图或语言无关的伪代码表达；只有附录 B 把概念对应到代码位置。

## 约定

- **状态标记**：✅ 已实现并经测试或实测验证 · 🟡 部分实现，缺口在文中说明 · ⚪ 已设计未实现，或仅为规划。凡没有标记的描述都指已实现的行为。
- **决策小节**统一为四段：**背景**（为什么要决定）→ **决策**（决定了什么）→ **取舍与后果**（放弃了什么、付出什么代价）→ **体现**（在系统行为中怎么看出来）。旁注"对照 ADR-00xx"便于与仓库中的决策记录互查，不是阅读本套文档的前提。
- **图**：Mermaid。状态机、时序、组件关系优先用图；只有判定细节才用伪代码（类 Python 缩进、英文标识符、中文注释，每段不超过 25 行）。
- **术语**：与附录 A 一致。Call 一律指语音通话；"调用"指一次 Capability 调用。
- **数字**：文中的阈值、上限、默认值都是对照提交时的取值，它们是实现常量或部署配置，不是契约。
