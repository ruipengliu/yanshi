# 附录 A 术语表

> 本套文档、代码、注释与对话使用同一套名词。每个词条给出定义、所在章节与"不要这样叫"——后者是为了在多人、多 Agent 协作时避免同一概念出现多个名字。

## 主体

| 术语 | 定义 | 章节 | 不要叫 |
|---|---|---|---|
| **BusinessLine（业务线）** | 接入平台的一条 C 端业务；租户隔离、配额与计费的单位。令牌由它签发，AgentDef、保留策略、内容安全配置都以它为单位 | §2.1、§6.1 | 租户（泛指时）、客户、应用 |
| **EndUser（终端用户）** | 使用某条业务线产品的自然人；同一 EndUser 可同时使用多条业务线，ID 跨业务线统一 | §2.1 | 用户（有歧义时）、账号、客户 |

## 节点与能力

| 术语 | 定义 | 章节 | 不要叫 |
|---|---|---|---|
| **Device（设备）** | EndUser 持有的物理终端，如手机、电脑 | §4.2 | 端、终端、客户端 |
| **HostApp（宿主应用）** | 嵌入了端侧 SDK 的业务线 App；一台设备上可以有多个 | §4.2、§5.1 | 客户端、插件 |
| **Node（节点）** | 向平台提供 Capability 的执行端点。设备上的每个 HostApp 实例、每个沙箱、每个委托目标都是一个 Node | §4.1、§4.2 | Worker、Agent、端 |
| **Capability（能力）** | Node 声明的一项可被 Agent 调用的动作，带输入输出契约、风险等级与幂等性 | §4.1 | 工具（指声明时）、插件、函数 |
| **Connection（连接）** | HostApp 实例与网关之间的一条 WebSocket 长连接；可作为 Node 声明能力，也可作为会话客户端订阅 Session、提交输入与审批，或两者兼任 | §5.1 | 通道、长链接、Socket |
| **Inbox（收件箱）** | 某个 Node 待投递的 Capability 调用集合；Node 上线后由网关投递，结果回写日志后移出 | §4.2 | 队列、任务列表 |
| **Sandbox（沙箱）** | 平台在云端托管的隔离代码执行环境，每个 Session 至多一个，是一种 Node；其中只运行不可信代码，由沙箱外的受信控制器驱动 | §4.6 | 容器、VM、执行器 |
| **Workspace（工作区）** | 沙箱中跨 Run 保留的文件系统；沙箱空闲回收时计算资源释放而工作区保留 | §4.6 | 磁盘、卷、目录 |
| **Presence（在场）** | 哪些设备此刻订阅着某个 Session、是否显示在前台、是否正在输入。易失、带有效期，不进日志 | §5.3 | 在线状态（指 Node 是否连接时）、已读 |
| **Question（提问）** | Agent 经 `ask_user` 向 EndUser 提出的、可点选或填写的问题；Run 挂起等待，回答作为该调用的结果回到 Run | §4.4 | 表单、弹窗、确认框（与 Approval 区分） |
| **UIContext（界面上下文）** | EndUser 提交输入时所在界面的内容（界面、对象、选中文字、可见内容、所在设备），由 HostApp 附在输入上；按不可信数据对待 | §5.4 | 屏幕内容、页面状态 |
| **Notification（提醒）** | 需要 EndUser 注意（待审批、待回答、长 Run 结束）而他没在看时，推送到他最近使用的一台设备的消息；只含种类与 ID | §5.5 | 通知（泛指时）、推送（指通道时）、消息 |

## 执行

| 术语 | 定义 | 章节 | 不要叫 |
|---|---|---|---|
| **AgentDef（Agent 定义）** | 一份版本化的声明：指令、能力白名单、模型策略、上下文与委托配置、预算 | §7.6 | Bot、智能体配置、Prompt |
| **Release（发布配置）** | 某个 AgentDef 名下各版本的发布状态：稳定版本、灰度版本与比例、撤回的版本 | §7.6 | 上线配置、版本策略 |
| **Canary（灰度版本）** | 按比例（按 EndUser 稳定分流）或白名单分给一部分 EndUser 的新版本 | §7.6 | 实验组、Beta |
| **Withdraw（撤回）** | 回滚一个 AgentDef 版本：新 Session 不再使用它，已有 Session 在下一个 Run 开始时切换到稳定版本 | §7.6 | 下线、删除版本 |
| **Session（会话）** | EndUser 与某个 AgentDef 之间长期存在的交互容器，可被多台设备同时接入；拥有一条独立的 Event 日志 | §2.1、§2.10 | 对话、聊天、线程 |
| **Run（运行）** | Session 内由一次输入触发的一段执行，可被插话与中断；终态为 completed、failed、interrupted；一个 Session 同一时刻至多一个未终态的 Run | §2.4 | 任务、Job、Turn |
| **Attempt（尝试）** | 某个 Worker 对一个 Run 的一次执行；故障接管或挂起恢复都开启新的 Attempt。Attempt 号是写入日志的 fencing 令牌 | §2.5 | 重试、执行实例 |
| **Worker** | 无状态的执行进程，认领 Session 并以 Attempt 推进其中的 Run | §2.5、§3.1 | Node、执行器 |
| **Step** | Worker 推进的最小单位：同步完成一件事（认领、开始 Attempt、一次模型调用、一次调用的一个阶段），内部不启动影响结果的并发 | §3.1 | 轮、迭代 |
| **Event（事件）** | Session 日志中只追加、不可修改的一条记录；Run 的全部状态都可由 Event 重建 | §2.2、§2.3 | 消息、日志条目 |
| **ContentBlock（内容块）** | Event 中承载一段多模态内容（文本、工件引用、界面上下文、卡片、卡片动作）的单元 | §2.3 | 消息体、Part |
| **Compaction（上下文压缩）** | 把 Session 中较早的历史替换为一段摘要，记录为 Event；之后的模型上下文由"最新摘要 + 其后的历史"组成。原始 Event 不删除 | §3.3 | 截断、记忆（与 Memory 区分） |
| **Artifact（工件）** | 属于某个 Session、不可变、可被独立引用和下载的文件；Event 中只以 `artifact://<id>` 引用 | §4.7 | 附件、输出、文件（泛指时） |
| **Interrupt（中断）** | EndUser 让进行中的 Run（或 Call 中的发言）立即停止；已产生的输出保留，Session 可继续接收输入 | §2.4 | 取消、停止 |
| **Suspend（挂起）** | Run 等待外部条件（审批、设备结果、回答、配额）时，当前 Attempt 正常结束、不占用任何 Worker；条件满足或超时后由任意 Worker 恢复 | §2.4 | 暂停、阻塞、睡眠 |
| **Steer（插话）** | EndUser 在 Run 进行中追加输入，以改变其后续方向而不终止它 | §2.4 | 追加消息、打断 |
| **Handoff（移交）** | Worker 主动结束自己的 Attempt，把 Run 交给其他 Worker：以 `handoff` 挂起并立即归还 Session。用于优雅停机，以及交互 Worker 交出已成为长任务的 Run。不是故障，不计入接管 | §3.6 | 迁移、转交、让出 |
| **长任务** | 活跃 Run 已经做了很多工作：模型回合与上下文压缩合计达到 6 次，或累计输出达到 16000 token。按已做的工作判定，不按经过的时间；以 Background 优先级排队，只由通用 Worker 认领 | §3.6 | 慢任务、后台任务 |
| **恢复名额** | 用户对长任务做出审批或回答后，它在后台池中先被认领的一次机会；由下一个 Attempt 消费，不可叠加；不让长任务回到交互池 | §3.6 | 插队、加急 |
| **Call（通话）** | Session 内的一段全双工实时音视频交互；耗时工作由 Call 派生 Run 完成。音频不进日志，双方每句话的转写进日志。**代码中"调用"指一次 Capability 调用，与 Call 无关**；表示通话的标识符一律带 Call 前缀 | §5.7 | 实时会话、语音模式、Live |
| **Card（卡片）** | Agent 经内置工具 `show_card` 展示给用户的结构化内容：标题、Markdown、图片、键值、列表、字段与按钮。随调用结果写入日志；同一 card_id 再次展示即替换。不阻塞 Run | §4.5 | 富文本消息、组件、Widget |
| **Card Action（卡片动作）** | 用户在卡片上点按钮或点选列表项，连同填写的字段作为一条输入提交；同一版卡片上的同一动作只生效一次 | §4.5 | 回调、按钮事件、Postback |
| **Delegation（委托）** | 一个 Run 把任务交给另一个 AgentDef 执行：在同一业务线、同一 EndUser 下派生子 Session 与 Run，父 Run 挂起等待其终态作为调用结果。Agent 在模型眼里是一种 Capability；子 Run 的能力不超出任何祖先的白名单 | §4.9 | 编排、子 Agent（指 AgentDef 时）、多 Agent（泛指时） |
| **Decision（判断）** | 对"给定状态、有限合法选项"的问题由规则、小模型或 LLM 作出的选择；只缩小候选、追加约束或触发默认路径，从不放宽安全要求；影响后续执行的判断记为 Event | §6.5 | 分类、路由（指模型路由时） |
| **Fault Rule（故障规则）** | 调试部署中向本进程注入一种服务端故障的规则：类型、可选的 Session 与次数 | §8.5 | 混沌实验、Mock 故障 |

## 个性化与治理

| 术语 | 定义 | 章节 | 不要叫 |
|---|---|---|---|
| **Memory（记忆）** | 关于某个 EndUser、跨 Session 留存的个性化信息；默认归属产生它的业务线；分固定的几个类别 | §6.3 | 画像、上下文、知识库 |
| **Recall（召回）** | Run 开始时检索 EndUser 的 Memory（本业务线的，以及经 Grant 可读的其他业务线的）并记录为 Event，作为当前 Run 的上下文；同时也是访问记录 | §6.3 | 注入、加载（泛指时） |
| **Grant（授权）** | EndUser 显式同意某个业务线读取其在另一业务线下某些类别的 Memory；可撤销、可到期 | §6.3 | 共享、权限 |
| **Approval（审批）** | 执行高风险 Capability 前，由 EndUser 在某台设备上做出的单次确认；Memory 写入闸门触发的批准也走审批 | §4.3 | 确认框、授权（与 Grant 区分） |
| **写入闸门** | Memory 写入前的确定性判定：上下文含外部内容、且要写入的内容在用户原话中找不到依据时，须经用户批准；只收紧不放宽 | §6.4 | 过滤器、审核 |
| **Token（令牌）** | 由业务线签发、证明调用方身份的短期凭证。用户令牌代表一个 EndUser，服务令牌代表业务线服务端；平台只验证不签发 | §6.1 | 会话（与 Session 区分）、票据、凭据（泛指时） |
| **Retention（保留策略）** | 业务线为其 Session 声明的保留期限：最后一次输入后多久自动关闭、关闭后多久自动删除 | §6.7 | 过期策略、TTL（泛指时） |
| **Usage（用量）** | 一次模型调用、沙箱执行或通话轮次消耗的资源及按价格表折算的金额；独立于日志长期保存，不含 Session 与内容。这里的 token 指模型计量单位，与令牌无关 | §7.5 | 账单、消费记录 |
| **Quota（配额）** | 一个周期内允许的用量金额上限：业务线每月一份，EndUser 每日一份。超出时拒绝新 Run、挂起进行中的 Run | §7.5 | 额度（指剩余量时可用）、预算、限流 |
| **PriceList（价格表）** | 部署配置中每个模型的 token 单价（含缓存输入与音频）与沙箱的时长单价 | §7.5 | 费率、定价策略 |
| **Moderation（内容安全）** | 对 EndUser 输入与模型输出的合规检查，在写日志之前进行；违规输入被拒绝、违规输出被替换为拒答文本。由可替换的提供商完成 | §6.2 | 审核（泛指时）、过滤、风控 |
| **Policy（策略）** | 约束 Run 能做什么的规则集合：能力白名单、审批要求、预算与内容安全 | §4.1、§6 | 规则、配置 |

## 机制名词

这些不是领域对象，但在文中反复出现：

| 术语 | 定义 | 章节 |
|---|---|---|
| **投影（State）** | 对一段 Event 日志做 Reduce 得到的状态；缓存为快照，带投影版本号 | §2.6 |
| **fencing** | 每批写入带 Attempt 号，日志只接受当前 Attempt 的写入；正确性的来源 | §2.5 |
| **租约** | 工作队列按 Session 发放的带 TTL 的认领凭据；活性的来源，不是正确性的来源 | §2.9 |
| **决策-提交循环** | 所有写入方共用的写法：看着投影决定事件，乐观并发追加，冲突后重新决定 | §2.7 |
| **原子唤醒** | 外部写入的追加与入队在同一事务 | §2.8 |
| **闭合边界** | 日志中的一个位置，此前请求的所有调用都已有结果；压缩只能截在这里 | §3.3 |
| **先写、后查** | 写入方写入后复查删除记录、命中即撤回；与 Janitor 的"先记、后清"配合，任何交错下总有一方看到另一方 | §6.7 |
| **登记制** | 每处存放 Session 数据的地方登记"按 Session 删除"的能力，Janitor 按列表清除 | §6.7 |
| **一致性套件** | 每类存储接口一套测试，所有实现必须通过 | §8.2 |
| **差分测试** | 同一种子在内存与 PostgreSQL 实现上运行，比较指纹 | §8.1 |
| **变异检验** | 故意去掉某个机制，对应的不变量必须发现 | §8.1 |
| **影子模式** | 判断只记录、不影响执行 | §6.5 |
| **工作类别** | 入队时带的业务线与优先级（Interactive / Resumed / Background） | §3.6 |
| **单元（cell）** | 一条业务线的一套部署 | §7.7 |
