# Persona ADR-0001：xinli 的知识按实体维护、以变更集写入，交谈由模型划定

> 原内核 [ADR-0042](../../../docs/adr/0042-xinli-entities-by-changeset.md)。它是 Persona 的业务决定，不约束内核，按层存放于此（[ADR 评审](../../../docs/review/2026-11-14-adr-review.md) §6.1）。2026-11-14 的修订以"（2026-11-14 修订）"标出，其余为原文。

xinli 原先以交谈为身份：平台按停顿切出交谈，ID 由切分位置派生，`file_exchange` 以它为键，摘要、项目归属与承诺都挂在交谈上，重交也只能取代同一段交谈。一个完整工作日的评测（`docs/review/2026-10-25-xinli-workday.md`）中，五种模型配置都留下了改期、换人之后的过时承诺（20/20），都因相隔几分钟的两通电话被并成一段而评分不过，混合话题的交谈只能归一个项目。切分本身也做不好：设备收不到手机通话，一通电话在旁听里只有佩戴者一侧；同一批人换话题，停顿与说话人都看不出来；`speaker_key` 跨批不可比较。

改为（设计见 `docs/design/xinli-model.md`）：

- 平台只按停顿切**时段**，作为 `captures` 分页与"是否已结束"的单位，不再承担语义。（2026-11-14 修订：原文、分页与时段现在都在业务线，见内核 ADR-0052 第 2 条。）
- **交谈**由整理的模型在时段内划定范围，可以关联多个项目，当天整理时可以合并。承诺不以交谈为身份。
- 一次整理交出一个**变更集**：新建交谈与承诺、修订或关闭承诺、合并。每个操作引用依据，按来源去重、重交时整体取代；修订带模型看到的 `rev`，账本在此之后被改过就拒绝。
- 改动不删除：修订带说话时间与记录时间，合并与作废只标记关系。
- 有新原话为据的修订在空闲触发的白天整理里就做，只能引用本次读到的原话；没有新原话的整理（合并重复、合并交谈、改正归属）在当天整理里做，当天整理的时机按各用户的空闲分散。`xinli-project` 保留按 ID 对账，作为依据摘要的修订，受同样的 `rev` 约束。（2026-11-14 修订：内核的"空闲触发"（ADR-0040）没有实施，白天整理由业务线判断静默后提交整理指令，见 `docs/design/xinli-captures.md` §2。）

实体与变更集由业务线保存，ADR-0037 的边界不变；平台的改动只有时段的命名与引用核对附上说话时间。（2026-11-14 修订：ADR-0037 已拆分，业务部分见 [xinli ADR-0001](../../../apps/xinli/docs/adr/0001-daily-work-sessions-and-projects.md)，内核部分见内核 ADR-0052。）

## Considered Options

- **维持交谈为单位，改进切分**（按说话人切、缩短间隔）：说话人在跨批与电话独白时无效，同一批人换话题无从判断；任何从信号推出的切分都会错，而错误改不回来。
- **会话窗口加撤回**（流处理的做法）：边界变化时撤回重交，只能修正时间上的错，语义边界仍无解。
- **逐条事实为单位**（时态知识图谱，Graphiti 的做法）：切分不再重要，但每条事实都要做一次实体消解，调用次数与出错机会随之增加，Graphiti 的成本与延迟随图增长。
- **项目活文档**：模型改写每个项目的文档。提醒需要结构化数据，反复改写会漂移，逐项依据难以核对。
- **只在深夜对账**：提醒更正不及时，用户多时负载集中在同一时段。
- **只追加、读取时消解**（mem0 的做法）：提醒需要任何时刻唯一的当前状态，读取时排序会让过时的期限浮上来。

## Consequences

- `file_exchange`、`find_projects`、`day_exchanges` 由 `file_changes`、`find_related`、`day_ledger` 取代，`xinli-day` 的指令重写，须 `make eval` 与基线比较，并新增改期、转交、合并交谈等用例。
- 交谈 ID 不再随平台的切分参数变化，读取位置中的交谈间隔只影响分页。（2026-11-14 修订：内核的读取位置已退役，处理进度在业务线。）
- 业务线要以变更集为日志叠加出实体，存储与实现比按交谈整份取代复杂。
- **人物与组织的建模是初期范围之外，不是结论**（2026-11-14 修订，原文为"人不建模"）。初期不为人建模：语音识别只能区分不同的人，不能指出是谁，称呼仍按原话；称呼对不上造成的漏召回、漏合并作为观察项。人物与组织实体允许在 Persona 中演进（[Persona 架构](../../../docs/design/persona-architecture.md) §3 已规划），**尚未完成**。演进时保留：依据、`rev` 版本冲突检查、来源重交时整体取代的语义；并且**识别出说话人不等于证明了人物身份**，不能据说话人标签把一段话归到某个人物实体上而不经依据核对。
- 每次操作按 EndUser 全量装载账本（`persona/store/pgstore/rows.go`），成本随数据增长；改为按需读取与增量物化是已认可的方向，保留变更集的事实语义，见 [Persona ADR-0002](./0002-on-demand-reads-and-incremental-materialization.md)。（2026-11-14 补充；2026-11-16：只读查询已改为按需读取，写事务仍整体装载）

## 重审条件

任一出现即重新评估：

- 开始为人物或组织建模；
- 账本装载的成本超出 P4 成本报告的可接受范围（`docs/design/persona-architecture.md` §13 Q93、Q111、Q123）；
- 出现第二条业务线复用 Persona 的知识模型。
